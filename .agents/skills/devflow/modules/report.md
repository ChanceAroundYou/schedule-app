**目的**：每轮完整工作流跑完，除了在聊天里说两句，再落盘一份结构化纪要，方便以后回看
"上次到底改了啥、发没发上去、两端实测过没过"。

```markdown
## 发布与实测

> 项目版本发布**默认两个渠道都发，严格先 Web 后 APK，顺序执行不并发**，不需要用户点名。
> 只有 ① 用户明确暂停/排除某一侧、② 该侧前置检查硬性失败，才可跳过；跳了哪侧、为什么必须写清。
> 纯内部工作（技能 / 记忆 / 文档维护）不产生线上版本时，两栏都写"不适用"。

### 网页端（第 1 步）
- 状态：<已自动发 + live-check 全绿 / 失败已回滚 / 跳过（原因） / 不适用>
- 关键断言：<core / now-line / repeat 等结果>

### 安卓端（第 2 步，网页端验收通过后才执行）
- 状态：<已自动发 + android-live-check 全绿 / 真机冒烟通过 / 失败已回滚 / 跳过（原因） / 不适用>
- 版本号：<versionName versionCode>

## 备注 / 待跟进
- <需要你后续决策的事项，或下轮要做的>
```

## 规则

- 纪要只记**事实**，不写冗长过程。
- 每轮**完整工作流**跑完必写一份（单步"存一下/推一下"这种小动作不写，免得刷屏）。
- 聊天里那两句话是**即时通知**，这份纪要是**存档**，两者互补，不冲突。
- 不进 git、不提交，纯本地存档。
