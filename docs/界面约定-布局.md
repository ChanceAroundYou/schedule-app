## 顶栏一行 + 日程副header（2026-10-07）

用户报的是「移动端 header 挤成好几行、暗色按钮多余、搜索框到处都是」，
日程页还要「整体重新设计简化」。落成了三件事：

**1. 顶栏（`.topbar`）在所有端都是一行** —— 标题 + 搜索 + 同步状态。
窄屏原先被 `styles/responsive.css` 改成 `flex-direction: column`，而第二行里的
`date-nav` 自己还会 `flex-wrap`，实际是**三行**。现在统一 `row`。
顶栏**照旧不许加 `position` / `z-index` / `sticky`**（见踩坑 11）。

**2. 日程页的控件搬进副header**（`ui/Shell.tsx` 的 `CalSubheader`）：
`‹ › / 今 / 找日期` + `日|周|月`，只在 `nav === 'calendar'` 时渲染，
紧贴顶栏下面一行（`.cal-subhead`）。**副header 只放控件，一个日期字都不写。**

> **日期长文本归顶栏**（就在副header 的上一行）。原先两处都写一遍，于是桌面
> 日程页「2026年10月7日 周三」在相邻两行各报一次，读的人不知道该看哪行。
> 现在粒度跟着视图走：**日 = 某天（`10月7日`）· 周 = 这一周的起止
> （`10月5日 – 10月11日`）· 月 = 年月（`2026年10月`）**。
> 周视图原先跟月视图一样写「2026年10月」，看不出「这一周是哪一周」。
> `browser-smoke.mjs` 第十七节数着 `.cal-subhead .date-range` 的个数（应当 == 0），
> 再按视图分别断言顶栏标题的格式。
>
> 三个控件各自的简化：
>
> - **「今天」按钮只留一个「今」字。** 在不在今天**不靠文字**，靠 `aria-pressed`
>   那一档配色（`--primary` 字 + `--primary-pale` 底 + 描边 + 加粗）——
>   见 `styles/shell.css` 的 `.date-nav [aria-pressed="true"]`。
> - **「找日期」只留图标**（lucide），没有文字，按钮上带 `aria-haspopup="dialog"`
>   + `aria-expanded`。
> - **上一 / 下一个是 `Btn variant="normal" size="sm"` 加 `w-[30px]`**：30px 见方。
>   里面只有一个图标，靠 `line-height: 1` 加内联 SVG 会偏 1~2px，看着就是
>   「没居中」。**功能跟着视图走**（`App.tsx` 的 `shift()`）：日 = ±1 天、
>   周 = ±1 周、月 = ±1 月 —— 这一段是既有的，探针补上了断言。

**3. 搜索框窄屏收成一个图标 + 点开的浮条**（`SearchPop`），宽屏仍是常驻输入框。
两者共用 `SearchInput` 与 `useSearchValue`（180ms 防抖）；浮条照抄 `JumpPop`
的 `position: relative` 包裹 + `useOutsideClose` 那一套，不引新机制。
**主题按钮不在顶栏**，入口只有设置页的外观卡（`.topbar` 里连 `onTheme` 都没有）。

两条接线上的坑，都锁在 `browser-smoke.mjs` 第十七节：

- **`onSearch` 必须是 `useCallback`。** `useSearchValue` 的 effect 依赖里有它，
  传内联箭头（每次渲染换一个身份）会让那个 effect 每渲染跑一遍。
- **Esc 那个键盘 effect 的依赖数组别漏项。** `searchOpen` 漏过一次，症状是
  「浮条开着按 Esc 关不掉」—— 闭包里读到的值永远停在挂载那一刻，而开浮条
  不会改动数组里其余任何一项，effect 根本不重跑。探针验过它有牙：
  把 `searchOpen` 摘掉重跑，会**中断在「Esc 关掉了搜索浮条」那一步**。

> **「视图切换选中态没有提示」是个真 bug，不是没设计。** 按钮的类名是 `.on`
> （`Shell.tsx`），CSS 规则却写的是 `.view-switch button.active` —— 两者不匹配，
> 选中态样式**从未生效过**。现在 `styles/shell.css` 两处都改成了 `.on`
> （`:hover` 那条也要跟着改，否则按下时高亮会消失）。
> 这是「类名与选择器对不上」的典型：**改类名时全仓搜一遍**，别只改写的那一处。

**副header 四个控件同高、同字号、同圆角、同描边**（`Btn size="sm"` /
`.view-switch button`）。它们并排站在一行里，任何一个高一点或字大一点，
整行看着就是歪的。**高度写死，不用 padding 推** —— 12.5px 的
`line-height: normal` 各浏览器差 1~2px，光靠 padding 永远对不齐；里面只有一个
图标或一个字，所以用 flex 居中（靠 `line-height: 1` 加内联 SVG 会偏 1~2px）。
宽屏 30px，窄屏 34px（触控目标）。日周月是**分段控件**（一个圆角框里三格），
描边由容器提供，格子用右边框分段 —— 但高度 / 字号 / 圆角 / 字色与旁边三个
独立按钮一致，否则并排看着就是两套。

## 周视图窄屏横滑 + 吸顶行背景 + 表头简化（2026-10-07）

**窄屏下 7 列要横滑**（`.week-view` 在 ≤900px 时 `overflow-x: auto`，列宽锁死
`minmax(92px, 1fr)` + `min-width: 644px`）。一屏只看得见 3 天，所以
`views/Calendar.tsx` 的 `centerWeekDay()` 把「今天 / 选中的那天」摆到可视区
中间 —— 不定位的话用户根本不知道左右还有。

> **周一和周日居中不了**（一边没有列），算出来的 `scrollLeft` 会越界，
> `Math.min(want, scrollWidth - clientWidth)` clamp 之后自然贴边，
> 所以不需要特判。判据是「左右各有足够的列」，不是「离中间最近」。
> `useViewLayout` 的 week 分支在 `g.scrollWidth > g.clientWidth + 1` 时才调
> `centerWeekDay` —— 宽屏不横滑，调了也是白调。

**吸顶的表头与未定时行，背景必须盖住整条滚动宽度。** 这两行是 `.week-view`
（`display: flex; flex-direction: column`）的 flex 项，作为 flex 项时只有容器那么宽
（≈一屏 526px），而它们内部的列网格 `min-width: 644px` —— 于是右边三四列的
头部透出下面时间网格的刻度线，看着就是「表头只画了一半」。修法是
`width: max-content`（列宽有 `min-width` 兜底，不会缩没）。
**未定时行同理**，而且它**上下都要有分割线**：只有下面那条时，这一行和上面的
周几表头融成一体，看不出「未定时」是独立的一块。

**表头不再有负载横条与任务计数**（`.wh-load` / `.wh-count` 已删），
**今天的数字也不再加圆形底色** —— 那一格会凭空高出 9px，同一行里其他日期的
数字看着就是没对齐。「今天是哪天」由下面 `.week-col.today` 的 `--primary-pale`
整列淡底负责，表头不重复做，只把数字染成 `--primary`。

锁在 `browser-smoke.mjs` **第二十一节**（跑在**宽屏**下）：四档控件同高 30px、
`.wh-load` / `.wh-count` 计数为 0、未定时行上边框 ≥ 1px、今天的数字没有圆底。

> **窄屏那几条（34px 按钮、7 列横滑、表头 `width:max-content`、`centerWeekDay`
> 居中）探针测不了。** 探针的伪窄屏只在 JS `matchMedia` 上套了 Proxy，CSS
> `@media (max-width: 900px)` 不认这个 —— 窗口真的 1280px，媒体查询就是不匹配。
> `Emulation.setDeviceMetricsOverride` 能把视口改窄，但改完之后合成事件不进处理器
> （见踩坑 24），没法点进周视图。**这几条只能靠真机 / 真浏览器看。**

## 项目页泳道布局（2026-10-08）

**项目页是泳道看板**（`views/Projects.tsx`）：泳道 = 项目，列 = 任务状态
（待办 / 进行中 / 已完成）。**为什么不是甘特图**：用户自述「有很多个项目在并行
推进，但大多数没有非常明确的时间节点」—— 这是 PARA 里 **Area**（持续关注、
无结束点）的形态，甘特图会逼用户给每个项目编一个假日期。

**布局结构：**

- **页面顶部**：标题「项目」+ 「＋ 新建项目」按钮
- **新建项目浮层**（`ui/ProjectSheet.tsx`）：名字 · **日程集** · 状态 · 进度 · 备注
  - **「日程集」选择器只在新建时出现**，编辑时不给。项目**不绑当前集** ——
    原来绑 `ui.cal`，当前集只读时 `commitMany` 会**静默丢弃**（连 deny 都不记），
    用户看到的是「点完创建浮层关了、项目没出现」。见踩坑 47。
  - 只列 **能写 ∩ 正勾着** 的集：写不进去的不列（骗人），没勾的不列（落进去
    项目按 `p.calId` 过滤，等于凭空消失）。
  - 默认取当前集（当前集能写就用它），否则第一个能写的。
  - **编辑时不给这个选择器**，因为挪集在数据模型里是「目标集新建一条 + 源集留
    墓碑」，`patchProject` 改不了 `calId` —— 给一个存不下去的死控件更坏。
  - **一个能写的集都没有时**，选择器是空的、创建按钮禁用 —— 这时开浮层弹一句
    toast：「所选日程集均无写入权限，无法新建项目」。**禁用的按钮不解释任何事**，
    光看到「点不动」用户不知道该去哪儿。文案要**精炼、克制无感情**：只说后果，
    不解释界面上看得见的东西，不写「请记得」这类。
    只在新建时弹（编辑没这个限制），一次开浮层只弹一次（依赖用原始值，
    拿 `writableShown` 这个每次渲染都换新的数组当依赖会每渲染弹一次）。
- **泳道列表**：每个项目一个 `.pj-lane`，包含：
  - **泳道头**（`.pj-head`）：展开/收起按钮、项目名、状态标签、停滞标记
    （`X 天没动`）、任务计数（`done/total`）、进度条、编辑按钮
  - **下一步输入框**（`.pj-next`）：blur 时落库，不每敲一个字就 commit
  - **三列**（`.pj-cols`）：待办、进行中、已完成，每列有列头和任务卡片

**卡片拖拽：**

- 卡片同时带 `.task-el`（dnd 认的类）和 `data-card`（泳道列的 `zoneCells` 认的属性）
- 列的语义是「状态桶」不是有序表（换列才提交，桶内顺序不动）
- 让位洞那一套（drop-hole / shiftCells）按 `data-kind` + 格子选择器走

**停滞标记：**

- 判据是「多久没动」，不是「错过截止」—— 这个模型里没有截止日
- `stale >= STALE_DAYS` 时显示「X 天没动」

**进度条：**

- 手填进度（`progress` 字段）或按任务自动算
- 手填时显示「手填进度 X%」，自动算时显示「按任务自动算 X%」

锁在 `browser-smoke.mjs` **第十九节**：建项目 → 挂任务 → 拖卡片换列 → 刷新还在。

## 设置页布局（2026-10-08）

**设置页是「大 header + 小 tab 切换」**（`ui/Settings.tsx`）：四个 tab ——
外观 · 安全 · 日程集 · 关于。**放在 `ui/` 而不是 `views/`**，这是故意偏离方案的一处：
`views/` 是「纯展示、零回调」，而设置页是普通表单，`ui/` 下本来就是这个形态。

**卡与小节的排法走组件库的 `Card` / `Field` / `Row`**（`ui/kit.tsx`），不写在页面里。

**布局结构：**

- **tab 栏**：唯一的 header，四个胶囊按钮，选中态用 `--primary` 底色
- **外观 tab**：
  - 功能区自定义（`NavCard`）：**三列网格**上的可拖拽 + 可点选按钮（每格一项，
    不是每项一行 —— 九项一行一个要占 280px 高，一屏就没了；网格里每格等宽，
    拖拽时让位的落点也是规则的）
    - **勾选的口径是「勾上 = 在这个设备的功能区里显示」**：宽屏 = 在侧栏里，
      不勾就是 `ui.navHidden`（藏起来）；窄屏 = 在底栏那 4 格，不勾的在「更多」抽屉里
    - 位置只由拖拽决定，不由勾选决定（见下）
    - **次序：显示中的全排在前面，被隐藏的排到最后**（2026-10-09 定）。
      不画分组标题、不加分隔线 —— 这是「次序」不是「两栏」。原先两组混着排，
      用户看到的是「真正显示的功能区夹在藏起来的中间」。
      - **拖是自由的，落点被钳回本组**：显示项被拖进隐藏区 → 松手落到**显示组末位**；
        隐藏项被拖进显示区 → 落到**隐藏组最前位**。钳的是落点、不是拖的过程。
      - 所以钳完 `arrayMove` 出来的顺序，它的「显示 / 隐藏」分组恰好等于它自己，
        直接当 `ui.navOrder` 写回去就行。
    - **顺序一变，`ui.tabs` 必须当场一起重写**（走 `domain/model.ts` 的 `orderTabs()`，
      `normalizeUi` 用的也是同一个函数）。底栏读的是 `ui.tabs` 自己的顺序，而
      `store.setUi()` 是个裸的浅合并、**不跑 `normalizeUi`** —— 只写 `navOrder` 的话
      窄屏底栏纹丝不动，要等刷新才变（见[踩坑 49](踩坑-前端.md)）。
    - **桌面侧栏那列不能拖，就不要装作能拖**：`.nav-item` 上原先挂着旧版残留的
      `cursor: grab`（`legacy/index.html` 里那排是真的 `draggable="true"`），
      桌面端鼠标一划过就是个抓手，试着拖却毫无反应。排序只有设置页这张网格能做，
      hover 底色留着（它说的是「可点」）。
    - **宽屏藏起来 ≠ 够不着**：侧栏底部有一个「更多」入口，列出的就是 `ui.navHidden`
      那几项（顺序跟 `navOrder`）。窄屏有底栏最后一格那个「更多」抽屉，桌面原本没有，
      一勾掉就只剩设置页能找回来 —— 那是个真死角。**一个都没藏时入口不画**
      （空浮层比没有更费解）。
  - 外观卡：色板（6 套）、风格（3 套）、深浅（3 套）—— 用 `Chips` 组件（不是 `<select>`）
- **安全 tab**：
  - 用户信息 + 修改密码 + 退出登录
  - 同步与备份：导出备份、导入备份、清空本机副本
  - 网络状态、待上传数
- **日程集 tab**：日程集管理（`CalsTab`）
  - 卡头右边是**邀请收件箱**入口 —— 它是全局的（别人邀请我，跟哪个集无关），
    不塞在某个日程集的展开面板里
  - 可展开的列表，每个日程集一行
  - **一行 = 一块圆角 + 底色的标题条**（`h-[40px]`，`--panel-3` 底），
    外框没有第二层描边。展开后正文直接摆在卡的留白里，**左右与标题条那个圆角条的
    外沿齐平**（2026-10-09 改）。
    这段改过两次，值得记下来：最初正文顶着卡片内容盒的两端画，于是每一行都比标题条
    **宽** —— 左边超出 10.5px（角色图标比名字还靠左）、右边超出 7px（移出钮比折叠
    箭头还靠右）。第一次修是把正文的 `pl-3 pr-2` **照抄标题条**（10.5 / 7），对齐到
    标题条的**内容盒**；结果每一行又比标题条**窄**一截，看着还是「没对齐」。
    第二次（用户：「宽度再宽一点点，让邀请输入框、新建按钮、header 对齐」）直接
    **不占横向留白**，贴齐圆角条的外沿 —— 邀请输入框因此宽 17.5px
    （456.48 → 473.98），纸飞机右缘与折叠箭头右缘重合。是**齐平**，不是超出。
    原先「卡里一个大框、框里一个小框、小框里每行又一个带底色的胶囊」是三层
    框套三层底色，用户的原话是「一层层大框套小框」
  - **标题条从左到右是三区**（用户 2026-10-08 定）：**名称区 · 操作区 · 箭头区**。
    原先折叠箭头夹在标题条**中间**（名字和铅笔之间），点起来要越过名字那一大段；
    现在它独占最右一格，`aria-expanded` 也只有它持有。
    - **名称区**：名字 + 星标（默认日程集）+ 角色徽标，全在 `InlineRename` 的
      `display` 里。**星标紧跟着名字**，而且**编辑态自动隐藏** —— 它住在
      `display` 里，编辑态整个被换掉，外面不用再判一次 `editing`
    - **操作区**：`InlineRename` 的动作槽，固定 `w-[52px]`（= 24 + 4 + 24，正好两格）。
      平时是「铅笔 + 删除」，编辑中是「√ + ✕」—— **两态都是两个按钮**，所以
      切换时槽宽不变、左边可用宽度不变（见 `docs/组件库.md`）
    - **箭头区**：折叠开关，独占最右。**名字区不再是按钮** —— 它里面装着星标
      这个 `<button>`，按钮套按钮是非法 HTML，而编辑态的 `<input>` 也进不了
      `<button>`。所以「点名字展开」这个行为没有了，展开收起只认最右那个箭头
  - **删除按钮在标题条上**，不在展开面板里：平时是「铅笔 + 删除」一组，
    编辑中是「√ + ✕」一组。删除走 `MiniIconBtn danger`（平时是中性灰，hover 才变红）
    —— 它紧挨着铅笔，不该比铅笔更吵；编辑态的 √ 用 `--primary`，因为那时它是
    唯一「提交」的动作，两个灰按钮分不出哪个是哪个
  - 展开后：成员 + 邀请、危险区。**改名和删除都不在展开面板里** —— 它们是最高频的
    动作，埋进折叠面板要多点一次。危险区里只剩「退出日程集」+ 只读成员的提示
  - **成员行不带底色**，一行就是一行；**邀请是列表的最后一行**（一个还没进来的
    成员），不是单独一个小节。邀请框的 placeholder 是「输入要邀请的用户名」——
     只给格式示例，**不当可访问名字**（名字走 `aria-label`）。**必须带「邀请」
     三个字**：这一行前面几行都是「谁有权看」，孤零零一个「输入用户名」读不出是在
     邀请谁，而 `aria-label` 眼睛看不见
  - **输入框的字号跟它所在那一行走**，全系统统一 13px（界面文字那一档）。
    这条踩过两次，第二次才是真凶：`styles/tokens.css` 里有一条**没有层**的
    `input { font-size: 14px }`，把 `Input` / `Textarea` 上每一个 `text-*` 都吃掉了；
    而 `styles/responsive.css` 里还压着一条同样没有层的
    `input { font-size: max(14px, 16px) }`（防 iOS 聚焦时自动放大页面），把**全项目
    每一个输入框**都钉在 16px —— 包括 kit 的 `<Input>` / `<Textarea>`。于是同一个
    抽屉里两种字号：`.field input` 是 13px（类选择器压得过它），`<Input>` 是 16px。
    修法是两条一起：`tokens.css` 那条挪进 `@layer base` 并定 13px；`responsive.css`
     里那三条 16px（`input, select, textarea` / `.jp-row input` / `.fast-add textarea`）
     **整块删掉**（2026-10-09 用户要求全系统统一）。
     **代价：≤820px 下聚焦输入框，iOS 上会拿回自动放大**（iOS Safari 对 <16px 的
     输入控件会强制放大整页）。要回去就把那三条加回来 —— 但它们是**没有层的作者
     样式**，挪进 `@layer base` 的话 `Input` 的 `text-[13px]` 会立刻压过它。
     详见[踩坑 45](踩坑-前端.md)

**默认日程集**（`ui.defaultCal`）：

- 星标标的就是它，**同时只有一个**，点另一个的星就换过去
- 它是**显式的 id**，不是拿名字比 —— 以前写的是 `cal.name === '我的日程'`，
  改个名这条判断就失效（「不能删除」的保护跟着没了），而别人建一个同名集把你
  拉进去，你个只读成员又会看到「这是你的默认日程集」
- 口径只有 `domain/model.ts` 的 `resolveDefaultCal()` 一处：选过的那个还在就用它，
  不在了退到**第一个自己建的集**，一个自己建的都没有才退到列表第一个
- 作用是「没有当前集时打开哪个」（`store.resolveCal()` 的回落），以及
  「哪一个不能删」（`CalsTab` 的删除按钮）
- 存**本地**不跟 `cals` 一起同步：`ui.cal`（当前看哪个集）本来就是本地偏好，
  「打开哪个」和「现在看哪个」是同一类。要跨设备得加 `users` 表一列 + 接口

- 三个输入框：当前密码、新密码、确认新密码
- **「确认」那一栏必须有** —— 没有找回口令的路子（没有邮箱、没有手机、没有管理员）
- 成功后其他设备被踢出去

## 顶栏与滚动条：2026-10-09 一次报的七条

用户一次报了七条，集中在「桌面 / 移动两套长得不一样」和「滚动条挤元素」上。

**1. 滚动条一律不占位**（`ui/scroll.ts` 的 `useOverlayScrollbar`）。
原生滚动条是**在布局里占宽度**的：内容一多，`clientWidth` 少掉十几 px，右边那一列
元素就跟着往左跳一下。改成两层 —— 容器挂 `.osb`（`scrollbar-width: none` +
`::-webkit-scrollbar { width: 0 }`，把原生条整条隐藏），`useOverlayScrollbar` 再往容器里
**追加**一个 `.osb-track`（4px 宽、`position: absolute` 贴右缘）+ `.osb-thumb`，
自己按 `scrollTop` 画、自己拖。

- **track 是 `pointer-events: none`、只有 thumb 收事件** —— 否则那 4px 会吃掉点击。
- `z-index: 2`：压得住普通内容，压不过周视图那两条吸顶行（5 / 6）。
- 容器本来是 `position: static` 时 hook 会补一个 `relative`（浮层要定位）——
  **别把滚动容器放在「绝对定位子元素的包含块」敏感的位置上**。
- 尺寸靠 `ResizeObserver` + `MutationObserver` + `scroll` 三处重画，
  `requestAnimationFrame` 合帧；拖拽走 pointer 事件 + `setPointerCapture`。

挂在哪：`.sidebar` / `.content` / `.week-view` / `.allday-zone` / `.drawer-body` /
`.ai-scroll` / `.ai-sessions-list` / `.repeat-pop` / 快速添加的 textarea / `Sheet` 的 body。

**2. 桌面「更多」浮层跟侧栏几乎等宽。** 包含块是 `.sidebar-footer`（底栏那一行，
正好横跨侧栏内容宽 240−14×2），`left: 0; right: 0` 就横跨整行 —— 实测 211px、左右各 14px。
**`.side-more` 不许有 `position`**：它一变成定位元素，包含块就缩回半个底栏宽（99.5px），
浮层缩在右下角。别写 `width: 211px` 这类死值，侧栏宽度一改就歪。

**3. 日程集那两处（移动端多选面板 / 桌面顶栏下拉）用同一套**：同一个 `Layers` 图标、
同一句「日程集 x/y」文字。原先桌面写的是 `calSummary()` 拼的「全部 1 个」，跟移动端
是两套说法（`calSummary()` 已删）。面板最后一行到面板底的留白从 7px 提到
16px + `env(safe-area-inset-bottom)`。

**4. 勾选圈的勾要正落在圆心。** 原来写 `left: 5px; top: 2px` + `rotate(45deg)` ——
`left/top` 摆的是盒子的**左上角**，盒子中心就落在 (7,6)，圆心在 (9,9)，整体偏左上 2×3px。
改成 `left: 50%; top: 50%; transform: translate(-50%,-50%) rotate(45deg)`：盒子中心
正好是圆心（旋转以盒子中心为原点，不动中心）。**三个尺寸（18 / `.sm` 14 / 响应式 22）
都得这么写**，只改一个是换个地方歪。
> 量法：`勾盒中心 = 边框宽 + left/top + 半个盒子 + transform 里的平移 e/f`。
> `left: 50%` 是相对 **padding 盒**算的，所以要加回边框宽度；旋转不动中心，
> 只有平移会挪它。别去量墨迹包围盒 —— 勾是个 L 形，它的包围盒中心天生比盒子中心
> 低 0.7px（18px 圈），那是形状本身的，不是没居中。

**5. 桌面搜索框跟旁边控件同高 30px。** 它原先只有 `padding: 6px 11px`、没有 `height`，
`<input>` 的默认行高把它撑到 47.5px —— 顶栏因此 76.5px 高，旁边那排 30px 的控件看着
像陷在里面。现在 `height: 30px`，顶栏 59px。

**6. 窄屏搜索浮条长在顶栏那一行里。** 原先 `top: calc(100% + 8px); right: 0` ——
它是**另起一行挂在 header 底下**的，把内容往下挤。现在 `right: 100%; top: 50%` +
`translateY(-50%)`，从搜索图标**原地往左伸出去**。浮条总高刻意做成
30 + 8×2 + 1×2 = **48 = 顶栏高**，居中时上下都不探出去（多 1px 就探出去 1px）。
外面要包一层 `.search-anchor`（`position: relative`）—— `SearchPop` 自己不定位。

**7. 设置页左上角写页名。** 写在**页面里**（`#content h1`），不写在顶栏 ——
顶栏那一栏再写一遍「设置」，两行同一个词看着像两个 header。

锁在 `browser-smoke.mjs`：**第三节**（桌面勾选圈）、**第五节**（设置页页名）、
**第十八节**（其余全部）。
