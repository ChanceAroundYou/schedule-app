> 探针一律从**仓库根**起跑。`cd app` 再跑也行，但脚本里的 `ROOT` 是从文件位置算的，
> 别照抄成相对路径。Chrome 由 `lib/probe-env.mjs` 自动找（Windows 两个默认安装位 →
> `/usr/bin/google-chrome` → `/usr/bin/chromium` → `/opt/google/chrome/chrome`），
> 都找不到才需要 `CHROME=` 指定 —— 本机用的是 `/tmp/schedchrome/chrome` 那个 wrapper
> （走 headless shell；playwright 目录里的 `chrome` 起不来，`chrome_crashpad_handler`
> 没有执行位，见[踩坑 24](踩坑-环境.md)）。
>
> **后两个探针跟其它探针不是一类**，红了先别去翻代码：
> - `week-look.mjs` **默认打线上伺服的那份**（`LIVE_URL` 没给就是线上）。本地改完还没发布时
>   它会红，红的含义是「线上还是旧版」。要比本地：先起 dev，再
>   `LIVE_URL=http://127.0.0.1:11717/ node app/tests/week-look.mjs`。
>   2026-10-24 两边各跑过一次，同一条 180 分钟的窄屏周视图卡：线上「不显示」、本地「显示（09:00 – 12:00）」。

>   没有它直接打用法退出（本机跑不了）。它验的是真机上的触摸与滚动，无头补不了。

### 探针的代码结构

三个大探针已拆成 **`lib/` 公共层 + `sections/` 分节**，入口文件只留编排：

| 入口 | 分节目录 | 说明 |
|---|---|---|
| `browser-smoke.mjs` | `sections/smoke/00–26.mjs` | 27 节，共享状态走 `ctx.state`，helper 走 `ctx.helpers` |
| `card-geometry.mjs` | `sections/geom/00–09.mjs` | 00 是六屏测量，01–09 是九组断言 |
| `android-live-check.mjs` | `sections/android/01–04.mjs` | 按 `--features` 分组（core / now-line / month / repeat） |

公共层：`lib/probe-env.mjs`（端口 / Chrome / 数据目录 / dist）、`lib/cdp.mjs`
（connect / evalJs / waitFor / touch / key）、`lib/server.mjs`（静态 + /api 代理）、
`lib/probe-assert.mjs`（`ok()` 计数）、`lib/seed.mjs`（**造数据**：注册账户、取默认日程集、
把种子任务拆成逐字段 op 推 `/api/sync`、邀请 + 接受、把登录态写进 localStorage、催一次同步）。
**改断言先看对应那一节，别改入口。**

> `lib/seed.mjs` 存在的理由是「**任务字段表只许有一份**」：2026-10-28 之前
> `card-geometry` 和 `browser-cards` 各自维护一份 fields 字面量，一份带 `repeatSeq` 一份不带，
> 服务端加字段时只有一个探针会红。它自己那份单测（`tests/lib/seed.test.mjs`，13 条）
> 锁的就是这张表、op 是不是逐字段拆的、日期从哪来 —— 已在 `npm test` 的 glob 里。
> **边界**：seed 只管**环境准备**，不管被测行为。`browser-smoke` 第七节测的是
> 「邀请在界面里被接住」，那一节不许用 helper 把考点跳过。

探针都会**自己起一个临时后端**（临时数据库 + 随机端口），不碰线上那份。
`smoke-share.mjs` 覆盖的是单元测试测不到的东西：限速之外的所有跨用户路径 ——
邀请 → 接受 → 跨账号同步 → 降级为只读后被拒 → 移出后写不进去。

界面照一遍（真实 Chrome + CDP，零 npm 依赖）：

```bash
node app/tests/browser-smoke.mjs
```

它自己起一套**完全隔离**的环境（临时后端 + 带 /api 代理的静态服务 + 独立
Chrome profile），然后像人一样走一遍：**第一趟就查预缓存** → 注册 → 顶栏出现日程集
多选 → 六个视图都不白屏 → 管理浮层改名 → **确认真落库** → 刷新还在 → 收到邀请 →
接受 → 切到新集 → **长按提起 → 拖到别处排序** → **鼠标拖拽同一套落点** →
**被降成只读后提示点名集名** → **同一字段两边都改过 → 抽屉里那条提示** →
**AI 提案卡片 → 确认 → 服务器上真有** → 离线小标 → **关掉静态服务还能打开** →
无障碍点名 → **方向键微调时间轴把手** → **软键盘变量 `--kb` 两端接没接上** →
**抽屉的 dialog 语义与焦点圈**。全程收集 console 报错，有一条就算失败。

> 之所以不用 `vite preview`：它的代理写死指向 25692，**那是线上后端**，
> 探针会往生产库里写账号。隔离是这里的第一要求。

> **跑完测试必须收干净**：`pkill -x chrome`（`chrome_crashpad_handler` 一并），
> `ss -ltnp | grep -E '5198|25701'` 找出残留服务 `kill`，`rm -rf /tmp/sched-browser-*`。
> 不清的代价与「新起的静默连到残留旧后端」那一类假失败，见
> [踩坑-环境.md](踩坑-环境.md) 第 40 条 —— 端口避让只管这一趟，撞着的那一趟照占。

> **触屏（第八节）和鼠标（第九节）测的是同一件事的两个入口。**（这两节是
> `browser-smoke` 的分节；`card-geometry` 也有一节叫「九」，讲的是设置页「显示」，别混）
> 两条路共用 `applyDropAt` / `finishDrag` / `commitDrop`，所以第八节证的是「手势对不对」，
> 第九节证的是「鼠标这条**接线**还通着」—— 重构共享代码时最先坏的就是那几个 handler 的
> 接线，而触屏那条根本不发这些事件，光靠第八节看不出来。

> 离线那一段有两处是**为了让断言有牙**才那么写的，别当成多余的：
>
> - 探针自己的静态服务对 HTML 回 `cache-control: no-store`（真实 nginx 给 `/schedule/`
>   配的也是 no-cache）。不然服务器关掉之后 Chrome 自己的 HTTP 缓存也能交出 index.html。
> - 关服务前要 `closeAllConnections()`。光 `close()` 只停止接受新连接，Chrome 池子里
>   那条 keep-alive 还能把请求送进来，同样是假通过。
> - **「第一趟就查缓存」必须在第一趟查**（第「零」节，第一次导航之后、任何刷新之前）。
>   放到后面就区分不出「安装时预缓存了」和「后来被动存下来的」—— 后者正是线上踩过的坑：
>   真实站点上第一次访问 `caches` 是空的。

> 探针里的 `waitFor` 条件要**只可能因为那件事成立**。踩过一次：等「成员列表加载完」写的是
> `innerText.includes('创建者')`，而那是 ROLE_LABEL，发邀请那个 `<select>` 的 `<option>`
> 里就有一个 —— 浮层一开就成立，等于没等。现在等的是成员**条数**非零。
> 另外它**不能以换行开头**（ASI 会把 `return` 断成空语句），见「踩坑 29」。

> **几节共用的写法**，新写一节时照抄：
>
> - **两段等**：本地那一层（localStorage / cals 角色）先等、DOM 后等。合成一个条件的话，
>   超时时分不清「同步没发生」和「同步到了但界面没画」—— 排查方向完全相反。
> - **造数据一律走 `lib/seed.mjs`**，不要在 `evalJs` 里把注册 / 造任务再写一遍字符串。
>   挪到 Node 侧之后造数据**快了一个来回**：往 localStorage 那份副本上写之前必须先
>   `nudgeSync()` + 等 `schedule-app-v4` 出现，否则 `JSON.parse(null).ui` 当场炸
>   （`browser-cards` 首跑就是这么红的，不是主程序坏了）。
> - **往表单里灌值按属性认字段**（`input[autocomplete="username"]` / `input[type="password"]`），
>   别按 `querySelectorAll('form input')` 的下标取 —— 表单加一行就把值灌错地方，
>   而红点在好几节之后的「等不到侧栏」。见 [踩坑-环境.md](踩坑-环境.md)
>   「探针取表单字段按属性取，不按位置」。
> - **`persist()` 有 250ms 防抖**：改完立刻读 localStorage 拿到的是上一版，断言会假红，
>   而且红在「归属没切过去」这种看着像逻辑 bug 的位置（见「踩坑 30」「踩坑 43」）。
> - **合成点击**要带 pointerdown（见「踩坑 32」）；**方向键**走 CDP `Input.dispatchKeyEvent`
>   按真实焦点派发（「踩坑 33」）；**`[role="dialog"]` 有歧义**（「踩坑 34」）。
> - **导航入口按屏走两条**：`[data-nav="…"]` 只在宽屏的侧栏里；窄屏侧栏整个不渲染，
>   入口在底栏 —— 而 `settings` 恒不在 `ui.tabs` 里（`CUSTOMIZABLE` 排掉了它），
>   只能「更多」那一格 → `.more-sheet [data-nav="settings"]`。写死一条的探针会红在
>   「等不到设置页」这种跟被测行为毫无关系的地方（第九节头一版就栽在窄屏那一半，
>   因为前五节最后把视口留在了 390）。同理：**要量什么屏就自己 `setDeviceMetricsOverride`**，
>   别蹭前一节留下的那一档 —— 顺序一动，量到的屏就漂，而且没有断言会报警。
> - **假模型判轮次**不能数「第几次调用」—— 一被 SDK 重试串扰就错位，且**一条报错都没有**。
>   改成看这一轮 `messages` 里有没有 `role:'tool'`（「踩坑 39」）。SSE 流**必须以
>   `data: [DONE]` 结尾**，漏了就一直等。
> - **量「竖直居中」不能当场量一次**：`ResizeObserver` 还没回调，偶发假红。用轮询到稳定的
>   小工具（`settleCenter()`），**不用 `waitFor`** —— 它超时抛异常会把后面几十条全带走。
> - **无头浏览器的限度**：合成触摸不驱动原生滚动（只能断言「没有谁写 scrollTop」）；
>   真软键盘造不出来（只验 `--kb` 管道两端）；无头 Chrome 有 526px 宽度下限
>   （窄屏靠 `matchMedia` 套 Proxy 强判，见「踩坑 24」）。这几种的真机那一半只能人看。

> 每节在验什么，读 `app/tests/sections/smoke/NN.mjs` 顶部那段注释 —— 那里写着这一节
> 为什么存在、验过它有牙的那次改动是什么。**文档不再复述断言内容。**

> 2026-10-28 补的这一段。之前 `app/package.json` 里那个 `src/sync/*.test.ts` glob
> **匹配不到任何文件** —— 同步层（`outbox` / 游标 / 单飞 / 退回分类 / 攒批与轮询）
> 一条单测都没有，全靠肉眼和探针守着。现在七个文件 58 条，都在 `cd app && npm test` 里。

垫片只有一份：`app/src/sync/testenv.ts`（**只给测试用**）—— 内存版 `localStorage`、
记请求的假 `fetch`（`__status` 造错误响应、`__throw` 造「请求根本没发出去」）、
一个集 + owner 的初始 state、`signIn()`。其余一律用真代码：`store`、`api`、`round`、
`syncNow`、`bootstrap` 都是真模块。**别在测试里重写一份假引擎**，那样测的是垫片。

| 文件 | 条 | 锁的是哪件事 |
|---|---|---|
| `rejected.test.ts` | 7 | 三种退回必须分开：`bad_request` / `forbidden` 是终态**丢掉**（留着会永远堵在发件箱最前面，forbidden 留着的另一层危险是「哪天被重新授权，几个月前的改动突然生效」）；`clock` **必须留着**（丢掉等于用户那几次操作凭空消失）。混在一批里时提示按 clock 说，两套措辞不许互相顶包 |

- `helpers.ts` 里那句「当前离线，改动先存在本机，联网后会自动同步」**在同步这条路上进不去**：
  断网时 `fetch` 抛的 TypeError 已经被 `data/api/request.ts` 接住、换成
  `ApiError(0, '连不上服务器')`，于是 `describe` 第一支就命中、直接返回那句 message，
  `navigator.onLine` 那一支永远轮不到（全项目 `describe` 只有 `syncNow.ts` 一个调用点）。
  该给用户哪句是产品判断，所以 `helpers.test.ts` **锁的是现状不是愿望**，注释里点明了这一支目前到不了。
- 服务端一次最多回吐 `MAX_PULL`(5000) 条变更，被截断时游标只推到本批最后一条（对的），
  但客户端 `syncNow` 的循环在「发件箱空了」那一支先 break —— 于是**截断剩下的要等下一次触发**

  没写测试冻住它，因为那是把一个疑似缺口写成「应该这样」。

**接口层新加的两条**（`server/tests/api.test.js`）：`HEAD` 走它对应 `GET` 的那条路由
（头一致、body 为空、鉴权不绕过），以及「地址在、方法不对 → 405 带 `Allow`，
地址真不存在才 404」。规矩本身写在 [接口.md](接口.md)。

## 界面约定锁在哪些节

[界面规则.md](界面规则.md)里每条都有断言钉着，改约定时要知道去哪儿看：

| 约定 | 锁在哪 | 怎么验的 |
|---|---|---|
| 每个控件都有可访问名字 / 勾选圈走 `<CheckBtn>` / 命中区 ≥24 | **第五节**（管理浮层，联网时跑：成员是拉的，断网后角色下拉根本不渲染）和**第十四节**（待办箱 / 抽屉 / 月视图，断网后跑） | `a11y(root)` 收一个可选选择器，**扫浮层时一定要传** —— 不传就扫全文档，侧栏里任意一个没名字的控件都会算到浮层那条断言头上，失败信息指错地方（这个探针里栽过一次，见踩坑 32） |
| 浮层的语义与焦点（`role=dialog` / 焦点陷阱 / 焦点还回） | **第十六节** | 从**最后一个**可聚焦元素按 Tab（从中间按证不了什么 —— 前后都在浮层里，圈不圈都一样），再按 Escape 看焦点有没有回到开浮层前那个输入框 |
