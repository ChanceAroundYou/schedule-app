## 跑什么

```bash
cd app          && npm test                     # 191 条（node --test，跑 *.test.ts）
cd app          && npm run typecheck
cd app          && node tests/contrast.mjs      # 文字 72 对 ≥4.5 · 描边 8 对 ≥3 · 变量名 · 兜底值 · .tsx 圆角类，零依赖
cd app          && node tests/color-scan.mjs    # 语义样式模块 + tailwind.css 里的写死圆角 / 边框 / 颜色 + 原生 <select> 归零
npm test                                        # 根目录：server/tests/ 那三个 node --test 文件
node server/tests/api.test.js                   # 54 条接口
node server/tests/migration.test.js             # 8 条 schema 迁移
node --test server/tests/ai.test.js             # 19 条 AI 层（假模型，不联网不烧额度）
node server/tests/smoke-share.mjs               # 两个人共用一个集，真走网络
cd app          && node tests/browser-smoke.mjs   # 492 条（无头 Chrome + CDP，零 npm 依赖）
CHROME=/path/to/chrome node app/tests/card-geometry.mjs   # 卡片几何 + 手势分工（六屏全量表 + 断言，770+ 条，含五·C 滚位那组）
CHROME=/path/to/chrome node app/tests/browser-cards.mjs   # 卡片皮肤（四面同一条框 / 主色不画竖线）
CHROME=/path/to/chrome node app/tests/week-look.mjs       # 周视图两档：字号 / 表头 / 时间行判据
CHROME=/path/to/chrome node app/tests/android-live-check.mjs  # 真机口径的周视图读数（时间行只由时长决定）
```

> 探针一律从**仓库根**起跑（`CHROME=… node app/tests/xxx.mjs`）。`cd app` 再跑也行，
> 但脚本里的 `ROOT` 是从文件位置算的，别照抄成相对路径。
> `CHROME` 在本机是 `/tmp/schedchrome/chrome` 那个 wrapper（走 headless shell）——
> playwright 目录里的 `chrome` 起不来，`chrome_crashpad_handler` 没有执行位
> （[踩坑 24](踩坑-环境.md)）。
>
> **后两个探针跟其它探针不是一类**，红了先别去翻代码：
> - `week-look.mjs` **默认打线上伺服的那份**（`LIVE_URL` 没给就是线上）。本地改完还没发布时
>   它会红，红的含义是「线上还是旧版」。要比本地：先起 dev，再
>   `LIVE_URL=http://127.0.0.1:11717/ node app/tests/week-look.mjs`。
>   2026-10-24 两边各跑过一次，同一条 180 分钟的窄屏周视图卡：线上「不显示」、本地「显示（09:00 – 12:00）」。
> - `android-live-check.mjs` 要**真机**：`--device <IP:端口>` 是手机投过来的调试地址，
>   没有它直接打用法退出（本机跑不了）。它验的是真机上的触摸与滚动，无头补不了。

后面两个会**自己起一个临时后端**（临时数据库 + 随机端口），不碰线上那份。
`smoke-share.mjs` 覆盖的是单元测试测不到的东西：限速之外的所有跨用户路径 ——
邀请 → 接受 → 跨账号同步 → 降级为只读后被拒 → 移出后写不进去。

界面照一遍（真实 Chrome + CDP，零 npm 依赖）：

```bash
cd app && node tests/browser-smoke.mjs
```

它自己起一套**完全隔离**的环境（临时后端 + 带 /api 代理的静态服务 + 独立
Chrome profile），然后像人一样走：**第一趟就查缓存里有没有那 5 条** →
注册 → 顶栏出现日程集多选 → 六个视图都不白屏 → 管理浮层改名 →
**确认服务器上真改了** → 刷新还在 → 收到邀请 → 接受 → 切到新集 →
**长按提起 → 拖到别处排序**（长按操作层已于 2026-10-11 删除，现在原地松手不弹任何东西） →
**鼠标拖拽同一套落点** → **被降成只读后提示点名集名** →
**另一台设备改过同一字段 → 抽屉里那条提示 → 知道了** →
**AI 提案卡片 → 确认 → 服务器上真有** →
离线小标 → **把静态服务关掉还能打开** → 无障碍点名 → **方向键微调时间轴把手** →
**软键盘变量 --kb 两端接没接上** → **抽屉的 dialog 语义与焦点圈**。
全程收集 console 报错，有一条就算失败。

> 之所以不用 `vite preview`：它的代理写死指向 25692，**那是线上后端**，
> 探针会往生产库里写账号。隔离是这里的第一要求。
> 浏览器路径用 `CHROME` 环境变量覆盖，默认 `/opt/google/chrome/chrome`。

> **跑完测试必须收干净，否则下一轮会假失败。** 三条，都是踩过的：
>
> - **Chrome 进程**：`browser-smoke.mjs` 起的无头 Chrome 被 kill / OOM 之后会残留，
>   实测一次能攒到 30 多个，把 12 GB 内存吃到见底，下一轮直接被 SIGKILL
>   （exit 137，报在「等不到侧栏渲染」上，看着像产品 bug）。跑完
>   `pkill -x chrome`（`chrome_crashpad_handler` 一并），再
>   `ps aux | grep -c '[c]hrome'` 确认归零。
> - **测试服务进程**：`browser-smoke.mjs` 的静态服务（5198）与临时后端（25701）、
>   `smoke-share.mjs` 的后端，被中断后都还留在监听。跑完
>   `ss -ltnp | grep -E '5198|25701'` 找出 pid `kill` 掉，确认端口空了再跑下一轮。
>   顺带清掉临时库 `rm -rf /tmp/sched-browser-*`。
> - **端口**：不用手工避让了。`browser-smoke.mjs` 的四个端口（25701 / 5198 / 9223 /
>   25711）**首选被占就自动往后让开**，起手打一行
>   `端口：后端 25712 · 页面 5209 · CDP 9234 · 假模型 25711（首选 25701 被占，已让开）`
>   —— 撞了端口靠这一行定位是哪一趟占的。要**钉死**用 `SMOKE_API_PORT` / `SMOKE_WEB_PORT` /
>   `SMOKE_CDP_PORT` / `SMOKE_MODEL_PORT`（注意前缀 `SMOKE_`，不是裸的 `API_PORT`）。
>   仍然要收干净：避让只管**这一趟**，撞着的那一趟照样占着端口，而且**新起的那个会静默
>   失败、探针转去连上一个残留的旧后端**，报出来的错（实测是注册 409）完全指错地方。
>   细节见 [踩坑-环境.md](踩坑-环境.md) 的坑 40。

> **第八节（触屏）和第九节（鼠标）测的是同一件事的两个入口。**
> 两条路共用 `applyDropAt` / `finishDrag` / `commitDrop`，所以第八节证的是
> 「手势对不对」，第九节证的是「鼠标这条**接线**还通着」——
> 重构共享代码时最先坏的就是 `dragstart` / `dragover` 那几个 handler 的接线，
> 而触屏那条根本不发这些事件，光靠第八节看不出来。
> 验过它有牙：**把 `onDragStart` 里的 `dragId = id` 删掉**，只有第九节失败
> （3 条），第八节照常全绿。

> 离线那一段有两处是**为了让断言有牙**才那么写的，别当成多余的：
>
> - 探针自己的静态服务对 HTML 回 `cache-control: no-store`。不然服务器关掉之后
>   Chrome 自己的 HTTP 缓存也能把 index.html 交出来，测试会假通过
>   （真实 nginx 给 `/schedule/` 配的也是 no-cache）。
> - 关服务前要 `closeAllConnections()`。光 `close()` 只停止接受新连接，
>   Chrome 池子里那条 keep-alive 还能把请求送进来，同样是假通过。
> - **「第一趟就查缓存」必须在第一趟查**（探针的第「零」节，在第一次导航之后、
>   任何刷新之前）。放到后面查就区分不出「安装时预缓存了」和「后来被动存下来的」——
>   而后者正是线上踩过的那个坑：真实站点上第一次访问 `caches` 是空的。
>
> 验过它有牙：**把 `dist/sw.js` 挪走再跑，探针会在「Service Worker 接管页面」
> 那一步中断**。改这块之后建议照做一遍。

> 探针里的 `waitFor` 条件要**只可能因为那件事成立**。踩过一次：等
> 「成员列表加载完」写的是 `innerText.includes('创建者')`，而那是 ROLE_LABEL，
> 发邀请那个 `<select>` 的 `<option>` 里就有一个 —— 浮层一开就成立，等于没等。
> 失败信息是「成员列表里有自己」，指向完全错的地方。现在等的是成员**条数**非零。
> 另外它**不能以换行开头**（ASI 会把 `return` 断成空语句），见「踩坑 29」。

> 第「十」节专测**只读成员被挡下时的提示**：真把爸爸降成 viewer → 真点勾选
> → 真看提示里有没有集名。分两段等（本地 cals 的角色先、DOM 后）—— 合成
> 一个条件的话，超时时分不清「同步没发生」和「同步到了但界面没画」。
> 写这一节时踩到「合成点击少了 pointerdown」，见「踩坑 32」。

> 第「十一」节专测**冲突提示的接线**：判定本身在 `domain/merge.ts` 有单测，
> 这里证的是「引擎把这一轮推的 op 和这一轮拉回的改动对上了没有」。
> 做法是从 Node 侧用**另一台设备**的 `deviceId` 推一条 ts 更晚的改动
> （ts = 现在 + 30 秒 → 那边赢，最吓人的那种：用户刚打的字变回去了），
> 再在本机改同一个字段、真点开抽屉看那条提示、真点「知道了」看它落盘。
> 验过它有牙：把 `engine.ts` 里那句 `store.addConflicts(...)` 拔掉重建，
> 只在「冲突记到本地」那一步中断。
> 写这一节时踩到 `persist()` 防抖（见「踩坑 30」）和 waitFor 只吃表达式（「踩坑 29」）。

> 第「十二」节专测 **AI 写路径的接线**：模型调工具 → 工具造提案 → SSE 推卡片 →
> 用户点确认 → 服务器落库。它自己另起一个 **40 行的假模型服务**（说 OpenAI
> chat-completions + SSE，第一轮吐一个 `create_task` 的 tool_call、第二轮吐文本
> 收尾），所以不联网、不烧额度。四条断言分别卡：卡片文案对 → **确认之前**服务器上
> 没有 → 确认之后有 → 那条的 `_dev.title === 'ai'`（证明是 AI 这条路写的，
> 不是碰巧被别的路径建出来的）。
> 假模型服务返回的流**必须以 `data: [DONE]` 结尾**，SDK 认这个（见
> `openai/src/core/streaming.ts:133`），漏了就一直等。
> 写这一节踩到四个探针自己的坑：`.ai-input` 是 **textarea**，value setter 要用
> `HTMLTextAreaElement` 的原型（拿 `HTMLInputElement` 的来 call 会当场
> `Illegal invocation`）；`snapshot.tasks` 是**按 id 索引的对象**不是数组
> （见 `server/lib/sync.js` 的 `snapshot`），写 `.some()` 直接 TypeError；
> **假模型判轮次不能数「第几次调用」**（见「踩坑 39」）—— 那个全局计数一被
> SDK 重试或别的来源串扰就错位，第一轮拿到文本收尾，卡片永远不出现且
> **一条报错都没有**（约 1/9 概率）。改成看这一轮 `messages` 里有没有
> `role:'tool'`。
> 另外等待拆成了**两段**（先 `.ai-msg.user` 气泡、再 `.ai-prop`），
> 超时时才分得清「回车没接上」和「往返慢」—— 同第「十」节那两段等。
>
> 第「十三」节（2026-10-06）专测**时间轴上下沿的键盘通路**：
> `Tab` 能不能够到那两个把手、方向键有没有按 `data-act` 接到对的那一端。
> 用 CDP 的 `Input.dispatchKeyEvent` 按**真实焦点**派发（见「踩坑 33」），
> 不是自己在页面里造一个 target。算式本身（15 分钟一档、上沿固定底边）
> 在 `domain.test.ts` 的 `nudgeEdge` 用例里，这一节只管接线。

## 界面约定锁在哪些节

`AGENTS.md` 的「三、界面硬规则」里每条都有断言钉着，改约定时要知道去哪儿看：

| 约定 | 锁在哪 | 怎么验的 |
|---|---|---|
| 每个控件都有可访问名字 / 勾选圈走 `<CheckBtn>` / 命中区 ≥24 | **第五节**（管理浮层，联网时跑：成员是拉的，断网后角色下拉根本不渲染）和**第十四节**（待办箱 / 抽屉 / 月视图，断网后跑） | `a11y(root)` 收一个可选选择器，**扫浮层时一定要传** —— 不传就扫全文档，侧栏里任意一个没名字的控件都会算到浮层那条断言头上，失败信息指错地方（这个探针里栽过一次，见踩坑 32） |
| 浮层的语义与焦点（`role=dialog` / 焦点陷阱 / 焦点还回） | **第十六节** | 从**最后一个**可聚焦元素按 Tab（从中间按证不了什么 —— 前后都在浮层里，圈不圈都一样），再按 Escape 看焦点有没有回到开浮层前那个输入框 |
| 状态语义（`aria-current` / `aria-expanded`） | **第十六节**最后三条 | 侧栏有且只有当前项带 `aria-current="page"`（和 `.active` 对得上），找日期那个按钮的 `aria-expanded` 跟着开合 `false → true` |

**第十八节补强**（2026-10-09，四条报障）：功能区那节原来只验了「点一下勾选」和
「拖一下排序落库」，**没验拖动之后底栏有没有跟着变** —— 而底栏读的是 `ui.tabs` 自己的
顺序、`store.setUi()` 又不跑归一，于是「拖完底栏纹丝不动、刷新才对」这个 bug
一直没被任何断言看过（见[踩坑 49](踩坑-前端.md)）。现在补上：

- 窄屏：`dragNav('habits','today')` 之后 **`.tabbar` 的文字顺序当场就变**（不刷新、
  不再点一次勾选），`ui.tabs[0]` 与 `navOrder[0]` 同步落盘
- 两种设备都验：网格里**勾中的全排在没勾的前面**，不再交叉排列
- 跨组拖拽的**落点被钳回本组**（显示项拖进隐藏区 → 显示组末位；反向 → 隐藏组最前位）
- 宽屏：`.sidebar .nav-item` 的 computed `cursor` 不是 `grab`；有隐藏项时侧栏底部
  出现「更多」，浮层里列出的正是那几项、点一下切过去且浮层自收、Escape 关掉并把焦点
  还回触发键；一个都没藏时入口不画

> 拖动靠新加的 `dragNav()`：合成 `mousedown → mousemove → mouseup`，
> **三步之间要 `setTimeout` 分开**。dnd-kit 的 `MouseSensor` 走 `mousedown` 那条路，
> 同一个 tick 里连发的话 React 还没重渲染，handler 闭包里的状态是旧的。

> **第十九节里挑「日程集」那一段不复用 `clickEl`**，走 `tapEl`（mousedown →
> mouseup → click）。原因是这一段验的是**嵌套浮层**：新建项目浮层里的 `SheetPicker`
> 那层是 portal 到 `body` 的，外层 `Sheet` 收不收起听的是 `useOutsideClose` 的
> **capture 阶段 mousedown**。DOM 上里层不是外层的后代，`contains` 判不出来 —— 不修
> `useOutsideClose` 的话，真手点一下选项就先把**外层**关掉、连带把选项那层卸载，
> 这一次点击白丢。而 `clickEl` 只派发 pointerdown / pointerup / click，**不派发
> mousedown**，所以它照样绿 —— 这个盲区跟 `hooks.ts` 里 `useOutsideClose` 注释记的
> 是同一个坑（「只在真机上出现，合成 click 测不出来」）。
> 判据写的是 `document.querySelectorAll('[role="dialog"]').length === 2`：
> 外层要是被误关，这里只剩 1 个。

**第十四之二（时间窗）这一轮换掉的抓手**（2026-10-08）：

- 时间窗的两个原生 `<select>` 换成 `Dropdown` 之后，`[data-day-win]` 这个抓手
  **没有了**：`setWindow()` 原先是用原生 value 描述符 + `change` 事件直接灌值的，

  再点 `[role="option"]`。菜单 `max-h-64` 会滚动，但 25 个整点在 DOM 里一个不少，
  所以按文字点就是。

  换控件就得连抓手一起换，否则那条断言会红在「等不到元素」上，而不是红在
  「行为不对」上，后者才信息量大。
- 顺带补上了一条**无障碍**：原先那两个 `<select>` 有 `id` 但**没有对应的

  所以这个洞藏得住。换 `Dropdown` 之后 `aria-label` 是它自带的，洞自己就没了。
