## 跑什么

```bash
cd app          && npm test                     # 193 条（node --test，跑 *.test.ts）
cd app          && npm run typecheck
cd app          && node tests/contrast.mjs      # 文字 68 对 ≥4.5 · 描边 8 对 ≥3 · 变量名 · 兜底值 · .tsx 圆角类，零依赖
cd app          && node tests/color-scan.mjs    # 语义样式模块 + tailwind.css 里的写死圆角 / 边框 / 颜色 + 原生 <select> 归零

node server/tests/api.test.js                   # 56 条接口
node server/tests/migration.test.js             # 8 条 schema 迁移
node --test server/tests/ai.test.js             # 19 条 AI 层（假模型，不联网不烧额度）
node server/tests/smoke-share.mjs               # 两个人共用一个集，真走网络
node app/tests/browser-smoke.mjs                # 500+ 条（无头 Chrome + CDP，零 npm 依赖）
CHROME=/path/to/chrome node app/tests/card-geometry.mjs   # 卡片几何 + 手势分工（六屏全量表 + 断言）
CHROME=/path/to/chrome node app/tests/browser-cards.mjs   # 卡片皮肤（四面同一条框 / 主色不画竖线）
CHROME=/path/to/chrome node app/tests/week-look.mjs       # 周视图两档：字号 / 表头 / 时间行判据
CHROME=/path/to/chrome node app/tests/android-live-check.mjs  # 真机口径的周视图读数（时间行只由时长决定）
```

> 探针一律从**仓库根**起跑（`CHROME=… node app/tests/xxx.mjs`）。`cd app` 再跑也行，
> 但脚本里的 `ROOT` 是从文件位置算的，别照抄成相对路径。
> `CHROME` 在本机是 `/tmp/schedchrome/chrome` 那个 wrapper（走 headless shell）——
> playwright 目录里的 `chrome` 起不来，`chrome_crashpad_handler` 没有执行位
> （[踩坑 24](踩坑-环境.md)）。
>
> **后两个探针跟其它探针不是一类**，红了先别去翻代码：
> - `week-look.mjs` **默认打线上伺服的那份**（`LIVE_URL` 没给就是线上）。本地改完还没发布时
>   它会红，红的含义是「线上还是旧版」。要比本地：先起 dev，再
>   `LIVE_URL=http://127.0.0.1:11717/ node app/tests/week-look.mjs`。
>   2026-10-24 两边各跑过一次，同一条 180 分钟的窄屏周视图卡：线上「不显示」、本地「显示（09:00 – 12:00）」。
> - `android-live-check.mjs` 要**真机**：`--device <IP:端口>` 是手机投过来的调试地址，
>   没有它直接打用法退出（本机跑不了）。它验的是真机上的触摸与滚动，无头补不了。

### 探针的代码结构

三个大探针已拆成 **`lib/` 公共层 + `sections/` 分节**，入口文件只留编排：

| 入口 | 分节目录 | 说明 |
|---|---|---|
| `browser-smoke.mjs` | `sections/smoke/00–26.mjs` | 27 节，共享状态走 `ctx.state`，helper 走 `ctx.helpers` |
| `card-geometry.mjs` | `sections/geom/00–07.mjs` | 00 是六屏测量，01–07 是七组断言 |
| `android-live-check.mjs` | `sections/android/01–04.mjs` | 按 `--features` 分组（core / now-line / month / repeat） |

公共层：`lib/probe-env.mjs`（端口 / Chrome / 数据目录 / dist）、`lib/cdp.mjs`
（connect / evalJs / waitFor / touch / key）、`lib/server.mjs`（静态 + /api 代理）、
`lib/probe-assert.mjs`（`ok()` 计数）。**改断言先看对应那一节，别改入口。**

探针都会**自己起一个临时后端**（临时数据库 + 随机端口），不碰线上那份。
`smoke-share.mjs` 覆盖的是单元测试测不到的东西：限速之外的所有跨用户路径 ——
邀请 → 接受 → 跨账号同步 → 降级为只读后被拒 → 移出后写不进去。

界面照一遍（真实 Chrome + CDP，零 npm 依赖）：

```bash
node app/tests/browser-smoke.mjs
```

它自己起一套**完全隔离**的环境（临时后端 + 带 /api 代理的静态服务 + 独立
Chrome profile），然后像人一样走：**第一趟就查缓存里有没有那 5 条** →
注册 → 顶栏出现日程集多选 → 六个视图都不白屏 → 管理浮层改名 →
**确认服务器上真改了** → 刷新还在 → 收到邀请 → 接受 → 切到新集 →
**长按提起 → 拖到别处排序**（长按操作层已于 2026-10-11 删除，现在原地松手不弹任何东西） →
**鼠标拖拽同一套落点** → **被降成只读后提示点名集名** →
**另一台设备改过同一字段 → 抽屉里那条提示 → 知道了** →
**AI 提案卡片 → 确认 → 服务器上真有** →
离线小标 → **把静态服务关掉还能打开** → 无障碍点名 → **方向键微调时间轴把手** →
**软键盘变量 --kb 两端接没接上** → **抽屉的 dialog 语义与焦点圈**。
全程收集 console 报错，有一条就算失败。

> 之所以不用 `vite preview`：它的代理写死指向 25692，**那是线上后端**，
> 探针会往生产库里写账号。隔离是这里的第一要求。
> 浏览器路径用 `CHROME` 环境变量覆盖，默认 `/opt/google/chrome/chrome`。

> **跑完测试必须收干净，否则下一轮会假失败。** 三条，都是踩过的：
>
> - **Chrome 进程**：`browser-smoke.mjs` 起的无头 Chrome 被 kill / OOM 之后会残留，
>   实测一次能攒到 30 多个，把 12 GB 内存吃到见底，下一轮直接被 SIGKILL
>   （exit 137，报在「等不到侧栏渲染」上，看着像产品 bug）。跑完
>   `pkill -x chrome`（`chrome_crashpad_handler` 一并），再
>   `ps aux | grep -c '[c]hrome'` 确认归零。
> - **测试服务进程**：`browser-smoke.mjs` 的静态服务（5198）与临时后端（25701）、
>   `smoke-share.mjs` 的后端，被中断后都还留在监听。跑完
>   `ss -ltnp | grep -E '5198|25701'` 找出 pid `kill` 掉，确认端口空了再跑下一轮。
>   顺带清掉临时库 `rm -rf /tmp/sched-browser-*`。
> - **端口**：不用手工避让了。`browser-smoke.mjs` 的四个端口（25701 / 5198 / 9223 /
>   25711）**首选被占就自动往后让开**，起手打一行
>   `端口：后端 25712 · 页面 5209 · CDP 9234 · 假模型 25711（首选 25701 被占，已让开）`
>   —— 撞了端口靠这一行定位是哪一趟占的。要**钉死**用 `SMOKE_API_PORT` / `SMOKE_WEB_PORT` /
>   `SMOKE_CDP_PORT` / `SMOKE_MODEL_PORT`（注意前缀 `SMOKE_`，不是裸的 `API_PORT`）。
>   仍然要收干净：避让只管**这一趟**，撞着的那一趟照样占着端口，而且**新起的那个会静默
>   失败、探针转去连上一个残留的旧后端**，报出来的错（实测是注册 409）完全指错地方。
>   细节见 [踩坑-环境.md](踩坑-环境.md) 的坑 40。

> **触屏（第八节）和鼠标（第九节）测的是同一件事的两个入口。**
> 两条路共用 `applyDropAt` / `finishDrag` / `commitDrop`，所以第八节证的是「手势对不对」，
> 第九节证的是「鼠标这条**接线**还通着」—— 重构共享代码时最先坏的就是那几个 handler 的
> 接线，而触屏那条根本不发这些事件，光靠第八节看不出来。验过它有牙：**把
> `onDragStart` 里的 `dragId = id` 删掉**，只有第九节失败（3 条），第八节照常全绿。

> 离线那一段有两处是**为了让断言有牙**才那么写的，别当成多余的：
>
> - 探针自己的静态服务对 HTML 回 `cache-control: no-store`（真实 nginx 给 `/schedule/`
>   配的也是 no-cache）。不然服务器关掉之后 Chrome 自己的 HTTP 缓存也能交出 index.html。
> - 关服务前要 `closeAllConnections()`。光 `close()` 只停止接受新连接，Chrome 池子里
>   那条 keep-alive 还能把请求送进来，同样是假通过。
> - **「第一趟就查缓存」必须在第一趟查**（第「零」节，第一次导航之后、任何刷新之前）。
>   放到后面就区分不出「安装时预缓存了」和「后来被动存下来的」—— 后者正是线上踩过的坑：
>   真实站点上第一次访问 `caches` 是空的。
>
> 验过它有牙：**把 `dist/sw.js` 挪走再跑，探针会在「Service Worker 接管页面」那一步中断**。

> 探针里的 `waitFor` 条件要**只可能因为那件事成立**。踩过一次：等「成员列表加载完」写的是
> `innerText.includes('创建者')`，而那是 ROLE_LABEL，发邀请那个 `<select>` 的 `<option>`
> 里就有一个 —— 浮层一开就成立，等于没等。现在等的是成员**条数**非零。
> 另外它**不能以换行开头**（ASI 会把 `return` 断成空语句），见「踩坑 29」。

> **几节共用的写法**，新写一节时照抄：
>
> - **两段等**：本地那一层（localStorage / cals 角色）先等、DOM 后等。合成一个条件的话，
>   超时时分不清「同步没发生」和「同步到了但界面没画」—— 排查方向完全相反。
>   （第十节降级、第十二节 AI 都是这么写的。）
> - **`persist()` 有 250ms 防抖**：改完立刻读 localStorage 拿到的是上一版，断言会假红，
>   而且红在「归属没切过去」这种看着像逻辑 bug 的位置（见「踩坑 30」「踩坑 43」）。
> - **合成点击**要带 pointerdown（见「踩坑 32」）；**方向键**走 CDP `Input.dispatchKeyEvent`
>   按真实焦点派发（「踩坑 33」）；**`[role="dialog"]` 有歧义**（「踩坑 34」）。
> - **假模型判轮次**不能数「第几次调用」—— 一被 SDK 重试串扰就错位，且**一条报错都没有**。
>   改成看这一轮 `messages` 里有没有 `role:'tool'`（「踩坑 39」）。SSE 流**必须以
>   `data: [DONE]` 结尾**，漏了就一直等。
> - **量「竖直居中」不能当场量一次**：`ResizeObserver` 还没回调，偶发假红。用轮询到稳定的
>   小工具（`settleCenter()`），**不用 `waitFor`** —— 它超时抛异常会把后面几十条全带走。
> - **无头浏览器的限度**：合成触摸不驱动原生滚动（只能断言「没有谁写 scrollTop」）；
>   真软键盘造不出来（只验 `--kb` 管道两端）；无头 Chrome 有 526px 宽度下限
>   （窄屏靠 `matchMedia` 套 Proxy 强判，见「踩坑 24」）。这几种的真机那一半只能人看。

> 每节在验什么，读 `app/tests/sections/smoke/NN.mjs` 顶部那段注释 —— 那里写着这一节
> 为什么存在、验过它有牙的那次改动是什么。**文档不再复述断言内容。**

## 界面约定锁在哪些节

`AGENTS.md` 的「三、界面硬规则」里每条都有断言钉着，改约定时要知道去哪儿看：

| 约定 | 锁在哪 | 怎么验的 |
|---|---|---|
| 每个控件都有可访问名字 / 勾选圈走 `<CheckBtn>` / 命中区 ≥24 | **第五节**（管理浮层，联网时跑：成员是拉的，断网后角色下拉根本不渲染）和**第十四节**（待办箱 / 抽屉 / 月视图，断网后跑） | `a11y(root)` 收一个可选选择器，**扫浮层时一定要传** —— 不传就扫全文档，侧栏里任意一个没名字的控件都会算到浮层那条断言头上，失败信息指错地方（这个探针里栽过一次，见踩坑 32） |
| 浮层的语义与焦点（`role=dialog` / 焦点陷阱 / 焦点还回） | **第十六节** | 从**最后一个**可聚焦元素按 Tab（从中间按证不了什么 —— 前后都在浮层里，圈不圈都一样），再按 Escape 看焦点有没有回到开浮层前那个输入框 |
| 状态语义（`aria-current` / `aria-expanded`） | **第十六节**最后三条 | 侧栏有且只有当前项带 `aria-current="page"`（和 `.active` 对得上），找日期那个按钮的 `aria-expanded` 跟着开合 `false → true` |
| 降低动态效果（全站关） | **第十六节** | 先量一遍**没开时**的值当基准，再 `Emulation.setEmulatedMedia` 切到 `reduce` 量第二遍 —— 不量基准的话「过渡是 0s」可能本来就是（压根没写过渡），断言会假通过 |
| **卡片几何同源**：圆角 = 短边 × 0.28（夹 2px~`--r-xl`）· 打勾左侧间距同值 · 周视图表头两档同步 | **`app/tests/card-geometry.mjs` 第一、二、四节**（六屏全量表：日 / 周 / 月 × 1400 / 390） | 断言用**卡自己的短边**算 want 再比（容差 0.6px），**不写死 7px 这种档** —— 写死的数字换个窗口就红。间距那条只比「同一屏上所有卡一致」，窄屏月胶囊没有勾选圈（`checkGap = null`）不参与比对。探针自己起临时后端 + 临时 profile，`CHROME=` 必填 |
| **时间行只由时长决定**：> 60 分钟必须有且完整在卡里 · ≤ 60 必须没有 · 月视图永远没有 · 时间行左端 = 标题**文字**左端 · 圈径 = 字号 × `--check-k`（现在 1，夹 9~18）· 圈中心落在整块文字中线上 · **装不下只压不加长** | **`app/tests/card-geometry.mjs` 第三节**（六屏 × 逐张卡）；`week-look.mjs` / `android-live-check.mjs` 从两个方向再钉一遍时间行 | 种子是**七条定时卡 120 / 90 / 75 / 61 / 60 / 45 / 30 分钟**（各一条），判据是 `时长 > 60` 与「这一张卡有没有 `.ev-time`」**必须相等** —— 61 与 60 挨着放，就是为了让「一小时」这个边界本身被跨过而不是被绕过。月视图那条断的是**元素数量**（`.pill-time` 现在根本不渲染，数出来必须是 0），不是「看不见」。圈径与居中用 `getBoundingClientRect` 实量，圆心的容差 1px。⚠️ 判据口径两边必须一样：纵向 = `.ev-text` 的 scrollHeight ≤ `.ev-body` 的 clientHeight（**不能**用 `.ev-body.scrollHeight`，勾选圈那个 24×24 的 `::before` 命中区会污染它）；横向 = `.ev-time` 的 `scrollWidth − clientWidth ≤ 0.5`。再加两条硬的：**卡上没有内联 `min-height`**、**卡高 = 按时长算出来的**（`--card-px` 与 CSS `min-height` 取大，容差 0.6px；30 分钟那条靠 `.task-el--timed { min-height: 12px }` 这条老地板，打印里点名「CSS 地板 12px 顶的」）。压缩落在第几档从卡上的 `data-fit`（`v1h2`）读，不断言档位本身。⚠️ `android-live-check.mjs` 里同口径的新两条（时间行不被横向裁 · 卡上无内联 `min-height`）**要真机才跑得起来**（`--device <IP:端口>`），本轮只改了判据、**没在真机上验过** |
| **手势分工**：长按 300ms 才开拖 · 开拖后区域不滑 · 不长按时区域照常滚 · 列表拖一行整页不滑 · **能拖的表面一律不可选字**（列表行 / 打卡行 / 功能区格都算；草稿框与垃圾箱行保持可复制） | **`app/tests/card-geometry.mjs` 第五~七节**；分身的两条在 `browser-smoke.mjs` 第十七节 | 机制层断言：在 `document` 冒泡阶段挂 `{passive: true}` 的 touchmove 探针，数「开拖前 / 开拖后」各几个、被 `preventDefault` 几个（长按趟 0/3 拦下 3，快划趟 3 拦下 0）；阈值两侧各测一次（380ms 起拖 / 200ms 不起拖）。⚠️ **无头合成触摸不驱动原生滚动** —— 「区域真没滚」只能断言到「没有谁写 scrollTop」，**真机上那一半要手工走一遍**（[踩坑 51](踩坑-前端-组件.md)）。拖出容器的做法是**分身**（`ui/dnd/lift.ts`），smoke 第十七节断言「分身仍可见」+「分身中心 = 指针位置（零偏移）」；**别再去查 `--keep` / `scrollKeep.ts`** —— 那套随 dev 合并删了（[踩坑 54](踩坑-前端-组件.md)） |
| 功能区（导航）：勾选口径 · 显示中的排在前 · 拖完底栏当场变 · 侧栏「更多」 | **第十八节**（窄屏半段 + 宽屏半段） | 拖动走 `dragNav()` 合成的 mousedown → mousemove → mouseup（dnd-kit 的 `MouseSensor` 那条路），**三步必须分开的 tick** —— 同一个 tick 里连发的话 React 还没重渲染，handler 闭包里的状态是旧的。判据：拖动后 `.tabbar` 的文字顺序**当场**变（不等刷新、不等点勾选）、`ui.tabs[0]` 跟着 `navOrder[0]` 走、勾中的格子全排在没勾的前面、跨组拖拽的落点被钳回本组、`.sidebar .nav-item` 的 computed `cursor` 不是 `grab`、有隐藏项时 `.sidebar [data-nav-more]` 才出现 |

> 最后一条有个取整细节：`getComputedStyle` 回的是**序列化后**的值 —— 写 `0.01ms`
> 它给你 `1e-05s`，所以按秒解析再比大小，**别比字符串**。

  不再点一次勾选），`ui.tabs[0]` 与 `navOrder[0]` 同步落盘
- 两种设备都验：网格里**勾中的全排在没勾的前面**，不再交叉排列
- 跨组拖拽的**落点被钳回本组**（显示项拖进隐藏区 → 显示组末位；反向 → 隐藏组最前位）
- 宽屏：`.sidebar .nav-item` 的 computed `cursor` 不是 `grab`；有隐藏项时侧栏底部
  出现「更多」，浮层里列出的正是那几项、点一下切过去且浮层自收、Escape 关掉并把焦点
  还回触发键；一个都没藏时入口不画

> 拖动靠新加的 `dragNav()`：合成 `mousedown → mousemove → mouseup`，
> **三步之间要 `setTimeout` 分开**。dnd-kit 的 `MouseSensor` 走 `mousedown` 那条路，
> 同一个 tick 里连发的话 React 还没重渲染，handler 闭包里的状态是旧的。

> **第十九节里挑「日程集」那一段不复用 `clickEl`**，走 `tapEl`（mousedown →
> mouseup → click）。原因是这一段验的是**嵌套浮层**：新建项目浮层里的 `SheetPicker`
> 那层是 portal 到 `body` 的，外层 `Sheet` 收不收起听的是 `useOutsideClose` 的
> **capture 阶段 mousedown**。DOM 上里层不是外层的后代，`contains` 判不出来 —— 不修
> `useOutsideClose` 的话，真手点一下选项就先把**外层**关掉、连带把选项那层卸载，
> 这一次点击白丢。而 `clickEl` 只派发 pointerdown / pointerup / click，**不派发
> mousedown**，所以它照样绿 —— 这个盲区跟 `hooks.ts` 里 `useOutsideClose` 注释记的
> 是同一个坑（「只在真机上出现，合成 click 测不出来」）。
> 判据写的是 `document.querySelectorAll('[role="dialog"]').length === 2`：
> 外层要是被误关，这里只剩 1 个。

**第十四之二（时间窗）这一轮换掉的抓手**（2026-10-08）：

- 时间窗的两个原生 `<select>` 换成 `Dropdown` 之后，`[data-day-win]` 这个抓手
  **没有了**：`setWindow()` 原先是用原生 value 描述符 + `change` 事件直接灌值的，
  现在改成点按钮（抓手是它的 `aria-label`「时间窗从几点开始」/「时间窗到几点结束」）
  再点 `[role="option"]`。菜单 `max-h-64` 会滚动，但 25 个整点在 DOM 里一个不少，
  所以按文字点就是。
  **教训**：探针里凡是**直接读那个 DOM 的抓手**，都和被测控件长在一起 ——
  换控件就得连抓手一起换，否则那条断言会红在「等不到元素」上，而不是红在
  「行为不对」上，后者才信息量大。
- 顺带补上了一条**无障碍**：原先那两个 `<select>` 有 `id` 但**没有对应的
  `<label htmlFor>`**（`Field` 没传 `htmlFor`，标题渲染成 `<div>`），
  等于**没有可访问名字** —— 而探针的 `a11y()` 一直没扫设置页外观那一档，
  所以这个洞藏得住。换 `Dropdown` 之后 `aria-label` 是它自带的，洞自己就没了。
