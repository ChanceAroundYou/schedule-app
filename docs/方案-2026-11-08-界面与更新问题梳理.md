## 自适应圆角资料与初步原则

### 可核对的成熟规则

1. W3C《CSS Backgrounds and Borders Module Level 3》§4.1 规定 `border-radius` 百分比按边框盒对应维度解析：水平半径看宽度、垂直半径看高度。§4.5 规定相邻半径可能重叠时，浏览器按统一比例缩小所有半径直到不重叠。这保证几何合法，但不保证不同卡片的“视觉圆润程度”一致。
2. MDN 的 `border-radius` 文档说明百分比会造成椭圆角，且按宽、高分别解析；适合按盒子比例变化，但对细长卡会产生较大的轴向差异，不能直接取代当前规则而不做视觉比较。
3. `clamp(min, preferred, max)` 可限制流体值，但本项目风格轴中 `flat` 的上限为 0，现有规则明确指出 `clamp(2px, x, 0)` 会保留最小值 2px，破坏 flat。因此如采用限幅仍须保留 `min()/max()` 的正确零上限语义或显式风格分支。
4. CSS 容器查询单位可以相对容器尺寸，但本项目卡片宽度/高度由布局直接测得；引入 container query 或 JS 新测量前，先证明现有实际尺寸输入为何不足。避免只为圆角新增尺寸观察器。
5. CSS `corner-shape: squircle` 属渐进增强选项，不是尺寸自适应的替代；Android WebView、桌面浏览器支持与视觉风格需单独验证，当前不建议作为第一步。

### 评估方向（供后续正式方案/试验）

保留单一圆角令牌与每张卡实测短边作为输入。把视觉目标定义为“半径/有效短边比例在相邻卡高度变化时平滑且可控”，分别检查最小尺寸地板、比例段、风格上限段何时切换；核算底边框/内留白后可供圆角使用的空间，避免最小高度卡仅被固定 2px 下限支配。候选可比较当前 `max(minRadius, ratio × shortSide)` 与按卡片短边分段/软上限的曲线；每个候选须在全部风格（soft/flat/notion）、日/三日/周/月、桌面/手机及窄高/宽低卡片上实际截图量几何。圆角方案确认并通过后，才调整标记右边距；标记的验收同时检查同界面统一右边缘基线与整个标记落在圆弧内。

不在此文件中预先给最终比例常数；常数须从现有卡片实际宽高分布、风格令牌及对照截图中推导并验证，而不是凭资料文章照搬。
