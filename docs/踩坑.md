## 同步 / 数据

**1. 两个 Service Worker 会打架：拆旧的那个必须只跑一次**
旧版注册过 `sw.js`（`CACHE = 'schedule-v12'`），缓存里有旧版 index.html；离线 / 抖动时
它回旧 HTML，用户看到上一版界面，**「怎么刷新都不变」**。新版自己也注册 SW
（`app/public/sw.js`），所以「注销作用域内所有 SW」会把自己刚注册的也干掉。

- 拆旧 SW（`main.tsx` 的 `migrateAwayFromLegacySW()`）用 **localStorage 标记
  `schedule-sw-migrated` 锁成一次性**：跑过就跳过，不支持 SW 的环境也要记标记。
- 删缓存只认 `/^schedule-v\d+$/`，**新版 `sched-shell-*` 不能删**。
- 重载仍要带 `sessionStorage` 标记 —— 没有它，每轮都「清理成功」就会**无限刷新**
  （无头测试里最容易把浏览器挂死的一类）。
- **dev 下不注册**（`import.meta.env.PROD`），否则缓存会骗过改代码的 dev。

新版 SW 策略：`/api/*` **不碰**（缓接口响应会拿过期数据当最新）；导航**网络优先 +
回落缓存 index.html**（缓存优先正是旧版病根）；`/assets/*` 缓存优先（文件名带哈希）；
其余同源 GET 先缓存、后台更新。预缓存清单**装的时候现场抠**（`precacheShell()` fetch
index.html 抠 `/assets/…`）—— 写死会在下次 build 后立刻过期；少了它第一次访问**存不下
东西**，「断网能用」要等第二次打开（线上实测 `caches.keys()` 是空的）。前提仍是**联网打开
过一次**；从没访问过的设备断网打开只会看到 `COLD_OFFLINE` 那张兜底页。改策略要顺手改
`CACHE` 名（现在 `sched-shell-v1`），否则 `activate` 删旧缓存不触发；`sw.js` 本身不用加版本。

**2. 拖动期间不要拉同步**
远端变更落地 → React 重绘 → 让位的 `transform` 和占位洞全部重建 → 用户看到
**「拖到一半整个列表弹回原位」**。修法在唯一的卡口：`sync/engine.ts` 的 `syncNow()`
开头 `if (isDragging()) return;`。跳过一轮没代价，outbox 还在，下个轮询自然会推上去。

**3. LWW 与 op 的三条：逐字段 · 幂等不靠 oplog · 时间戳只拒绝不钳制**
- **逐字段，不是整条。** 整条 LWW 会让人「改的东西凭空没了」（手机改标题、桌面改日期，
  后同步的把整个字段集覆盖）。逐字段代码量几乎一样，两个改动都留得住。副作用：同字段
  两边都改过时，后同步的那台会看到「字自己变了」—— 所以详情里多一条只读提示
  （见 `AGENTS.md`「同步」末）；它不改数据，只是把 LWW 的判决说出来。
- **幂等不靠 oplog。** 比较键 `(ts, deviceId)` 在**创建 op 时固定**并持久化在发件箱，
  重放时比较键相同 → `ON CONFLICT` 的 `WHERE` 不成立 → 一行都不改。**别再加一张
  「这批 op 处理过了」的表。**
- **时间戳只拒绝、不钳制。** 钳制值取决于「收到请求那一刻」，同一条 op 重放两次会钳出
  两个时间戳，**幂等性当场破掉**。现在超过 24 小时退回并标 `code: 'clock'`，客户端
  留着不丢、时钟校准后自然能推上来。

**4. 旧数据导入：先同步，再看账号空不空 —— 顺序不能反**
`sync/engine.ts` 的 `bootstrap()` 里是 `await syncNow()` **之后**才判断要不要把本机旧
数据搬上来，判据是**服务器账号里有没有东西**，不是本地 localStorage 空不空。
