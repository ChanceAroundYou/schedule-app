**5. 落点标记 `data-zone-id` 必须挂在有 padding 的元素的祖先上**
「有的任务拖不动」的真正根因（踩过两次）。这个标记原先叫 `data-drop`、挂在**内层**
`.allday-items` 上，而它有 padding：拖到 padding、任务间空隙、容器边缘时
`closest('[data-zone-id]')` 找不到 zone，`dragover` / `drop` 直接 return ——
**静默失败，无任何报错**，用户感知就是「有的能拖、有的不能」。修法：
`data-zone-id` + `data-date` 上移到最外层 `.allday-zone`，内层纯做布局。

> ⚠️ 2026-10-15：同一个标记**现在有两个消费者**，拖放（`ui/dnd/`）和点击委派
> （`clickDispatch.ts` 第 4 步 = 点空格子就地新建）。所以「改这一套命名」等于改两处行为 ——
> 反过来的失效方式也很隐蔽：2026-10-15 用户报「点格子不弹出新建」，根因正是
> dnd-kit 那次重构把视图上的 `data-drop` 换成了 `data-zone-id`，而委派那条链还照着旧名字找，
> `closest()` 静默返回 null。名字只有一处定义、两边共用，改之前先把两个消费者都找齐。
>
> **前缀不是日历专用的**：项目泳道的每一列也用它（`proj:<id>:<column>`）。委派那一侧靠
> 前缀白名单（`DRAFT_KINDS`）挑出真能开草稿的那四类（`timeline` / `allday` / `week` / `day`）。

**6. 拖动排序用「让位洞」模型，不是插入线**
拖动时其他任务实时平滑挪开，在光标处留一个占位洞 `.drop-hole`，落点由「洞在哪」表达。
**不要退回「静态插入线 + 目标格描边」**（线条只在跨格时跳一下，中间一大段位移没有反馈），
也**不用 FLIP**：直接改 DOM 顺序 + CSS transition（每帧改 DOM 太贵，transition 会和
dragover 重排互打断），实测 **180ms**（`.18s cubic-bezier(.22,.61,.36,1)`）足够顺。实现在
`ui/dnd.ts`：`zoneCells`（按**视觉 row-major** 排，不按 DOM 顺序）/ `inferCols` /
`cellUnder` / `refForIndex` / `shiftCells`（让位本体）。**判定只看「光标落在哪一格」，不
比较到各条线的远近** —— 用「最近线段」会串行：光标在格中心时上方那条线反而更近，整片区域
被判成同一档，左右拖动没准头（「只有横线、左右全靠猜」的病根）。**五条铁律**：

- **位置一律按 dragstart 时量的原始布局（`rawLayout`）**，不能用实时坐标：让位是加在元素上
  的 `transform`，`getBoundingClientRect()` 读到的是位移后的值，拿它当基准会整体偏一格
  （跨行拖动时整列被甩出容器）。
- **`left` / `top` 都按容器坐标算**：洞是 `position:absolute`，只设 `left` 它会一直停在原处
  —— **DOM 顺序变了、落库也对，就是看不见**。
- **只有落点真变了才动 DOM 顺序**（`dragover` 每秒几十次，用
  `key = scope + '|' + k + '|' + cells.length` 去重），否则让位动画一直重启更卡。
- **被拖元素留在原位压暗，不参与位移**（`shiftCells` 里 `i === selfIdx` 跳过）：让它也滑过去
  会和洞叠在一处，比不做更乱。
- **让位方向必须整段统一，不能逐格算**：夹在出处和目标之间的格子一律朝**远离出处**那侧挪一
  格（`step = k > selfIdx ? -1 : 1`）。曾写成逐格 `i < k ? i+1 : i-1`，符号反了 —— 单列下相邻
  两格挪到同一位置，**画面凭空少一条任务，洞也被压在下层看不见**。症状很有欺骗性：**落库
  顺序完全正确**、DOM 也动了，只有画面重叠。

`clearHole()` 独立成函数，不要塞进 `clearDropUI()`（后者每次 `dragover` 都会被调，会把标记
立刻抹掉）。`zoneCells` 按 `zone.dataset.kind === 'habit'` 在 `[data-habit]` 与
`[data-untimed="1"]` 之间切换：**打卡列表也走这套排序**。落点类名：`.drop-hole` 占位洞（在
用）· `.drag-muted` 被拖元素淡出（**只在鼠标那条路**）· `.touch-drag` 触屏提起阴影（在
`tailwind.css`）· `.tl-guide` 时间轴落点线 · `.tl-busy.drag-src` 拖走时隐藏原底纹 ·
`.ins-line` / `.ins-bar` / `.ins-hl` **旧插入线模型，已彻底删除（连 CSS 都没了）**。
**时间轴落点仍是画线**（`.tl-guide`），时间轴是连续坐标，「让位」在那里没有对应概念。

**7. 拖到视口上下缘会自动滚屏**
`runAutoScroll()` 用 `requestAnimationFrame` **持续**滚（不是在 `dragover` 里挪一点：
`dragover` 跟着鼠标走，鼠标不动就一顿一顿）。上下各 84px 进滚动区（`EDGE = 84`），最快每帧
17px（`MAX_SCROLL = 17`），越靠边越快。**滚完位置变了，落点必须按新位置重算**，否则洞会停
在旧处 —— 所以要保留 `dragProbe` / `dragProbeZone` 并重新 `showDropGuide()`。

**8. 高度一律用 JS 实算，不要写 `calc(100vh - N)`**
浏览器工具栏、缩放、系统字号都会让 N 猜错（实测差 22px）。正确做法是
`el.clientHeight - paddingTop - paddingBottom`（`views/Calendar.tsx` 的 `availHeight()` /
`useViewLayout()`；周 / 月视图走同一个 `fit()` 分支）。`fit()` 还负责写 `--week-head-h`
（周视图表头实测高度），因为未定时行的 `sticky top` 取的就是它，写死必错（CSS 兜底
`var(--week-head-h, 79px)`）。

**9. 月视图必须能滚**
`fit()` 对月视图**只写下限、不均分**：`gridAutoRows = minmax(下限, auto)`（先清掉
`gridTemplateRows`，否则旧的 `repeat(6, 1fr)` 会压住它）。`auto` 让内容多的行自己长高 →
`.content` 出滚动条。早期把富余高度均分到 6 行强行铺满，1920×1080 下每行 167px 却只塞
3 条任务（大片空白），而且刚好铺满时 `scrollHeight == clientHeight`，**滚轮怎么滚都没
反应**。常量在 `views/Calendar.tsx` 顶部：`MONTH_ROW_MIN=104` / `MONTH_ROW_MAX=132` /
`MONTH_HEAD_H=30` / `MONTH_CELL_MAX=8`，下限算式是
`clamp(MONTH_ROW_MIN, (可用高 - MONTH_HEAD_H) / 6, MONTH_ROW_MAX)`。
> 「每格直接列出几条」**不写死**，超出的折叠成「还有 N 项」并加 `data-jump` 可点进那天的
> 日视图；上限太大（15）会把整行撑到几百像素、同行其他天全被拉空。

**10. 窄屏断点 900px，`isNarrow()` 与 CSS 媒体查询必须一致**
`ui/hooks.ts` 的 `useIsNarrow()` 用 `matchMedia('(max-width: 900px)')`，CSS 里对应
`@media (max-width: 900px)`。**改一处必须改另一处**，否则标签栏与侧栏显隐打架。≤900px 侧栏
收进「更多」抽屉，改用底部 `.tabbar`；**逾期必须留在底栏**（不能藏进「更多」）；浮层
z-index 必须 > 标签栏的 45（现在 60 / 61），否则抽屉被压住一截。
> **浮层宽度要按「内容盒」算，不是外框。** `* { box-sizing: border-box }` 意味着 `width` 已
> 扣掉边框和内边距。`.clock-pop` 写 274px，扣两条 1px 边框和左右各 15px 内边距只剩 242px，
> 而里面 `.cp-face` **写死 246px** —— 表盘比内容盒宽 4px，`margin: 0 auto` 塌成 0，整体偏右
> 2px。现在写 278px。**凡是「里面有个写死宽度的东西」都要这么对一遍。**
> `styles/responsive.css` 里另有 `@media (max-width: 820px)` / `(max-width: 640px)`，那是排版微调
> （字号、间距），**不是**响应式断点，别混。

**11. 顶栏绝对不能加 `position` / `z-index` / `sticky`**
会生成层叠上下文，把里面的找日期面板（z-index 60）困住，被下方内容盖住变半透明（实测窄屏
下整个变半透明）。窄屏下顶栏随内容一起滚反而省垂直空间。

**12. 触屏与鼠标：两条路完全分开，只共用落点**
- `@media (hover: none)` 处理 hover 才显形的元素（抓手、箭头、背景高亮）。
- **鼠标走 HTML5 拖拽，触屏走自己的 `pointer` 通路**，输入不共用、**落点共用**：输入在
  `ui/dnd.ts` 文件头（`beginTouch` / `moveTouch` / `endTouch`）；落点（`applyDropAt` /
  `finishDrag` / `commitDrop`）**是同一份代码** —— 让位洞、时间轴预览、边缘自动滚屏只有
  一处实现。改落点逻辑时两条路一起变，这是故意的。
- 触屏手势：`pointerdown` 计时 `LONG_PRESS_MS = 480` 到点把行**提起**（`.touch-drag`，只是
  「抓住了」的反馈，还**不是**拖动）；挪过 `TOUCH_SLOP`（8px）才算「在拖」、才画落点；
  **原地松手** → 弹长按操作层 `ActSheet`。计时只在 `pointerType !== 'mouse'` 时启用。
- **抬手那一下必须把浏览器补的鼠标事件整串掐掉**（`swallowCompat` + 非 passive 的
  `touchend` 里 `preventDefault()`）。Chrome 在 `touchend` 后会在同一点补 `mousedown` /
  `mouseup` / `click`：原地松手时操作层刚打开，这串正好打在它的遮罩上，`onClick={onClose}`
  当场把操作层关掉 —— **表现是「长按完什么也没发生」**，事件日志却干净得看不出问题。只在
  「提起过」的那次吞，普通点击不受影响。
- `lp.current.fired`：长按后抬手补的 `click` 要吞掉，否则顺带打开抽屉。取消是容器上
  `onPointerMove` / `onPointerUp` / `onPointerCancel` / `onPointerLeave` 四个一起调的
  `clearLp`，不是 capture 拦截。**它的复位必须排在 `pointerDown` 里那次鼠标 `return` 之
  前**，否则鼠标这条路永远不复位，长按过后用鼠标点的第一下被静默吃掉（见 32）。
- **动作值用无歧义前缀**：`dur60` 不是 `d60`（与 `del` / `date` 撞，靠 `+slice(1) > 0` 猜
  必然误伤）。改动作值按 `/^dur(\d+)$/` 匹配。窄屏下显式 `dragstart` → `preventDefault()`，
  避免移动浏览器模拟半截行为（**只对 HTML5 那条路有意义**，触屏不发 `dragstart`）。
> 触屏这条路**已有自动化覆盖**（见 `docs/测试.md` 与 24），不必只靠真机；但探针证的是
> 「指针事件管道通」，不是「真手指在真手机上顺手」。

**13. 列表与输入框的四条小规矩**
- **`moveInList` 的候选列表不能排除自己。** 原来 `filter` 时把自己排除，`findIndex` 恒
  返回 -1、`refIdx` 永远是 0 → **「下移」永远把任务插到最前面**。现在用含自己的 `all` 定位、
  用排除自己的 `list` 取参照。
- **浮层外点击收起要用 `mousedown` + capture**（`useOutsideClose()`）。不用 capture 的话
  面板内 input 的 blur 会抢先把它关掉。
- **输入框不要在编辑时重建。** 换 DOM 节点或改正在编辑的 `value` 会让光标跳到开头；
  `Drawer.tsx` 的标题 / 备注是**本地草稿**（按 `lastId` 的 ref 记住），好让打字期间的重渲染不把光标拽走。
- **滚动位置要在 render 阶段读，不能在 effect 里读。** `useViewLayout` 要在重渲染前后保住
  `.content` / `.week-view` 的滚动位置：React 先跑完 render 再改 DOM，render 体内读
  `el.scrollTop` 拿到的是更新前的值；放进 `useLayoutEffect` 读到的已是清零后的 0。

**14. 时间轴与日期格的四条小规矩**
- **日期密度指示用淡底 + 底部短横，不要 4px 圆点。** 找日期面板与月视图日期格：有未完成
  任务的格子加淡底 + 一条短横，横宽按任务数分 3 档（`.lv2` / `.lv3`）。**圆点 4px 在 1x 屏上
  几乎看不见**。窄屏月视图格子压成圆点（`font-size:0`）是因为塞不进文字，与这里不是一回事。
- **时间轴方块两行，短任务不渲染第二行。** `.tl-event` = `.ev-head` + `.ev-time`；高度
  < 46px 时**不渲染**时间行（15 分钟短任务会被挤成两半）。时间行明显弱于标题：
  `font-size: 10.5px` / `color: var(--text-3)`。
- **时间轴上下沿都可拖。** `.ev-resize` 是下沿、`.ev-resize-top` 是上沿。上沿拖动
  `ns = clamp(start + addMin, 0, end - 15)`，**底边固定**，同时改 `time` 和 `duration`；下沿
  只改 `duration`。15 分钟步进。测试时 `.ev-resize` **同时匹配上下沿** —— 用
  `[data-act="resize-top"]` 区分，否则会误判拉伸失效。
- **已完成的未定时任务不占日程位置。** `untimedOn(iso)` = `!t.time && !t.done`，日 / 周共用。
  已完成的**定时**任务仍留在时间轴上灰显（它占着具体时间段，抹掉会丢失「那段时间做过
  什么」）。「今天」页有可折叠的「今天已完成」区块，状态存 `ui.tdoneOpen`，默认收起。

**15. 重叠任务按「重叠簇」分列**
`domain/layout.ts` 的 `layoutOverlap(events)`：先切成重叠簇（`e.start < cur.end` 并入，
否则另起一组），再在**簇内**贪心分列，每簇独立算 `cols`。旧算法把全天事件塞进一个
`colEnds`、`cols` 取全天最大值，于是**任何**一段重叠都会让当天所有方块一起变半宽 ——
不重叠的任务也跟着变窄。日视图与 `weekTimed()` 共用此函数，占用底纹与方块宽度严格一致。
> **占位底纹 `tl-busy` 必须与方块同列宽**（`left: e.col*w%` + `width: calc(w% - 4px)`）。
> 原来 `left:0; right:0` 整条铺满，两个穿插任务叠在一起时整段时间被染色。

**16. 侧栏顺序存在 `ui.navOrder` / `ui.navBottom`，`normalizeUi` 必须区分 undefined 与空数组**
状态存 `ui.navOrder`（全局顺序）+ `ui.navBottom`（哪些归底部那一组）。底部组窄屏是底部标签
栏之外的「更多」抽屉，宽屏是侧栏下半区。写入方在 2026-10-06 的「功能区自定义」里补回，入口
在**设置页**（不复用 `ui/dnd.ts`，那套是给时间轴与让位洞用的）。
> **`navBottom` 不能用「空则默认 `['trash']`」的写法** —— 那会把用户主动拖出底部的垃圾箱又
> 塞回去。必须区分「从未设置（`undefined` / 不是数组）→ 给默认」与「空数组 → 用户有意为
> 之，原样保留」。代码里就是 `bottom === null ? ['trash'] : bottom`，`domain.test.ts` 有用例
> 锁着。
其他坑：侧栏 active 高亮要用统一的 `$$('.nav-item')` 取，不能分开写 `#nav` 与 `#navBottom`。

> **`navBottom` 不再是「功能区」那个勾选框写的东西了**（2026-10-09）。那个框原先管的是
> 「挪到侧栏下面那一组」，点一下打勾，这一项就从侧栏主列里消失跑到底下去了 —— 用户看到
> 的是「勾选时消失，未勾选时显示」，正好反着；而且勾选框问的是「要不要它」、干的是
> 「换个位置」，两回事。现在勾选 = 显示：宽屏不勾就写进 `ui.navHidden`，位置只由拖拽决定。
> `navBottom` 本身留着（默认 `['trash']`），但界面里没有入口改它了。
>
> **`navHidden` 必须单开一个字段，不能靠「从 `navOrder` 里删掉」表达** —— `normalizeUi`
> 会把 `CUSTOMIZABLE` 里缺的键补回 `navOrder`（老用户本地那份顺序里没有新页），删了刷新
> 就自己回来了。和 `navBottom` 一样，空数组是合法状态（一个都没藏），不能写「空则默认」。
> **藏起来的项在渲染那一层过滤**，不在 `normalizeUi` 里删 —— 否则 `order` 一变，
> 拖拽排序的索引和用户看到的就对不上了。

**17. CSS 层叠两条：同特异度后写的赢；Tailwind 无层赢过一切**
**同特异度后写的赢，给折叠元素加类要查 `display`。** `.habit-list { display:flex }` 声明在
`.mc` 之后会覆盖 `display:grid`，必须补 `.habit-list.mc { display:grid }` 提特异度。
`.td-body` 收起时 `display:none`，但 `.mc { display:grid }` 在后面会把它强制成 grid →
**折叠的「今天已完成」区块凭空展开**，必须补 `.today-done .td-body { display:none }` +
`.today-done.open .td-body.mc { display:grid }`。
> 规律：**给折叠 / 隐藏元素加类时，一定要检查该元素的 `display` 规则与新类的层叠顺序。**

**Tailwind 4 把它的东西（含 preflight 重置）全塞进 `@layer`，而没有层的作者样式永远赢过
任何层内样式。** 所以 `tailwind.css` 先引入 `tokens.css`，再按语义模块顺序引入其他作者样式；这些模块不放进 `@layer`，压在所有 Tailwind 工具类之上 —— 这正是要的。代价：已覆盖的元素上 Tailwind 工具类**不生效**
（给 `.task-row` 加个 `mt-2` 是白写的）。新表面样式配色
**跟着语义样式模块的 CSS 变量走**（`var(--text-3)` 等），写死颜色会让深色模式在新表面上失效。

> **第三条，同一条规律的另一个方向：同一层里两个工具类撞车，赢的是「生成顺序」靠后的那个，
> 不是 `className` 写在后面的那个。** 实测：`MiniIconBtn` 基类有 `text-[var(--text-3)]`，
> 外面再叠一句 `className="text-[var(--primary)]"` —— 类名两个都在、顺序也对，**颜色一点没变**
> （读出来还是 `rgb(95,101,119)`，和旁边那个灰按钮一模一样）。因为 `cx()` 只管拼字符串，
> 谁生效是 Tailwind 生成 CSS 时定死的。
> 所以**给组件加色调要加 prop（真 variant），不要在外面叠 `className`** ——
> `MiniIconBtn` 的 `danger` / `primary`、`Btn` 的 `chip` / `chipOn` 都是这个道理。
> 顺带一个测量陷阱：这类按钮带 `transition`，而 React 会**复用同一个 `<button>`**
> （铅笔 → ✓），切换后**立刻读 `getComputedStyle().color` 会读到动画中途的值**（150ms 后才落定）。
> 探针里要先轮询到落定再比，否则这条断言会时红时绿。

**41. `h-6` 不是 24px：本项目 `html { font-size: 14px }`，Tailwind 一档是 3.5px**
Tailwind 的间距刻度是「`0.25rem` × n」，而 `app/src/styles/tokens.css` 里
`html, body { font-size: 14px }` —— 于是 **`1rem = 14px`，一档 = 3.5px**，
`h-6 w-6` 算出来是 **21×21**，不是 24×24。
`MiniIconBtn` 一直写着「24px，WCAG 2.5.8 的下限」并用 `h-6 w-6` 实现，实测 21px ——
**低于下限 3px，肉眼看不出来，所以一直在那儿**。已改成 `h-[24px] w-[24px]`。
> 写 24px 以上时一律用 `h-[Npx]`，别拿 Tailwind 刻度换算 —— 心算的那一步正是错的来源。
> 同理 `w-8` 是 28px 不是 32px（`IconBtn` 因此没暴露这个问题，它本来就达标）。

**42. 下拉的选项表不许漏掉当前值，否则触发按钮显示成 placeholder**
`Dropdown` 的触发按钮原先是 `current ? (renderValue ? renderValue(current) : current.label) : placeholder`
—— 当前值不在 `options` 里时，`current` 是 `undefined`，于是**回退成
`placeholder`「选择…」**。日程集成员那个角色下拉正是这样：`owner` 不在
`ASSIGNABLE_ROLES` 里（它不是能分下去的权限），创建者那一格就显示成「选择…」。
改成 `renderValue ? renderValue(current) : (current ? current.label : placeholder)`，
并把 `renderValue` 的参数类型放宽成 `DropdownOption<K> | undefined`。
> 推论：**「给谁挑权限」的选择器用 `ASSIGNABLE_ROLES`，不是 `ROLES`。**
> 把 `owner` 列进选项，等于在问「把谁升成第二个主人」—— 那是个没有答案的问题。

**43. 探针里读 localStorage 要轮询，别读一次**
`store.persist()` 是 **250ms 防抖**的（`setTimeout` 攒着再写）。接受邀请、改名这类
「改完立刻读 `localStorage` 对答案」的断言，有大概率读到落盘前的那一份 ——
症状是**同一条断言时红时绿**，重跑一次又好了，看着像产品偶发。
改成 `waitFor` 轮询（`browser-smoke.mjs` 第七节「接受完自动把归属切到刚加入的那个集」
就是这条）。**凡是断言读的是「刚被写过的本地状态」，一律轮询。**

**44. 行内改名要「零位移」，靠的是固定宽度的动作槽，不是「切换时别动」**
`InlineRename` 的验收标准是**切换编辑态时左边那段内容一像素都不动**。
光写「切换时别动」是没用的 —— 动作槽里平时放几个按钮、编辑态放几个按钮，数目不一样，
槽宽就跟着变，左边可用宽度一变，会截断的文字当场重新折行，看着就是「抖了一下」。
做法：**动作槽固定 `w-[52px]`（= 24 + 4 + 24，正好两格），而且两态都是两个按钮** ——
平时「铅笔 + `extraAction`」（日程集 header 的删除按钮走这个口子），编辑中「√ + ✕」。
只给铅笔、不给 `extraAction` 时**也照样占满 52px**：槽的右边缘是一切对齐的基准，
它不能随内容伸缩。
行高**交给外层**（调用方给固定高度的容器），组件自己不定高。
> 这条守不住，所以探针里有一条**量编辑态前后标题行高度和下面那块成员区位置**的断言，
> 差超过 0.6px 就算坏。注释挡不住，量才挡得住。
>
> 推论一：**想「编辑态隐藏」的东西，塞进 `display` 或 `extraAction` 里就行** ——
> 编辑态这两格整个被换掉，它会自己消失，外面不用再判一次 `editing`。日程集 header 的
> 星标（「设为默认」）就是这么做的：放在 `display` 里紧跟着名字，一进编辑态就没了，
> 不会出现「名字已经是输入框了，星标还杵在旁边」这种两处状态对不上的错位。
>
> 推论二：**`display` 里可以有按钮，但别把 `display` 整个包进 `<button>`** ——
> 按钮套按钮是非法 HTML，`<input>` 也进不了 `<button>`（浏览器会把里层那个甩出去）。
> 需要「点整行展开」时，那个开关必须放在 `InlineRename` **外面**：日程集 header 现在
> 就是把它单独放在最右的「箭头区」，由它独家持有 `aria-expanded`。

**45. 给输入框定字号的规则必须待在 `@layer base` 里，而且要躲开「防 iOS 放大」那条**
症状是**「输入框里的字永远比它旁边那行字大一号」，而且改类名毫无反应** —— 不报错、
不白屏，只是那一处永远不生效（和第 17 条同类）。这一条上踩了**两次**，两次的根因不同：

**第一次**：`tokens.css` 里有一条**没有层**的作者样式

```css
input, select, textarea { font-size: 14px; }   /* ← 没有层，所以它赢过一切 */
```

它把 `<Input>` / `<Textarea>` 上**每一个** `text-*` 都静默吃掉了：`<Input dense>` 写的
12.5px、行内改名框写的 13px，渲染出来全是 14px。挪进 `@layer base` 即可（Tailwind 的
`utilities` 层排在 base 之后，组件上写的 `text-[13px]` 就能生效）。

**46. `el.closest(sel)` 会先匹配 `el` 自己 —— 量「行」经常量成「按钮」**
拿「角色下拉的按钮」往上找它所在的那一行，顺手写了

```js
const row = document.querySelector('[aria-label$="的权限"]').closest('[class*="h-[30px]"]');
```

结果量回来的是**按钮自己**（78px 宽），不是那一行（590px）：`closest` 从**元素自己**
开始找，而那个按钮自己就带着 `h-[30px]`（`Dropdown` 的 `sm` 档）。症状是断言
**照样绿**，只是它量的根本不是你以为的那条边 —— 这类错比红还坏，因为它把
「这条边对不对」这个信息整个丢掉了。**从 `parentElement` 往上找**，或者干脆把
选择器写成一个不可能落在子元素身上的（比如行上独有的那个类）。

**第二次（真凶）**：`styles/responsive.css` 里还压着一条**更靠后、同样没有层**的

```css
input, select, textarea { font-size: max(14px, 16px); }   /* 防 iOS 聚焦时自动放大页面 */
```

它把**全项目每一个输入框**都钉在 **16px** —— 包括 kit 的 `<Input>` / `<Textarea>`。
所以「输入框自成一套」的现象比第一次严重得多：界面文字 13px，输入框 16px，差 23%。
而 `.field input`（13px）、`.search-box input`（13px）这些**类选择器**写的规则压得过它
（(0,2,1) > (0,0,1)），于是同一个抽屉里两种字号 —— 这正是「全系统都统一一下字体，
尤其是输入控件」这句话的由来。

**修法（两条一起）**：

1. `tokens.css` 那条挪进 `@layer base`，默认字号定 **13px**（界面文字那一档：成员名、
   列表行、行内改名的显示态都是 13px）。
2. `responsive.css` 那条**删掉桌面端那一半**，只留 `@media (max-width: 820px)` 里的 16px ——
   桌面端没有 iOS 放大问题，输入框该跟界面文字同字号。

> **2026-10-09：那三条 16px 已经整块删掉了** —— 用户要求「全系统都统一一下字体，
> 尤其是输入控件」。现在桌面与窄屏一律 13px。
> **代价说清楚：≤820px 下聚焦输入框，iOS 上会拿回自动放大**（iOS Safari 对 <16px 的
> 输入控件会强制放大整页，放大之后那一屏就再也回不到原样）。要回去就把那三条加回来
> —— 但它们是**没有层的作者样式**，挪进 `@layer base` 的话 `Input` 的 `text-[13px]`
> 会立刻压过它，iOS 该放的放大就放回来了。

> 判据：**凡是「给表单控件定字号 / 颜色」的规则，先问两件事** —— ① 它有没有层？
> ② 它有没有被另一条没层的规则压着？两条都问过才算完。
> 同一条也解释了为什么 `.ai-memory-edit`（12px）、`.pj-next-i`（12.5px）这些能生效：它们是
> 类选择器 (0,1,0)，本来就压得过元素选择器 `input` (0,0,1)，和层无关。
> `browser-smoke.mjs` 第五节有一条断言量「输入框的字号 == 非编辑态那一行字的字号」，
> 就是这条的看门人。

**47. 只读集上 `commitMany` 是**静默丢弃** —— 新建东西必须先落一个能写的归属**

`store.commitMany()` 里那道权限关卡是这样的：

```ts
const writable = items.filter((it) => {
  const calId = it.calId || calOf(it.entity, it.id);
  if (calId && canWrite(roleOf(state, calId))) return true;
  if (calId) blocked.push(calId);
  return false;          // ← 空的 calId 走到这里，**连 deny 都不记**
});
if (blocked.length) deny(blocked);
if (!writable.length) return;
```

**空 `calId` 连 `deny()` 都不记**，只读 `calId` 才弹一次提示。而新建项目那会儿
（`ProjectSheet.save()` → `store.addProject(trimmed)`）项目是 `makeProject(name, ui.cal)`
—— **绑死当前集**。于是：当前集恰好是只读的（被别人降级过）→ 写不进去 → 用户看到的是
「点完**创建**，浮层关了，项目没出现」，外加一条一闪而过的提示。

**最骗人的地方是它长得像别处坏了**：探针第十九节的表现是「等不到泳道出现」，一眼看
过去像是泳道视图本身挂了，去查 `Projects.tsx` 能查掉半个下午。真正的原因是**第十节
把当前集的权限降成了 `viewer`**。

**修法：别让「新建」隐式继承 `ui.cal`。** `addProject(name, calId?)` 收下显式的集
（不传才退回 `ui.cal`，`store.test.ts` 那几个老调用点一个都不用改），新建浮层里给一个
`SheetPicker`，**只列「能写 ∩ 正勾着」的集**：

- **能写** —— 写不进去的列出来就是骗人。
- **正勾着** —— 项目按集可见（`useScopedState` 按 `p.calId` 过滤），落进一个没勾的集
  等于**凭空消失**，跟 `toggleCal()` 那条「归属不能没有显示的地方」是同一件事。

默认取当前集（当前集能写就用它），否则第一个能写的。

**只在新建时给这个选择器，编辑时不给**：`patchProject` 的白名单里根本没有 `calId`
（挪集 = 目标集新建一条 + 源集留墓碑，不变量 2）。一个「选了看着变了、存下去没变」的
死控件比没有更坏 —— 用户会以为挪成功了。

> 顺带记一笔：`deny()` 是**唯一**能让用户知道「你被挡了」的东西，所以别指望它兜底
> 只读集这一条 —— 它只在 `blocked.length` 非空时才弹，而空 `calId` 那条路压根不记。

**48. portal 出去的嵌套浮层，会被外层的 `useOutsideClose` 当成「点到外面」**

`SheetPicker` 自己弹的那层是 `Sheet`，而 `Sheet` 是 `createPortal(..., document.body)`
—— 在 DOM 上它**不是外层面板的后代**。外层的 `useOutsideClose` 判的是
`el.contains(e.target)`，判不出来，于是这一下被当成「点了外面」。

**而且它听的是 capture 阶段的 `mousedown`**：`mousedown` 先于 `click`，所以外层**先一步**
被关掉、连带把里层一起卸载 —— 用户这一次点击白丢。症状是「点选项没反应，浮层倒是没了」。
`Drawer` 里那个 `SheetPicker` 一直没事，纯粹因为 **`Drawer` 不用 `useOutsideClose`**
（它只有 `useFocusTrap`），**不是**因为它躲过了什么。

**修法**：判据从「在本面板外」改成「在**别的**浮层里」。`Sheet` 的 portal 根节点挂一个
`data-sheet-root`，`useOutsideClose` 把落点自己那一棵跟本面板的比：

```ts
const own = (el?.closest('[data-sheet-root]') as Element | null) || null;
const hit = (t?.closest?.('[data-sheet-root]') as Element | null) || null;
if (hit && hit !== own) return;   // 落在别的浮层里，不关本层
cb.current();
```

比的是**根**不是**面板**：落在本层自己的遮罩上 `hit === own`，照旧要关 —— 要是图省事
拿 `hit !== el` 去比，本层遮罩就永远关不掉了。

> **这一类 bug 探针测不出来**：`clickEl` 只派发 `pointerdown` / `pointerup` / `click`，
> **不派发 `mousedown`**，所以外层永远不会被误关，断言照样绿。`hooks.ts` 里
> `useOutsideClose` 的注释早就记着这个盲区（「只在真机上出现，合成 click 不派发
> mousedown，所以 `clickEl` 那套测试永远测不出来」）。要验嵌套浮层就得自己派发真的
> `mousedown` —— 探针第十九节里那个 `tapEl` 就是干这个的，判据是
> `document.querySelectorAll('[role="dialog"]').length === 2`。

**49. `store.setUi()` 是个裸的浅合并 —— 派生字段会静默过期**

`normalizeUi()` 会把 `ui.tabs` 按 `ui.navOrder` 重排（底栏的顺序跟侧栏走，两个列表
没必要让用户各记一套），但**它只在载入 / 导入时跑**：

```ts
export function setUi(patch: Partial<UiPrefs>): void {
  state.ui = { ...state.ui, ...patch };   // 就这一行，没有归一
  persist(); emit();
}
```

于是设置页拖一下顺序只写了 `navOrder`，`ui.tabs` 还是老顺序 —— 而底栏渲染的是
`state.ui.tabs` 自己的顺序。**症状：拖动完底栏纹丝不动，刷新一下（或者随便点一下
某个功能区的显示 / 隐藏）才对。** 用户 2026-10-09 的原话就是「拖动修改后底栏不会
跟着立刻变化，要刷新 / 切换某个功能区显示隐藏后才变化」。

「点一下勾选就好了」正是这个 bug 的指纹：那个分支写的是 `tabs` 本身，顺手把它排了序。

**为什么不能在 `setUi` 里补一次 `normalizeUi`**：它是通用 setter，别的补丁（`dayFrom` /
`dayTo` / `cal` / `cals`）不该被拖去跑归一 —— 归一会夹 `dayFrom`/`dayTo`、会回落
`tabs`，一个只改「时间窗」的写入顺带改了别的东西，那才是真的难查。

**修法：派生关系只留一个出口。** `ui.tabs = orderTabs(order, tabs)` 抽成
`domain/model.ts` 的 `orderTabs()`，`normalizeUi` 和设置页那三处写入方（拖拽 + 两个
勾选分支）全部从这里过。

**别在写入方就地抄一遍排序**：抄的那一刻是对的，下次改口径（比如改 `TAB_MAX`、
改兜底值）就只改了其中一处 —— 这个坑本身就是「只在 `normalizeUi` 里写了一遍」来的。

> 同类风险：任何「A 由 B 派生」的字段，只要写入方是 `setUi`，都要问一句
> 「B 变了，A 谁负责重算」。现在这类派生只有 `tabs ← navOrder` 一处。
