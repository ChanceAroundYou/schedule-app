**41. `h-6` 不是 24px：本项目 `html { font-size: 14px }`，Tailwind 一档是 3.5px**
Tailwind 的间距刻度是「`0.25rem` × n」，而 `app/src/styles/tokens.css` 里
`html, body { font-size: 14px }` —— 于是 **`1rem = 14px`，一档 = 3.5px**，
`h-6 w-6` 算出来是 **21×21**，不是 24×24。
`MiniIconBtn` 一直写着「24px，WCAG 2.5.8 的下限」并用 `h-6 w-6` 实现，实测 21px ——
**低于下限 3px，肉眼看不出来，所以一直在那儿**。已改成 `h-[24px] w-[24px]`。
> 写 24px 以上时一律用 `h-[Npx]`，别拿 Tailwind 刻度换算 —— 心算的那一步正是错的来源。
> 同理 `w-8` 是 28px 不是 32px（`IconBtn` 因此没暴露这个问题，它本来就达标）。

**42. 下拉的选项表不许漏掉当前值，否则触发按钮显示成 placeholder**
`Dropdown` 的触发按钮原先是 `current ? (renderValue ? renderValue(current) : current.label) : placeholder`
—— 当前值不在 `options` 里时，`current` 是 `undefined`，于是**回退成
`placeholder`「选择…」**。日程集成员那个角色下拉正是这样：`owner` 不在
`ASSIGNABLE_ROLES` 里（它不是能分下去的权限），创建者那一格就显示成「选择…」。
改成 `renderValue ? renderValue(current) : (current ? current.label : placeholder)`，
并把 `renderValue` 的参数类型放宽成 `DropdownOption<K> | undefined`。
> 推论：**「给谁挑权限」的选择器用 `ASSIGNABLE_ROLES`，不是 `ROLES`。**
> 把 `owner` 列进选项，等于在问「把谁升成第二个主人」—— 那是个没有答案的问题。

**43. 探针里读 localStorage 要轮询，别读一次**
`store.persist()` 是 **250ms 防抖**的（`setTimeout` 攒着再写）。接受邀请、改名这类
「改完立刻读 `localStorage` 对答案」的断言，有大概率读到落盘前的那一份 ——
症状是**同一条断言时红时绿**，重跑一次又好了，看着像产品偶发。
改成 `waitFor` 轮询（`browser-smoke.mjs` 第七节「接受完自动把归属切到刚加入的那个集」
就是这条）。**凡是断言读的是「刚被写过的本地状态」，一律轮询。**

**44. 行内改名要「零位移」，靠的是固定宽度的动作槽，不是「切换时别动」**
`InlineRename` 的验收标准是**切换编辑态时左边那段内容一像素都不动**。
光写「切换时别动」是没用的 —— 动作槽里平时放几个按钮、编辑态放几个按钮，数目不一样，
槽宽就跟着变，左边可用宽度一变，会截断的文字当场重新折行，看着就是「抖了一下」。
做法：**动作槽固定 `w-[52px]`（= 24 + 4 + 24，正好两格），而且两态都是两个按钮** ——
平时「铅笔 + `extraAction`」（日程集 header 的删除按钮走这个口子），编辑中「√ + ✕」。
只给铅笔、不给 `extraAction` 时**也照样占满 52px**：槽的右边缘是一切对齐的基准，
它不能随内容伸缩。
行高**交给外层**（调用方给固定高度的容器），组件自己不定高。
> 这条守不住，所以探针里有一条**量编辑态前后标题行高度和下面那块成员区位置**的断言，
> 差超过 0.6px 就算坏。注释挡不住，量才挡得住。
>
> 推论一：**想「编辑态隐藏」的东西，塞进 `display` 或 `extraAction` 里就行** ——
> 编辑态这两格整个被换掉，它会自己消失，外面不用再判一次 `editing`。日程集 header 的
> 星标（「设为默认」）就是这么做的：放在 `display` 里紧跟着名字，一进编辑态就没了，
> 不会出现「名字已经是输入框了，星标还杵在旁边」这种两处状态对不上的错位。
>
> 推论二：**`display` 里可以有按钮，但别把 `display` 整个包进 `<button>`** ——
> 按钮套按钮是非法 HTML，`<input>` 也进不了 `<button>`（浏览器会把里层那个甩出去）。
> 需要「点整行展开」时，那个开关必须放在 `InlineRename` **外面**：日程集 header 现在
> 就是把它单独放在最右的「箭头区」，由它独家持有 `aria-expanded`。

**45. 给输入框定字号：先问「有没有层」，再问「有没有被另一条没层的规则压着」**
症状是**输入框里的字永远比旁边那行大一号，改类名毫无反应** —— 不报错、不白屏，只是
那一处永远不生效（和第 17 条同类）。这一条踩了两次，根因不同：

1. `tokens.css` 里一条**没有层**的 `input, select, textarea { font-size: 14px }` —— 把
   `<Input>` / `<Textarea>` 上**每一个** `text-*` 都静默吃掉了（`dense` 的 12.5px、行内
   改名框的 13px 全是白写的）。挪进 `@layer base` 即可（`utilities` 排在 base 之后）。
2. 真凶是 `responsive.css` 里**更靠后、同样没有层**的
   `input, select, textarea { font-size: max(14px, 16px) }`（防 iOS 聚焦时自动放大页面）——
   它把**全项目每一个输入框**都钉在 16px，连 kit 的 `<Input>` 也跑不掉。而 `.field input`
   （13px）、`.search-box input`（13px）这些**类选择器**压得过它（(0,2,1) > (0,0,1)），
   于是同一个抽屉里两种字号 —— 就是「全系统都统一一下字体，尤其是输入控件」那句话的由来。
   **2026-10-09 按用户要求把这几条 16px 整块删掉**（连同 `.jp-row input` /
   `.fast-add textarea`）：现在桌面与窄屏一律 13px。
   **代价说清楚**：≤820px 下聚焦输入框，iOS 会拿回自动放大。要加回来就得保持**没有层**
   —— 挪进 `@layer base` 的话 `Input` 的 `text-[13px]` 立刻压过它，iOS 那个放大也回来了。

> 判据：凡「给表单控件定字号 / 颜色」的规则，① 有没有层 ② 有没有被另一条没层的规则压着，
> 两条都问过才算完。`.ai-memory-edit`（12px）、`.pj-next-i`（12.5px）能生效是因为类选择器
> 本来就压得过元素选择器 `input`，和层无关。`browser-smoke.mjs` 第五节有一条断言量
> 「输入框的字号 == 非编辑态那一行字的字号」，就是这条的看门人。

**46. `el.closest(sel)` 会先匹配 `el` 自己 —— 量「行」经常量成「按钮」**
拿「角色下拉的按钮」往上找它所在的那一行，顺手写了
`closest('[class*="h-[30px]"]')`，结果量回来的是**按钮自己**（78px 宽）而不是那一行
（590px）—— `closest` 从**元素自己**开始找，而那个按钮自己就带着 `h-[30px]`
（`Dropdown` 的 `sm` 档）。症状是断言**照样绿**，只是它量的根本不是你以为的那条边 ——
这类错比红还坏，因为它把「这条边对不对」这个信息整个丢掉了。**从 `parentElement`
往上找**，或者把选择器写成一个不可能落在子元素身上的（比如行上独有的那个类）。

**47. 只读集上 `commitMany` 是「静默丢弃」—— 新建东西必须先落一个能写的归属**

```ts
// store.commitMany()：空 calId 走到这里，**连 deny 都不记**
const writable = items.filter((it) => {
  const calId = it.calId || calOf(it.entity, it.id);
  if (calId && canWrite(roleOf(state, calId))) return true;
  if (calId) blocked.push(calId);
  return false;
});
```

**空 `calId` 连 `deny()` 都不记**，只读 `calId` 才弹一次提示。而新建项目那会儿
（`ProjectSheet.save()` → `store.addProject(trimmed)`）项目是 `makeProject(name, ui.cal)`
—— **绑死当前集**。于是：当前集恰好是只读的（被别人降级过）→ 写不进去 → 用户看到的是
「点完**创建**，浮层关了，项目没出现」，外加一条一闪而过的提示。

**最骗人的地方是它长得像别处坏了**：探针第十九节的表现是「等不到泳道出现」，一眼看过去
像是泳道视图本身挂了，去查 `Projects.tsx` 能查掉半个下午。真正的原因是**第十节把当前集的
权限降成了 `viewer`**。

**修法：别让「新建」隐式继承 `ui.cal`。** `addProject(name, calId?)` 收下显式的集（不传才
退回 `ui.cal`，`store.test.ts` 那几个老调用点一个都不用改），新建浮层里给一个 `SheetPicker`，
**只列「能写 ∩ 正勾着」的集**：能写（写不进去的列出来就是骗人）· 正勾着（项目按集可见，
落进没勾的集等于**凭空消失**，和 `toggleCal()` 那条是同一件事）。默认取当前集（能写就用它），
否则第一个能写的。

**只在新建时给这个选择器，编辑时不给**：`patchProject` 的白名单里根本没有 `calId`（挪集 =
目标集新建一条 + 源集留墓碑，不变量 2）。一个「选了看着变了、存下去没变」的死控件比没有更坏。

> 顺带记一笔：`deny()` 是**唯一**能让用户知道「你被挡了」的东西，所以别指望它兜底只读集
> 这一条 —— 它只在 `blocked.length` 非空时才弹。

**48. portal 出去的嵌套浮层，会被外层的 `useOutsideClose` 当成「点到外面」**

`SheetPicker` 自己弹的那层是 `Sheet`，而 `Sheet` 是 `createPortal(..., document.body)`
—— 在 DOM 上它**不是外层面板的后代**。外层的 `useOutsideClose` 判的是
`el.contains(e.target)`，判不出来，于是这一下被当成「点了外面」。

**而且它听的是 capture 阶段的 `mousedown`**：`mousedown` 先于 `click`，所以外层**先一步**
被关掉、连带把里层一起卸载 —— 用户这一次点击白丢。症状是「点选项没反应，浮层倒是没了」。
`Drawer` 里那个 `SheetPicker` 一直没事，纯粹因为 **`Drawer` 不用 `useOutsideClose`**
（它只有 `useFocusTrap`），**不是**因为它躲过了什么。

**修法**：判据从「在本面板外」改成「在**别的**浮层里」。`Sheet` 的 portal 根节点挂一个
`data-sheet-root`，`useOutsideClose` 把落点自己那一棵跟本面板的比：

```ts
const own = (el?.closest('[data-sheet-root]') as Element | null) || null;
const hit = (t?.closest?.('[data-sheet-root]') as Element | null) || null;
if (hit && hit !== own) return;   // 落在别的浮层里，不关本层
cb.current();
```

比的是**根**不是**面板**：落在本层自己的遮罩上 `hit === own`，照旧要关 —— 要是图省事
拿 `hit !== el` 去比，本层遮罩就永远关不掉了。

> **这一类 bug 探针测不出来**：`clickEl` 只派发 `pointerdown` / `pointerup` / `click`，
> **不派发 `mousedown`**，所以外层永远不会被误关，断言照样绿。`hooks.ts` 里
> `useOutsideClose` 的注释早就记着这个盲区（「只在真机上出现，合成 click 不派发
> mousedown，所以 `clickEl` 那套测试永远测不出来」）。要验嵌套浮层就得自己派发真的
> `mousedown` —— 探针第十九节里那个 `tapEl` 就是干这个的，判据是
> `document.querySelectorAll('[role="dialog"]').length === 2`。

**49. `store.setUi()` 是个裸的浅合并 —— 派生字段会静默过期**

`normalizeUi()` 会把 `ui.tabs` 按 `ui.navOrder` 重排（底栏的顺序跟侧栏走，两个列表
没必要让用户各记一套），但**它只在载入 / 导入时跑**：

```ts
export function setUi(patch: Partial<UiPrefs>): void {
  state.ui = { ...state.ui, ...patch };   // 就这一行，没有归一
  persist(); emit();
}
```

于是设置页拖一下顺序只写了 `navOrder`，`ui.tabs` 还是老顺序 —— 而底栏渲染的是
`state.ui.tabs` 自己的顺序。**症状：拖动完底栏纹丝不动，刷新一下（或者随便点一下
某个功能区的显示 / 隐藏）才对。** 用户 2026-10-09 的原话就是「拖动修改后底栏不会
跟着立刻变化，要刷新 / 切换某个功能区显示隐藏后才变化」。

「点一下勾选就好了」正是这个 bug 的指纹：那个分支写的是 `tabs` 本身，顺手把它排了序。

**为什么不能在 `setUi` 里补一次 `normalizeUi`**：它是通用 setter，别的补丁（`dayFrom` /
`dayTo` / `cal` / `cals`）不该被拖去跑归一 —— 归一会夹 `dayFrom`/`dayTo`、会回落
`tabs`，一个只改「时间窗」的写入顺带改了别的东西，那才是真的难查。

**修法：派生关系只留一个出口。** `ui.tabs = orderTabs(order, tabs)` 抽成
`domain/model.ts` 的 `orderTabs()`，`normalizeUi` 和设置页那三处写入方（拖拽 + 两个
勾选分支）全部从这里过。

**别在写入方就地抄一遍排序**：抄的那一刻是对的，下次改口径（比如改 `TAB_MAX`、
改兜底值）就只改了其中一处 —— 这个坑本身就是「只在 `normalizeUi` 里写了一遍」来的。

> 同类风险：任何「A 由 B 派生」的字段，只要写入方是 `setUi`，都要问一句
> 「B 变了，A 谁负责重算」。现在这类派生只有 `tabs ← navOrder` 一处。

**50. 「一小时卡」和「无时间卡」要处处一样：换算基准固定成整天，同一条属性只许声明一次**

用户 2026-10-24 连着报三轮「高度 宽度 圆角 左右 margin 都还是不一致」。**三轮各有根因，
每一个都被「我改了」盖住** —— 因为改的都是显眼的地方，红的是别处。

1. **未定时行高的基准是「整天」，不是「当前时间窗」**。`domain/layout.ts` 的 `untimedRowPx()`
   原来按窗口跨度摊（`60 / spanMin × 容器高`）：默认整天时它正好等于一小时卡高（对），
   可探针把窗口设成 08:00–11:00 时它变成 **206px**，未定时区乘 `--un-visible`（3.2）就是
   七八百像素 —— 日面板被捅穿，时间轴被压成 12px（卡片撞上 `min-height`），拖起来的卡片
   跑到面板外（browser-smoke「拖拽中卡片上下沿限制在日面板内」那条就是这么红的）。
   **别改回 `60 / spanMin`**，现在写的是 `60 / Math.max(spanMin, 1440)`；
   下限待在 CSS 的 `max()` 里（`--row: max(自然行高, --row-hour)`）。
2. **同一条属性只在一处声明**。`.task-el--timed` 的圆角本来已经是 `clamp(3px, 卡高×30%, --r-lg)`，
   可**同一个文件后面**还留着一条同特异度的老皮肤 `.task-el--timed { … border-radius: var(--r-sm) }`
   —— 同特异度后写的赢，30% 那条**静默失效**。这就是「圆角程度也不一样」的全部根因，
   前几轮一直在改前面那条，所以怎么改都没用。
   ⚠️ 同一天晚些时候**又犯一遍**（月视图那条）：基础块一条 `var(--r-sm)`、定时卡一条
   `clamp`、`responsive.css` 窄屏胶囊一条写死的 `4px` —— 三条里 `4px` 赢，于是「月视图
   窄屏比别的地方更方」。**消掉重复声明才是修法，改其中任一条都不是。**
3. **左边缘不齐是容器 padding 不一致**：`.wun-cell` 有 `padding: 2px 3px`、`.week-col` 没有
   → 同一列宽下两种卡的 x 差 3px、可用宽差 6px。现在横向留白只由卡片自己给（**`--card-pad-x`
   一个令牌**，桌面 7px / 窄屏 2px），两个容器的横向 padding 一律 0。
   日视图同款：窄屏那条 `.allday-items[data-cols="1"] .task-el--untimed { padding: 1px 8px }`
   让未定时卡左右 8px、定时卡 6px，已删。

**什么才算收敛**（不是「看着差不多」）：日 / 周 / 月 × 宽 / 窄六组，把三种卡的
`height / width / left / border-radius / padding-left / padding-right` 打到一张表上比对，
**高宽 x 差 ≤ 1px、圆角差 ≤ 0.1px、padding 完全相同**。残差只允许来自「百分比高 × 含边框的容器高」
的取整。探针断言用**卡自己的短边**（`radius / 短边 ≈ 0.28`，见 `app/tests/card-geometry.mjs`），
**不许写死 `7px` 这种档** —— 写死的数字换个窗口就红。

> 百分比圆角读不回来：`getComputedStyle` 里 `border-radius: 30%` 不会算成 px，探针读到的是
> `"30%"` 这个字符串。所以半径一律写成 px 算式：
> `min(var(--r-xl), max(2px, calc(var(--card-h) * var(--card-r-k))))`。
> ⚠️ **用 `min()` / `max()`，不能用 `clamp()`**：flat 风格档的 `--r-*` 全是 0，
> `clamp(2px, x, 0)` 里上限 < 下限，返回的是**下限 2px** —— flat 档会莫名其妙全变圆。
> ⚠️ **上限不能低于 `高 × 0.28`**：一旦贴着上限，高卡不跟着比例走，同一屏上
> 「一小时卡」和「无时间卡」的圆润程度又错开（实测 0.226 vs 0.300，正是要修的那件事）。

**51. 「拖卡片的同时整个区域在滑」：长按窗口里浏览器在同时选字，而 dnd-kit 只在开拖后拦滚动**

用户 2026-10-24 报：触屏长按拽起未定时卡，卡片在拖、**整个未定时区也在跟着滑**。

1. **根因是 delay 窗口比人手长**。触摸传感器写的是 `delay: 480, tolerance: 8`：
   真人「按住再拖」的停留一般 200–400ms，**手指已经动了、拖还没起来**，
   窗口里 `tolerance` 一超就把这次拖拽作废让给滚动 —— 用户看到的正是「卡片没起来、区域在滑」。
   改成 `delay: 300`（鼠标那条 `distance: 8` 不动：鼠标没有 delay 这一说）。
2. **开拖之后不滑，靠的是库里那一行 `preventDefault`，不是 CSS**。
   `AbstractPointerSensor.handleMove` 只在 `activated` 之后才
   `if (event.cancelable) event.preventDefault()`；delay 窗口里那条分支直接 return，
   **一个都不拦**。所以「长按拽起 → 之后怎么动都不滚」是库保证的，`touch-action` 改不出这个效果。
3. **库自带的 AutoScroll 默认开着**（`DndContext` 的 `autoScroll`）：被拖方块进入某个可滚容器
   边缘的阈值区，它自己去 `scrollBy` 那个容器（`core.esm.js` 的 `getAutoScrollerOptions`）。
   已在 `provider.tsx` / `sortable.tsx` 两处关掉；键盘传感器本来就是 `autoScrollEnabled = false`，
   关掉后三条路一致。
   ⚠️ **这一条只有源码证据，没有实测证据**：headless 里 `Input.dispatchTouchEvent` 合成的触摸
   **不驱动原生滚动**，A/B 两版（关掉 / 开着）探针读数一模一样（列表里拖最后一行，`.content`
   scrollTop 402 → 402）。测得到的只有「开拖后 3 个 touchmove 全被拦 / 不长按时 3 个全放行」
   和「没有任何容器替它滚」。**真机上这一半要手工走一遍。**
4. **长按窗口里浏览器同时会开始选字** —— 手指按住 300–500ms，十有八九变成「选中了一段任务名」。
   dnd-kit 清选区只发生在**开拖之后**（`handleStart` 里挂 `SelectionChange`），窗口内不管。
   所以**能拖动的表面一律** `user-select: none; -webkit-user-select: none; -webkit-touch-callout: none`。
   判据是**能不能拖**，不是长什么样（2026-10-25 用户改口径：「能拖动的都不允许复制」）——
   收的选择器是拖拽标记 `.task-el, .habit-row, .nav-chip`，与界面无关。
   ⚠️ **两个例外一定要留住**：`.new-cell`（就地新建的草稿框，拿来打字的）与 `.trash-row`
   （垃圾箱行只有 `.task-row` 没有 `.task-el`，拖不动 —— 里面的任务名要能复制出去找回东西）。
   2026-10-22 曾定过「列表行文字要能复制」，**已被本次口径取代**（列表行是 `SortableList`
   的拖拽表面，同一件事不该按界面分两套）。
   ⚠️ **探针现在可以写 `.task-el` 了**（从前是禁忌：会把列表行扫进来变成假红）；
   但 `.new-cell` / `.trash-row` 必须**单独反向断言可选中**，否则宽口径会静默吃掉它们。
   ⚠️ **`-webkit-touch-callout` 在 Chrome 里量不出来**：`CSS.supports` 返回 false、
   `getComputedStyle` 读到空串、CSSOM 的 `cssText` 直接把这行未知声明丢掉（实测样式表
   原文里有、`document.styleSheets` 遍历出 0 条）。这条只能 fetch 样式表原文按正则找，
   真正生效与否只能在 iOS 真机上看。
   ⚠️ 同一个症状还有**第二条根因**（2026-10-24 同一天第二次复发）：卡片被标记的那一帧
   那一区切成 `overflow: visible`，浏览器当场抹掉它的 `scrollTop` —— 见 **54**。

**52. 同一个时长四种画法、圈与文字对不齐：硬编码的对齐值在替结构做决定**

用户 2026-10-24 第四轮三条：「日视图时间行与任务文字没左对齐」「打勾太大、位置不对」
「周视图卡片怎么始终没有时间？不是超过 1 小时的都该显示么」。三条共用一个形状 ——
**同一件事在四个地方各写一遍，各自跟着自己那块屏幕长。**

1. **时间行有四种画法**：窄屏周视图 CSS 里 `display: none`、宽屏按 `roomy`（卡够不够高）决定
   画不画、月视图胶囊另有 `.pill-time` 一条、日视图又是另一套。90 分钟的任务在窄屏周里没有
   时间、宽屏周里有、月视图里挂气泡 —— 用户读到的是「规则随屏幕变」。
   现在全项目一条：**时长 > 60 分钟才有时间行，有了就必须露出来**（判据在 `TaskCard`，
   装不下只压不加长 —— 第四轮当时是「压行距 + 给卡加长」，加长在第五轮被用户否掉，见 53），
   月视图**永远**不画（时间挂 `title` 气泡）。
   ⚠️ 老规矩在探针里留过化石：`week-look.mjs` 的「窄屏周视图不显示时间行」——
   改 CSS 不同时翻它，「改对了」和「探针绿」会互相抵消。现在那条已改成
   「时间行在不在 = 时长是否 > 60 分钟」，窄屏宽屏同一条判据。
2. **左对齐是一个写死的 `padding-left: 21px` 撑的**（`.ev-time`、`.ev-note` 各一条）。
   那个 21 照着「圈 14 + gap 2 + 边框」估的，圈一改就漂，日视图实测偏 5px。
   现在标题 / 时间 / 详细内容在同一个 `.ev-text` 里，左端只有一处定义（探针断言差 ≤ 0.5px）。
3. **`grid-row: 1 / -1` 不跨隐式行**（中间那一步踩的，值得单独记）。想把圈跨到时间行下面
   居中，`-1` 只数**显式**网格的行，而卡片内容的行全是 auto 放置出来的隐式行 ——
   圈因此只盖住标题那一行，中心**偏上 6px**（最小复现 -6.03，探针第三节同一读数）。
   现在的做法是不跨行：`.ev-body` 是「圈 + 文字块」两件的**单行 flex**，
   `align-items: center` 让圈对**整块文字**居中，`align-content: center` 管整块在卡里居中 ——
   **两句缺一不可**：只写前者，整块内容会顶到卡片上沿。
4. **圈的尺寸三档写死**（本体 18px / `.sm` 14px / 窄屏响应式又 22px），12.5px 的文字旁边
   挂一个 18px 的圈 —— 这就是「打勾太大」。现在一条 `--check-size`（字号 × `--check-k`，
   夹 `--check-min`~`--check-max`），勾的笔画按比例缩放，`sm` 那一档连参数一起取消。
   ⚠️ 系数本身也跟着用户来回改过一次：第四轮 0.85 夹 9~16（「打勾太大」），
   第五轮 1 夹 9~18（「打勾太小了 比例再大一点」）。**改的是令牌，不是某一屏的 CSS** ——
   在这里再写一档就会让列表和卡片又长歪。圈吃的是横向：窄屏周视图直径按公式从
   11 × 0.85 涨到 11（涨 1.65px），文字净宽就少这么多（圈与文字块在同一条 flex 行上，
   圈多宽文字就少宽），而那一列的时间行总共只有 ~52px 可用（见 53）。

> 顺带一条探针规矩：**「藏起来的元素」和「不存在的元素」不是一回事**。
> `.pill-time` 这个元素现在根本不渲染，可原先的断言 `querySelector('.pill-time')` 读不到
> 就算通过 —— 藏起来也绿。现在的断言是 `document.querySelectorAll('.pill-time').length === 0`
> （元素不许存在），另一头 `.ev-time` 那种「元素在、但被 CSS 藏了」要读 `display` 才算数。

**53. 「装不下就给卡加长」把时长画长了；一条共用阶梯又把标题带下水**

**规则**：卡高只由时长定，装不下**只压不加长**，而且**两个轴各自一条阶梯** ——
纵向（`.ev-text` 高出 `.ev-body`）压 行距 → 卡内上下留白归零 → 标题字号（下限 9px）；
横向（`.ev-time` 的 scrollWidth 超出自己的 clientWidth）压 紧凑写法 → 字距 →
**时间行自己的**字号（下限 7.5px）。两个判据在 `useCardFit` 与探针里必须是同一口径。

**为什么不能改回去**：

1. 上一轮的「压行距 → 再不够给这张卡 `min-height`」把 61 分钟的卡顶到 **28.25px**
   （窄屏一小时只有 ~20.5px）—— 卡高就是时长，顶高等于把 61 分钟画成 68 分钟，
   圆角也跟着错（圆角按卡高报）。用户那句是「没有什么地方有给卡片加长的兜底」。
2. **合成一条阶梯会把不该缩的字缩掉**：窄屏周视图为了「时间行横向装不下」把**标题**
   也缩一档，同一屏上 60 分钟卡 11px、61 分钟卡 10px —— 「未定时与定时同字号」当场破
   （`week-look.mjs` 那条断言就是抓它的，它红了才发现是阶梯的问题不是 CSS 的问题）。
3. **判据换口径会假绿**，两处都是实测：
   · 用 `.ev-body` 的 `scrollHeight` 判纵向 → 被勾选圈那个 **24×24 的 `::before` 命中区**污染，
     圈比文字高时永远判「装不下」，于是一张本来装得下的卡被压到字号档。
   · 用「行的矩形在不在卡里」判 → `align-items: center` 把 1px 超出**上下各分一半**，
     11px 的行装在 10.14px 的框里各露 0.43px，落在 0.5px 容差里出不来，
     于是停在 11px 不再往下压。
4. **`var()` 在声明它的那个元素上替换完**（与 52 同一个形状，第二次踩）：
   · 想给卡「让出上下留白」，在卡上覆盖 `--card-pad-y` **等于没改** —— 卡片消费的是
     `--tl-event-pad` / `--allday-pill-pad`，那两条声明在 `:root`、替换早完成了；
     要覆盖就覆盖消费的那两条。
   · 反过来，默认值一旦定义在 `.task-el` 上，`.ev-title` 里 `var(--ev-title-lh, 兜底)`
     的兜底**永远不会生效** —— 五处兜底全删，周视图的大档行高（18）改写回卡上，
     窄屏那条还得写在 `responsive.css`（同特异度后写的赢，踩坑 50 第一条）。
   · `contrast.mjs` 那道「未定义的 CSS 变量」正是抓这一类的：把它误报成「JS 在写的变量」
     而放宽守卫，等于把这一类重新放回去。

**失败症状**：窄屏周视图时间行尾巴变「…」—— 完整写法「17:00 – 18:01」要 67px、
那一列净宽只有 54px，**裁 13px**（紧凑写法 + 两轴压完才是 `裁 = 0`）；
tier2 改了 `--card-pad-y` 但卡高一点没变；`contrast.mjs` 报五条 `--ev-*` 未定义。

⚠️ 还有一条**没撤**的老地板：`calendar.css` 的 `.task-el--timed { min-height: 12px }`
（早于本轮）。30 分钟的卡按时长只有 **9.50（窄屏周）/ 10.25（窄屏日）/ 11.25（桌面周）px**，
实际卡高 12.00 是它顶的 —— 桌面日视图那张 12.14 ≈ 应高 12.15，地板没顶到它。
探针点名打印「（CSS 地板 12px 顶的）」而不是假装相等。**撤不撤待用户定**：
撤了那张卡连一行 10px 的字都塞不下，留着则它是「不许加长」目前唯一的例外。

**54. 同一个症状的第二条根因：给滚着的容器切 `overflow: visible`，浏览器当场抹掉它的 `scrollTop`**

用户 2026-10-24：「怎么又回退了，拖动未定时任务的时候整个未定时区又滑动了」——
**51 那三条一条没少**（AutoScroll 关了、`preventDefault` 到位、`delay: 300`），症状却回来了。

1. **可滚容器一旦不再是滚容器，`scrollTop` 当场归零**（最小复现：滚 80px → 切 `visible`
   → `scrollTop` 0、内容往下跳 80px；切回 `auto` 又拿回 80）。当时为了让卡片能拖出格子，
   `calendar.css` 写过 `.allday-zone:has(.task-el.dragging) { overflow: visible }`
   （1bef36b 为「卡片被截断」加的）—— 卡片一被标记，那一区的滚位就被抹掉，**整格内容替卡片滑**。
2. **为什么它一直埋着、那天才露头**：得先真滚起来才看得见。把条数推过溢出线的，正是
   「已完成的未定时任务也留在未定时区」那条改动。**探针同样在盲区**：
   `card-geometry.mjs` 的 `dragCard()` 起点把 `scrollTop` 归零 —— 等于把这条的读数主动抹平了。
3. **橡皮筋是第二条通路**：`app/touchDamp.ts` 挂在 `passive` 监听上，dnd-kit 的
   `preventDefault` 拦不住它**看见**这些 touchmove。开拖之前手指已经挪掉的那一段它已经写了
   `--pull`，开拖之后还在写 → `> *` 全体被拽走。现在 `isDragging()` 为真就不参与，
   并把已经拉开的那一段当场归零（摘 `data-pull` → 过渡接管 → 弹回）。

**现在的做法：拖拽用「分身」，不切 `overflow`。** `ui/dnd/lift.ts` 在 pointerdown 量好卡片
原始位置，拖起后用 `createPortal` 把分身画到 `body`（`position: fixed`，不受任何祖先裁剪），
本体 `visibility: hidden` 原地不动。**区自始至终还是滚容器**，`scrollTop` 根本没被动过 ——
所以 `--keep` 补位移那套（连同 `ui/dnd/scrollKeep.ts`）随 dev 合并一起删掉了，
**别再搬回来**。

**不许改回去的两处**：别把 `:has(.task-el.dragging) { overflow: visible }` 加回来
（卡片不裁了，但滚位会丢）；别让 `touchDamp` 在 `isDragging()` 时还写 `--pull`。

## 键盘与坐标（2026-10-17，真机连着修了三轮才对）

三条都不带编号（不是「别改回去」的约定，是「真机上为什么这样」的解释）。

**1. 焦点不能当用户意图信号。** 「输入框失焦 = 用户不要这条了」在安卓上不成立：键盘弹起
会把 App 高度撑变、布局重排，输入框会在 200–400ms 之间被系统自己弄丢焦点。拿它当放弃，
用户看到的是「输入法闪一下就没了」。第一版修法（延后 250ms 再结算）**无效** —— 焦点是真
被拿走了，延到 400ms 还是「丢了」。现在结算只看三件事：回车、Esc、手指点到框外
（`document` 的 pointerdown）。

**2. `visualViewport` 差值判键盘高度，在 App 里恒等于 0。**
`键盘高度 = innerHeight - visualViewport.height - vv.offsetTop` 在桌面成立（键盘只压可视
视口），但 **App 是 adjustResize**：键盘弹起时整个界面被压小，两项一起变小，相减恒为 0。
后果：「手动收键盘 → 撤掉空草稿」**从来没被触发过**，同一个 `--kb` 管的登录页 / 抽屉避让
也一直是 0。→ 原生壳改用 `@capacitor/keyboard` 的 `keyboardWillShow/WillHide`；
`useKeyboardInset` 在原生壳里直接 return（`app/src/app/kb.ts` 的 `isNativeShell()`），否则会把
原生写好的 `--kb` 覆盖回 0。浏览器里的 `--kb` 见 [界面约定-快速添加.md](界面约定-快速添加.md)。

**3. 坐标与 rect 必须来自同一时刻。** 点时间轴空白 → 落点 = 位置 ÷ 时间轴高度。键盘弹起时
`pointerdown` 的 `clientY=320` 配的是 199px 高的时间轴，等 `click` 时布局已恢复到 611px ——
`320 ÷ 611 × 1440 ≈ 754` 分钟，落成 7:00（点的是 21:00），**实测偏 14 小时**。解法：在
pointerdown 就把分钟算完存快照，click 只取结果（`app/src/app/tapSnap.ts`，也是
`AGENTS.md` 五、13 那条）。复现脚本 `deploy/kbtiming.cjs`（改视口高度即可，不需要真机）。

> 顺带：压缩后时间轴密度是 8.3px/小时（300px 高时只有 3.3px）。换算本身是准的，但手指落点
> 必偏 —— 那是物理问题，不是算法问题。
