# 接口一览

后端在 `server/`，Node 22 + `node:sqlite`，**零 npm 依赖**。
线上只通过 nginx 的 `/schedule/api/` 反代暴露（`127.0.0.1:25692` 不直接对外）。

```bash
# 本地直连（开发时）
curl -s http://127.0.0.1:25692/api/health

# 线上（走 nginx）
curl -s https://home.xiaokubao.space/schedule/api/health
```

**没有版本号**，只有一套接口。所有请求与响应的 body 都是 JSON 对象。

---

## 认证

除了下表标「公开」的四条，其余都要带令牌：

```http
Authorization: Bearer <token>
```

令牌是自签的 JWT（`HS256`，密钥在数据目录的 `secret.key`，0600）。
**退出登录会把 jti 记进吊销表**，所以令牌是真的作废，不只是前端忘掉它。

密码用 `scrypt` 存（每个账户独立 salt），**不存明文、不存可逆哈希**。
用户名不存在时后端也会跑一遍 scrypt —— 否则响应时间会泄露「这个用户名在不在」。

| 接口 | 公开? |
|---|---|
| `GET /api/health` | ✅ |
| `GET /api/auth/state` | ✅ |
| `POST /api/auth/register` | ✅ |
| `POST /api/auth/login` | ✅ |
| 其余 | ❌ 需要 `Authorization` |

## `GET /api/health`

存活探针。

```json
{ "ok": true, "time": 1791106800000 }
```

## `GET /api/auth/state`

登录页据此决定显示「登录」还是「创建第一个账户」。

```json
{ "hasUsers": false }
```

## `POST /api/auth/register`

**只有库里一个用户都没有时才能用**，之后一律 `403`。
这是刻意的：空库时第一个注册者成为管理员，之后关掉自助注册
（开放注册等于把日程本挂在公网）。

```json
// 请求
{ "name": "xiaokubao", "password": "……" }

// 200
{ "token": "eyJ…", "user": { "id": "…", "name": "xiaokubao", "isAdmin": true, "createdAt": 1791224937633 } }
```

| 状态码 | 什么时候 |
|---|---|
| 400 | 用户名或密码不合规（长度等，见 `server/lib/auth.js` 的 `nameProblem` / `passwordProblem`） |
| 403 | 已经有账户了 → 改成调 `POST /api/users` |

> 事务里会**再查一次** `countUsers()`：两个请求同时到达时，第二个在这里被挡住。

## `POST /api/auth/login`

```json
// 请求
{ "name": "xiaokubao", "password": "……" }

// 200
{ "token": "eyJ…", "user": { "id": "…", "name": "xiaokubao", "isAdmin": true, "createdAt": 1791224937633 } }

// 401
{ "error": "用户名或密码不对" }
```

> 用户不存在和密码错**返回同一句话**，不区分。

## `POST /api/auth/logout`

需要登录。把当前令牌的 jti 记进吊销表。

```json
{ "ok": true }
```

## `GET /api/users` — 管理员

```json
{ "users": [ { "id": "…", "name": "…", "isAdmin": true, "createdAt": 1791224937633 } ] }
```

非管理员 `403 { "error": "需要管理员权限" }`。

> **别拿它当「我是谁」用。** 前端把登录返回的 user 缓存进 localStorage
> （`app/src/data/api.ts` 的 `getCachedUser()`），没有 `/api/me` 这个接口。

## `POST /api/users` — 管理员

新建一个**普通**账户（管理员只能靠空库注册那一刻产生）。

```json
// 请求
{ "name": "mama", "password": "……" }

// 200
{ "user": { "id": "…", "name": "mama", "isAdmin": false } }
```

`400` 不合规 · `403` 非管理员 · `409` 用户名已存在。

> **界面上还没有这个入口。** 加人目前只能 curl（见文末例子）。

## `POST /api/sync`

**推和拉是同一次往返。** 客户端永远调这一个接口，不分开。

```json
// 请求
{
  "ops": [ { …op… } ],
  "cursor": 0
}
```

`cursor = 0` 表示「我不知道服务器到哪了」（首次登录 / 换设备）→ 回**全量快照**；
`cursor > 0` 表示增量 → 回**自该游标之后的变更**。

### op 的形状

```json
{
  "opId": "本设备内唯一，用它划掉发件箱里已处理的条目",
  "deviceId": "设备标识（存在 localStorage 的 schedule-app-device）",
  "entity": "task | habit",
  "entityId": "任务/打卡的 id",
  "ts": 1791106800000,
  "fields": { "title": "交周报", "time": "15:00" }
}
```

**一次 op 只带变了的字段**，不是整条任务 —— 这是「逐字段 LWW」的前提，
手机改标题、桌面改日期，两个改动都留得住。

派生 id（重复任务的实例）形如 `a3f2…#2026-10-07`：`#` 前是系列 id，后是发生日。

### 响应

```json
{
  "applied":  ["opId1", "opId2"],
  "rejected": [ { "opId": "…", "code": "clock", "reason": "设备时间与服务器相差超过 24 小时，请校准后再同步" } ],

  // cursor = 0 时
  "cursor": 128,
  "snapshot": { "tasks": { "id": { "title": "…", "_ts": {}, "_dev": {} } }, "habits": {} },

  // cursor > 0 时
  "cursor": 131,
  "changes": [ { "entity": "task", "entityId": "…", "field": "title", "value": "交周报", "ts": 0, "deviceId": "…" } ],
  "truncated": false
}
```

**先落盘再取数** —— 快照必须反映「本批 op 合并之后」的真值，
否则客户端会拿一个慢半拍的快照把自己的写入盖回去。

`applied` 里的 op 表示**已被处理**（不保证胜出），客户端据此把它们从发件箱划掉。
落败的字段会以对方的版本出现在本次响应附带的 `changes` 里，应用后自然收敛。

`rejected[].code` 决定客户端怎么处理：

| code | 含义 | 客户端该做什么 |
|---|---|---|
| `bad_request` | 这条 op 本身有问题，重试多少次都一样 | 丢掉，报错 |
| `clock` | 设备时钟不对 | **留着**，校准后重推 |

### 常量

| 名 | 值 | 在哪 |
|---|---|---|
| 单次最多 op | 2000 | `sync.js` `MAX_OPS` |
| 单次最多回吐变更 | 5000（超了 `truncated: true`，下轮接着拉） | `sync.js` `MAX_PULL` |
| 单字段上限 | 64 KB | `sync.js` `MAX_FIELD_BYTES` |
| 时钟允许偏差 | 24 小时 | `sync.js` `MAX_SKEW_MS` |
| 请求体上限 | 16 MB | `server.js` `MAX_BODY` |

## 为什么不需要 oplog 做幂等

LWW 的比较键是 `(ts, deviceId)`，**两样都由客户端在创建 op 时固定**并持久化在
发件箱里。同一条 op 重放时比较键完全相同 → 既不是 `>`、也不是同值下更大的
deviceId → `ON CONFLICT` 的 `WHERE` 不成立 → **一行都不改**。

所以没必要额外建一张「这批 op 处理过了」的表，也没必要给 op 发号。

> **时间戳只拒绝、不钳制。** 钳制过一版：钳制值取决于「收到请求的那一刻」，
> 同一条 op 重放两次会钳出两个不同的时间戳，幂等性当场破掉（重放被当成新改动）。
> 现在改成超过 24 小时就退回并标 `clock`，客户端留着重试。

## 手工加一个账户

```bash
B=https://home.xiaokubao.space/schedule
TOKEN=$(curl -s -X POST $B/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"name":"你的用户名","password":"你的密码"}' | grep -o '"token":"[^"]*"' | cut -d'"' -f4)

curl -s -X POST $B/api/users \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"mama","password":"……"}'
```

> **别把密码写进任何文件或脚本。** 上面这行是从终端历史里粘的，
> 用完 `history -d` 清掉，或者干脆从标准输入喂。
