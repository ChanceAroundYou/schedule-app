**21. 工程目录经 SMB 共享，偶发丢文件（重要）**
NAS 本机看到的是 btrfs（`/vol2/@team/family/星星包/coding/日程管理`），同一份目录经
SMB 共享给 Windows / 另一台 ubuntu（`/mnt/fnos/family/星星包/coding/日程管理`）。
**实测丢过文件**：编辑工具写完当场还在，几十秒后整个文件没了。
- 传大文件先写本机磁盘再 `cp` + 两端 `md5sum`；写完 / 移动完**立刻 `ls -l`**。
- **改完就提交**（`app/` 曾没进版本库，唯一的后悔药是从会话记录里捞 `Write` 内容）。
- **别用 `perl -i` / `sed -i`**：靠「写临时文件再改名」，跨 SMB 改名会失败、**原始文件当场
  消失**（实测丢过 `app/tests/browser-smoke.mjs`，靠 `git checkout` 捞回）。要用编辑工具或写临时文件再 `mv`，改行尾同理，见 36。

**22. `pkill -f "…"` 会打到自己**
`pkill -f "node server/server.js"` 连同一条命令里的 shell 一起杀（exit 144），因为 zsh 的
命令行本身含这个字符串。**拆成两条命令**；或用端口 `fuser -k 25692/tcp`；写
`node [s]erver/server.js` 只在同一条命令里没有字面量时才有用。无头 Chrome 残留同理，用
`pkill -x chrome`（见 40）。

**23. 非交互式 shell 里 `systemctl --user` 连不上总线**
报 `Failed to connect to user scope bus ... $DBUS_SESSION_BUS_ADDRESS and
$XDG_RUNTIME_DIR not defined`（AI / 脚本执行命令时都撞上，没有登录会话）。先设：
```bash
export XDG_RUNTIME_DIR=/run/user/$(id -u)
export DBUS_SESSION_BUS_ADDRESS=unix:path=$XDG_RUNTIME_DIR/bus
```

**24. 无头 Chrome 的坑（照抄即可）**
- `document.body.textContent` 搜中文会命中内联 `<script>` 源码 → 假阳性；改用
  `document.getElementById('content').textContent`。
- 合成 `DragEvent` 的 `target` 默认是派发元素，`closest('.task-el')` 找不到 → 派发前
  `Object.defineProperty(ev, 'target', { value: 真实元素 })`。
- **别在测试脚本里写 `location.reload()`**：内联脚本随页面重跑 → 无限刷新，headless 挂住。
- 断言 CSS 优先看 `display` / `getComputedStyle`，**别读 `opacity`**（无头下 transition 读值
  不可靠，所以隐藏源底纹用 `display:none`）。
- 合成事件后若触发了重渲染，后续必须**重新 querySelector**（旧引用 `getBoundingClientRect()`
  全是 0）；算「本周内某一天」用 `weekStart(today)` 再偏移，别直接 `today+2`（跨周拿到 null）。
**最小窗口宽度约 526px**（`--window-size=390` 实测 `innerWidth` 526），截图会被裁。**但「触屏」
和「窄屏」是两件事**：触屏只要指针事件带 `pointerType: 'touch'`，**桌面视口下就能合成**：
```js
await page.send('Emulation.setTouchEmulationEnabled', { enabled: true, maxTouchPoints: 1 });
await page.send('Input.dispatchTouchEvent', { type: 'touchStart', touchPoints: [{ x, y }] });
```
三个坑：**必须给 Chrome 加 `--touch-events=enabled`**（否则事件被静默丢掉，不报错只是不生效）；
`maxTouchPoints` **只能 1..16**（给 `0` 报「Touch points must be between 1 and 16」）；抬手也要带坐标。
> **窄屏有两条路，别再混为一谈**：
> ① **伪窄屏** —— `Page.addScriptToEvaluateOnNewDocument` 给 `matchMedia` 套 Proxy 强行判窄。
>    只骗得过 JS（`isNarrow()`），**CSS 的 `@media` 一条都不会生效**，窗口真的还是 1280px。
> ② **真窄屏** —— `Emulation.setDeviceMetricsOverride({ width: 390, height: 854, mobile: true })`
>    再 `Page.navigate` 一次。媒体查询**真的生效**，合成点击也照样进处理器
>    （`sections/smoke/26.mjs` 就是这么断言「真窄屏周视图锁单屏」和「三日视图不横滑」的）。
>    **要测 CSS 层面的窄屏就必须走这条**；`--window-size=390` 不管用（实测 `innerWidth` 仍是
>    526px，那是窗口最小宽度的下限，只会把截图裁掉）。
> 旧版用 iframe 绕开已放弃（headless 下 `iframe.onload` 时序不可靠）。

**25. 快速添加不解析文本 —— 日期是「选」出来的，不是猜出来的**
2026-10-15 用户明确要求删掉自然语言日期 / 时间识别（输入「买 3 本书」被认成 3 号，
猜错比不猜更糟）。`domain/parse/` 整目录已移除，日期 / 时间只剩两个来源：
**时钟面板选的 > 当前 tab 的默认值**（`quickDefaults()`）；重复与时长只能进抽屉设。
**别把解析加回来。**
> 「找日期」输入框是独立的一套（`domain/date.ts` 的 `parseDateText`），认得 `1015` /
> `2026-10` / `上个月`，年份基准是**面板所在月份**不是今天。它由用户主动触发、服务于
> 「跳到某天」，不属于自动识别，保留。

**26. 窄屏的负载文字要用 `shortLoad`，不要用完整时长**
月视图格子窄（53px），完整文案「3小时45分」会**折成三行把日期数字挤扁**。
`D.shortLoad(mins)` 专给窄屏：`225 → 3¾`、`60 → 1时`、`45 → 45分`。只有宽屏才用完整的
`D.fmtDuration`。

**27. 改 nginx 配置在服务器本机的 shell 里直接 cp，别 ssh 自己**
`ubuntu`（`192.168.1.6`）**就是 nginx 与后端所在服务器**。注意工程目录在那边是
**autofs + CIFS 挂载**（`/mnt/fnos/…`），不是本机磁盘 —— 所以「在本机改配置」指的是
**登录到 ubuntu 之后的那个 shell**，不是 NAS 本机（NAS 上 `/vol2/…` 是本机 btrfs，
但那儿没有 nginx 也没有 `~/docker`）。在 ubuntu 上改 `deploy/schedule.conf` 后直接：
```bash
cp deploy/schedule.conf ~/docker/nginx/conf.d/home/schedule.conf
docker exec nginx nginx -t && docker exec nginx nginx -s reload
```
> **别写 `ssh nas`** —— `~/.ssh/config` 里没有这个别名（本机叫 `ubuntu` / `fn`），会报
> `Could not resolve hostname nas`。

**28. 端口 25692 上如果有手动起的进程，systemd 服务会静默重启循环**
表现是 `systemctl --user status` 里 `restart counter is at N`、`journalctl` 里 `EADDRINUSE`。
**排查后端时先看 25692 是谁占着**：`ss -lptn 'sport = :25692'`。

**29. 探针表达式：`waitFor` 只吃表达式、`evalJs` 要自己 `return`**
`evalJs` 把表达式包成 `(async () => { <表达式> })()`，`waitFor` 再在前面加 `return`。
- **`waitFor` 的表达式不能以换行开头**：生成的代码是 `return\n [ …`，**ASI 在 `return` 后补
  分号** → 整条表达式不可达、恒为 `undefined`，一直等到超时（报「最后一次求值 = undefined」，
  看着像应用没反应，其实探针写错了；多行表达式几乎必然踩上）。已在 `waitFor` 里
  `expr.trim()`，别当多余；多行模板也别把 `? 1 : null` 拆到下一行。
- **`waitFor` 只能放表达式**：`const t = …;` 会报 `Unexpected token 'const'`；要写多行就包
  一层 `(() => { … })()`。
- **`evalJs` 不会替你补 `return`**：光写表达式求值恒为 `undefined`，断言永远红而页面其实好
  好的。**规矩：`evalJs` 一律写 `return …;`，`waitFor` 一律不写。**
- `evalJs` 报异常打 `exceptionDetails.exception.description`；只打 `.text` 全是「Uncaught」。

**30. `persist()` 有防抖，别在改动之后立刻读 localStorage**
`store.persist()` 是**防抖**的：「加一条任务 → 立刻读 localStorage」读到的是上一版盘子 ——
界面上那行已经在了、`outbox.length === 0` 也「成立」（读的是旧值），只有任务是空的（像凭空
消失）。要真值就走 DOM 或等轮询，**别把「读一次 localStorage」当同步点**；凡是拿
localStorage 当断言的，都套在 `waitFor` 里。失败**诊断行要带原始值**（防抖前读到
`undefined`，`undefined + 15` 是 `NaN`，表现成「按了键没反应」）。

**31. 写探针时踩到的三个（都会伪装成「应用坏了」）**
加「方向键微调时间轴上下沿」那节时连假失败三轮，**每轮都指向产品代码，实际全是探针的错**：
- **待办箱里快速添加「9:00 开会」得到「有时间、没日期」的任务**（`quickDefaults()` 对
  `nav==='inbox'` 返回 `date: null`），时间轴按 `date` 挑 → 任何日视图都不画方块，探针在
  「等方块」上超时，看着像时间轴渲染坏了。要造时间轴方块就在**日程页**加或写字面日期。
- **`.ev-resize` 会先命中上沿**（上沿 class 是 `ev-resize ev-resize-top`，DOM 里在前）：断言
  名写「下沿」实际查上沿，形状一样于是照样绿。要下沿用 `.ev-resize:not(.ev-resize-top)`。
- **「改 localStorage 再刷新」不作数**：想让 App 起在日程页，最顺手的是直接改写
  localStorage 里的 `ui.nav` 再 reload —— **会被覆盖**，因为离开页面那一刻 App 会把
  自己的内存状态 flush 回去，两个写入方抢同一个键。症状是「明明写了 `ui.nav='calendar'`，
  刷新后还是今天页」，看着像 App 没读盘子。修法：**走界面点**
  （`[data-nav="calendar"]` / `[data-view="week"]`），它本来就是用户那条路径；
  只有一次性种子数据（任务 / 打卡）适合走 API 直写服务端。
> 共同点：**症状全指向产品，根因全在探针**；加断言时顺手把关键中间量打进失败信息。

**32. 合成点击与 `clickEl`**
点击委托是 **pointerdown 驱动**的，`el.click()` 只补一个 `click`，跟真手指 / 真鼠标走的不是
同一条路。要发全：
```js
el.dispatchEvent(new PointerEvent('pointerdown', { bubbles: true, pointerType: 'mouse' }));
el.dispatchEvent(new PointerEvent('pointerup',   { bubbles: true, pointerType: 'mouse' }));
el.dispatchEvent(new MouseEvent('click'));
```
> **「第一下被吃掉」这种症状先怀疑探针**：真手指的点击永远带 pointerdown，合成事件不带。
>
> **受控输入要过 React 的 onChange**：直接写 `el.value = 'x'` 界面没反应（组件根本没有
> 重渲染）。借用原生 setter 再补一个 input 事件才是真进门：
> `Object.getOwnPropertyDescriptor(HTMLTextAreaElement.prototype, 'value').set
> .call(el, v)` 之后 `el.dispatchEvent(new Event('input', { bubbles: true }))`。
> 键盘事件同理：`new KeyboardEvent('keydown', { key: 'Enter', bubbles: true })`。
`clickEl(page, x)` 把 `x` **原样拼进页面求值**（`const el = ${x};`）：必须给完整的
`document.querySelector('…')` —— 只写 `'#content .task-row'` 会被当 JS 源码（`#content` 是
私有字段语法，报 `Private field ... must be declared in an enclosing class`，完全指不到
「选择器写错了」）；字符串用单引号，动态 id 用 `'…[data-id=' + ${JSON.stringify(id)} + ']'`。

**33. 合成方向键要用 CDP 的 `Input.dispatchKeyEvent`**
`el.dispatchEvent(new KeyboardEvent('keydown'))` 的 `target` 是**我们自己摆上去的**：控件压根
拿不到焦点（比如漏了 `tabIndex`）断言照样通过。走 CDP 则按**真实焦点**派发 —— 验过它有牙：
摘掉下沿的 `tabIndex={0}`，焦点落到 `BODY`，断言当场失败。
```js
await page.send('Input.dispatchKeyEvent', { type: 'keyDown', key: 'ArrowDown', code: 'ArrowDown', windowsVirtualKeyCode: 40 });
```
`keyDown` / `rawKeyDown` 都进得来，`keyUp` 要跟着发一个。

**34. 探针里的 `[role="dialog"]` 现在是个歧义选择器**
详情抽屉也变成 `role="dialog"` 后，`waitFor('[role="dialog"]' 存在)` 会**先命中抽屉**（它本来
就开着）：「确认浮层打开」假通过、结尾「等它关掉」永远等不到（报「等不到确认浮层关掉」，
指向 Sheet 实现，问题在选择器）。Sheet 是 portal 到 body 的，用
`body > div > div[role="dialog"]` 或按文字筛。**加了 `role` 就要回头看有没有别的选择器被带偏。**
- **上一节把抽屉留在打开状态，下一节点一行不会重挂组件**，靠 `[id]` 触发的 focus-in
  `useEffect` 根本不会跑（症状：焦点读到快速添加框、「还回原处」等不到）。断言的**前置条件
  也要自己造**，别假设上一节留了干净盘子。
- **`getComputedStyle` 回的是序列化后的值**：CSS 写 `0.01ms`，Chrome 读出来是 `1e-05s`；比
  字符串会假失败，要按单位解析成秒再比大小。

**35. 探针伺服的是 `dist/`，不是源码**
`serveDist()` 读 `../dist`，**改完前端不 `npm run build` 就等于没改**（探针证的只是接线，不
是刚修的那个 bug）。**改完前端先构建，再跑探针。**
- **`dragover` 是连续事件，React 会批处理**：同一个 `evalJs` 里 `dispatchEvent(dragover)`
  紧接着读 DOM，读到的是**上一帧**的让位线（症状 `no-ins`，像事件没进处理器）。要等一拍再读。
- **断言别写死「应该是什么」，要写「和刚才量到的一致」**：侧栏拖拽那节写
  `navBottom === ['habits']`，而正确值是 `['trash','habits']`（垃圾箱**本来就该**留在底部组）。
  和 DOM 里量到的顺序比才既对又不脆。

**36. 行尾一律 LF，`.gitattributes` 锁着 —— 别删它，也别用会改行尾的工具**

全仓库文本文件一律 LF，由根目录 `.gitattributes` 的 `* text=auto eol=lf` 管着。**`eol=lf` 不
能省**：只写 `text=auto` 的话，`core.autocrlf=true` 的机器（Windows）**检出时又会写出 CRLF**；
`eol=lf` 会压过每台机器的 `autocrlf`。
> **为什么单独立一条**：2026-10-07 提交语义样式模块时整个文件被从 CRLF 归一成 LF，
> `git show --stat` 报 **3440 行改动**，而 `git diff --ignore-all-space` 真实改动只有 152/98
> 行 —— 差点把「到底改了什么」整个盖掉。规矩：**一个文件要么一直 LF，要么一直 CRLF**；判断
> 纯行尾改动就用 `git diff --ignore-all-space`。
查残留（有输出就是有）：`git ls-files --eol | grep -v '^i/lf.*w/lf'`。**别用 `sed -i` /
`perl -i` 改行尾**（跨 SMB 编辑时改名失败、原文件当场消失，见 21）。
> 本组还有两条**只在部署时撞上**的，写在 [DEPLOY.md](../DEPLOY.md)「八、排障 · 环境踩坑」：
> `scp` 传中文路径报 `pipe: Unknown error`（改用 `cat 文件 | ssh ubuntu "cat > 目标"`）、
> 以及「NAS 本机 ≠ 服务器 ubuntu」这条最容易搞混的前提。

**37. `ResizeObserver` 不保证投递「元素本来 `display:none`、后来才有盒子」这一步**
窄屏圆钮要跟横条**实测高度**竖直居中，量高度用 `ResizeObserver`；但**收起时挂上的观察者，
展开后收不到第一次通知** —— `barH` 一直是 0，圆钮停在「按一行算」的默认位置，横条一高它偏
上（实测 **20.6px**）。后续高度变化（输入框撑成两行）反而收得到，所以症状是「第一次展开偏、
之后就对了」，很容易当偶发。修法是**两条腿**：`useLayoutEffect` 里同步读 `offsetHeight`
（不依赖观察通知投递）+ `ResizeObserver` 兜「字体替换 / 换行」那一类。

**38. `position: fixed` + `left` / `right` 时，`margin` 会再加一层偏移**
`fixed` 的包含块是视口，`left` / `right` 定位的是它的**外边距盒**。所以
`.fast-add { margin: 6px 22px 18px }` 让 `right: 74px` 实际让出 **96px**、`bottom: 64px` 实际
离底 **82px**。窄屏那套几何是内联 `style` 给的，所以 `margin: 0` 也必须写在内联里 —— CSS
媒体块里清掉不够（媒体查询按**真实**视口宽度走，而探针是「JS 判窄、CSS 判宽」的环境，见
24），那边清不掉，量出来就是「差 22px」这种看着像算错了的数。同类坑：`fixed` 的 `width: 100%` 是**视口**的 100%，不是父元素的。

**39. 假模型的「第几次调用」不能当轮次判据**
假模型服务原先写 `if (modelCalls === 1)` 就给 tool_call。**那个全局计数不是「这一轮对话的
第几轮」** —— 它数的是进程里所有打到这个端口的请求。SDK 重试一次、晚间汇报插一脚、别的账号
也指着这个 baseUrl，计数就错位，第一轮拿到「文本收尾」。后果特别难查：**一条报错都没有**，
文本是合法响应，只是没 tool_call、也就没提案，表现成「卡片不出来」（偶发约 1/9，日志全干
净）。判据换成**看对话内容**：这一轮 `messages` 里出现 `role:'tool'` 就说明上一轮工具已执行、
该收尾了。重试和串扰都不再影响（原来的症状是从 15 秒超时完全看不出方向）。
> 顺带验掉一个很像的假设：以为 React 对 `input` 的 flush 是异步的、同任务里紧接着派发
> `keydown` 会命中旧闭包。**实测不成立** —— React 对离散事件是同步 flush 的。

**40. 跑完测试必须收干净，否则下一轮假失败（Chrome · 服务 · 端口）**
- **Chrome 进程**：无头 Chrome 被 kill / OOM 后会残留（实测一次攒到 30 多个），12 GB 的机器被
  吃到见底，下一轮直接被 SIGKILL（exit 137），报在「等不到侧栏渲染」上 —— 看着像产品 bug。
  跑完 `pkill -x chrome`（`chrome_crashpad_handler` 一并），再 `ps aux | grep -c '[c]hrome'`。
- **端口**：`browser-smoke.mjs` 的四个端口（`API_PORT` 25701 · `WEB_PORT` 5198 · `CDP_PORT`
  9223 · `MODEL_PORT` 25711）**首选被占就自动让开**，起手那行「端口：…（首选 X 被占，
  已让开）」就是定位是哪一趟占的。也能用环境变量钉死（前缀是 `SMOKE_`）：
  `SMOKE_API_PORT=25741 SMOKE_WEB_PORT=5328 SMOKE_CDP_PORT=9343 node tests/browser-smoke.mjs`。
- **避让只解决「起之前就占着」**，不解决「起的时候被抢」：假模型那个服务器第十二节才起，
  号是开头挑的，中间几十秒可能被别的探针占上 —— 两个 `listen` 另走 `listenFree`，
  真被抢就退内核分配。**这两条都只保这一趟**。
- **最坑的是「静默连到残留的旧后端」**：新起的那份失败退出，探针转去连旧的，报的错完全
  指错地方（实测 `/api/auth/register` 409 —— 旧库里已有那个用户）。
  收尾：`pkill -x chrome`；`ss -ltnp | grep -E '5198|25701'` 找 pid `kill`；
  `rm -rf /tmp/sched-browser-*`。

- **注释里别写占位符类名**：Tailwind 4 的扫描器是**裸文本匹配** —— 注释、字符串、
  文档片段里出现的类名形状它照样当真，于是给占位符生成**非法** CSS。
  本项目实际踩过：`app/tests/contrast.mjs` 讲圆角约定的注释里，用三个横杠加一个星号
  当通配写了个 `rounded-` 接 `var()` 的样子，另有一处字面量写了省略号，构建稳定报
  `Found 2 warnings while optimizing generated CSS: Unexpected token`，生成两条
  `border-radius:var(--r-*)` / `var(...)`。
  - **症状极轻**：那两条规则非法、浏览器直接丢，样式**一点没坏**，所以没人会发现；
    代价只是每次构建刷两条黄字，久了就当背景噪音，真正的新警告反而看不见了。
  - **要举例就写个真令牌**（`--r-md`），别写占位符。改完产物里那两条非法规则就没了。
  - 别为了消警告去改 `.gitignore` 或 Tailwind 的扫描范围 —— 真正的源头是源码里的
    注释，**先查 `grep -rn -F 'rounded-[var('` 定位到具体那行**。
    （当年这条坑差点被误诊成「Tailwind 扫到了 `.mindfs/` 里的历史会话日志」——
    `.mindfs/` 确实在 `.gitignore` 里，而日志里出现那串字符是因为它**抄了源码行**，
    不是因为被扫到了。**下结论前先确认那串字符到底在哪个目录。**）

## adb / 真机调试（2026-10-17）

### 1. `adb pull` 的目标路径必须是 Windows 盘符形式

这条命令同时带**远端 Unix 路径**（`/sdcard/x.png`）和**本地路径**：
远端要靠 `MSYS_NO_PATHCONV=1` 才不被转坏，而转换被关掉后 `/tmp/x.png` 就变成
一个 Windows 上不存在的目录。**不报错**，只是文件没生成 —— 单独手跑正常、
放进脚本就空文件，很难查。

```bash
SHOT="$(cd /tmp && pwd -W)/shot-$(date +%H%M%S).png"     # ← 用这个
MSYS_NO_PATHCONV=1 "$ADB" pull /sdcard/loop.png "$SHOT"
```

### 2. 别反复 `adb connect`

每连一次手机弹一次「已连接到无线调试」的系统通知，**用户会烦死**。
会话开头 `start-server` + `connect` 一次，之后全程复用；不确定就在同一条命令里串起来。
端口会轮换，连不上先 `adb mdns services` 重新发现，再向用户要当前地址。

### 3. adb / CDP 注入唤不出软键盘

Android 只允许**真实用户手势**弹输入法。所以凡是键盘、输入法、布局被撑变的现象
**都无法自动复现**。别把「测不了」当成「没发生」—— 用户报的现象先当真 bug 查
（这一点上误判过两次）。

### 4. WebView 的 DNS 可能整体失效

App 里 `fetch` 任何域名都在 20–30ms 内失败、`transferSize=0`，连 baidu 都
`net::ERR_NAME_NOT_RESOLVED`；但**系统 ping、系统浏览器、原生 HttpURLConnection 全正常**
（表现是「检查更新」按钮能用、界面却一直挂「连不上服务器」）。

- 不是服务端、不是证书、不是 CORS、也不是 Private Network Access。
- 解法：`capacitor.config.ts` 启用 `CapacitorHttp`（fetch 改走 Android 原生网络栈）。
- 取证靠 CDP 的 `Network` 域（`loadingFailed.errorText`），别在页面里猜。

### 5. 「连不上服务器」其二：原生栈拿到 Cloudflare IP，而家里宽带直连它被丢包

2026-10-19 真机实测。和第 4 条**表象一样、根因不同**：CapacitorHttp 工作正常
（`baidu.com` 195ms、IP 字面量 TLS 103ms 都通），但 `home.xiaokubao.space` 稳定
10.2 秒后 `SSLHandshakeException: connection closed`。

**一句话**：手机拿不到路由器那条「域名 → 192.168.1.6」的内网解析，绕去 Cloudflare
（`172.64.x`）被丢弃。路由器本身解析是对的，但手机 `DnsAddresses` 退到了公网 DNS
（`180.76.76.76 / 223.5.5.5`），IPv6 也没有默认路由。**不是代码 bug，是网络路径。**

解法（不动手机 DNS、不依赖 Cloudflare）—— 局域网 IP 直连，三处已经落地：

1. NAS 的 nginx `conf.d/servers/zz-lan-direct.conf`：80 端口 `listen 80 default_server`，
   Host 是 IPv4 字面量时**不跳 https**，明文伺服 `/schedule/`；域名访问照旧 301。
2. `app/android/app/src/main/res/xml/network_security_config.xml` 按域名精确放行
   `192.168.1.6`（**别用 `usesCleartextTraffic="true"`**，那是全局明文）。
3. `API_BASE=http://192.168.1.6/schedule ./deploy/build-apk.sh`（`UPDATE_BASE` 已可 env 覆盖，
   默认仍是域名，正式包不受影响）。

**已知边界**：这个包**只在家用局域网能用**，出门（移动数据）连不上内网 IP。要一包通吃得
在 `request.ts` 做「基址失败自动切换 + sticky」，没做。

> 取证套路（半小时定位）：CDP 里直接调
> `window.Capacitor.Plugins.CapacitorHttp.request({method,url})` 打四个样本 ——
> 真实域名 / 不存在的子域 / IP 字面量 / 公网知名域名。「DNS 坏」「TLS 坏」「解析到不通的
> IP」三种病因当场分开。手机侧解析看 `adb shell getprop | grep net.dns`。

## git / GitHub 连通性卡点（2026-10-24）

- 环境里挂着代理（`http_proxy` = `http://127.0.0.1:52341`）：curl 走它通，但
  **git 走它会握手失败或挂起无输出**；清代理变量直连也不通。
- 两条可用路径：① **HTTPS 原样重试**（多为瞬时故障，多给几十秒就通）；
  ② **SSH 通道**（`ssh -T git@github.com` 认证直接过）：
  `git -c url."ssh://git@github.com/".insteadOf="https://github.com/" <命令>`。
- `gh auth status` 报 keyring 登录失败**不影响 git 推送**，别被它带偏。
- **结论**：见到 `git ls-remote` 失败先原样重试一次，再考虑 SSH insteadOf，
  不要一头扎进代理排查（本机在这上面虚耗过 3 分钟）。

## WorkBuddy 沙箱劫持 rm/unlink/rmdir —— 发版脚本别落临时文件再删（2026-10-25）

- **机制**：WorkBuddy 沙箱用 `BASH_ENV` 全局注入 `rm` / `unlink` / `rmdir` 三个函数
  （转发到 `CODEBUDDY_SAFE_DELETE_BIN_DIR` 下的 shim，**bash 子进程也会带上**，`bash xx.sh`
  照样中招）。参数**内嵌 `X:`**（`*/[A-Za-z]:*`，如 `C:/Users/...`）即拒收：
  `[safe-delete][SAFE_DELETE_INVALID_PATH] embedded drive prefix is not allowed`，**exit 64**
  —— `set -e` 脚本当场死。
- **症状**（2026-10-24/25 连坑 4 次）：publish-apk.sh 曾用 `mktemp` + `trap 'rm -f' EXIT`
  写 version.json，mktemp 在 Git Bash 返回盘符路径 → 收尾 rm 被 shim 拦 → **已经发成功**
  的版本以非零码退出 → mobile-loop 判定「发布失败」→ **装机被跳过**，且每次表现都是
  「发布实际成功 + 结尾报 SAFE_DELETE」。
- **规矩**：
  1. 发版脚本**不落临时文件再删**——数据从 stdin 直传（30a8fc0 已改：`"$SSH" host "cat > 目标" <<EOF`）。
  2. 调用方判发布成败**以产物回读为准**（version.json 回读 + HTTP 200），别只信退出码。
  3. 临时验证脚本要删自己产的东西时，删 POSIX 形式路径（`/tmp/...`）没事；删盘符路径必被拦。
