# 组件库

`app/src/ui/kit.tsx` —— 全应用统一的 UI 组件库。

## 为什么需要组件库

旧版有 40+ 个按钮类和 6+ 个输入框类散落在 `legacy.css` 里，各自长歪了：
- 月/周视图的勾选圈是 `<span>`（Tab 进不去、没有按钮角色、读屏念不出）
- 打卡页和时间轴的勾选圈没有可访问名字
- 逾期行的标题写死成「标记完成」（已完成时也是这句，读屏听起来是反的）

收成一个组件库，这些漂移就不可能再发生。

## 组件清单

### Btn

按钮。**四种固定 variant**，覆盖全应用所有动作按钮：

| variant | 用途 | 样式 |
|---------|------|------|
| `primary` | 主操作（保存、确认、跳转） | 实心 `--primary` 底 |
| `normal` | 普通操作（导航、切换、取消） | 透明底 + `--input` 描边 |
| `ghost` | 极轻操作（关闭、清空） | 透明底，无描边 |
| `danger` | 危险操作（删除、退出） | 透明底 + `--danger` 描边 |

三种 size：

| size | 高度 | 内边距 | 字号 |
|------|------|--------|------|
| `sm` | 30px | `0 10px` | 12.5px |
| `md` | 36px | `0 14px` | 14px |
| `lg` | 44px | `0 20px` | 15px |

`sm` 那 30px 不是随手定的：顶栏副 header 那排控件（上一/下一个 · 今 · 找日期 · 日周月）
**必须同高**，高度写死 30px 而不是靠 padding 推 —— 12.5px 的 `line-height: normal`
各浏览器差 1~2px，光靠 padding 永远对不齐。

```tsx
import { Btn } from './kit.tsx';

<Btn variant="primary" onClick={save}>保存</Btn>
<Btn variant="ghost" size="sm" onClick={cancel}>取消</Btn>
<Btn variant="danger" onClick={remove}><Trash2 size={14} /> 删除</Btn>
```

**选中态用 `aria-pressed`，不要再加 variant。** 需要「选中就亮」的按钮（比如顶栏的
「今」）传 `aria-pressed={bool}`，配色由 `legacy.css` 的 `.date-nav [aria-pressed="true"]`
统一给。展开式控件（弹出浮层那个）用 `aria-expanded` + `aria-haspopup="dialog"`。

**`Btn` 带一个稳定的 `btn` 类名**，给测试和 `legacy.css` 当钩子：探针要量「日期导航
那四个控件高度一致」，靠的是 `.date-nav .btn`；而 `legacy.css` 里
`.cal-subhead .date-nav .btn { height: 34px }` 这条也只有它才接得到。没有这个类名，
那两处都是对空选择器说话。`Btn` 与 `IconBtn` 都是 `forwardRef`，`ref` 能拿到那个
真 `<button>` —— 浮层的 outside-close 要靠它拿「开合键自己」当例外。

**哪些 `<button>` 不该换成 `Btn`：** 视图分段切换（日/周/月）、底部标签栏、
菜单项、日历格子、勾选圈（`CheckBtn`）、拖拽把手、快速添加圆钮。
它们是**结构控件**，有自己的布局协议，换成 `Btn` 会把网格/分段布局弄坏。
判据：这个按钮的尺寸是**内容撑出来的**，还是**父容器按格分配的**？后者别换。

### Input / Select / Textarea

输入框 / 下拉框 / 文本域。样式全部引用 `legacy.css` 的设计令牌，不在 `.tsx` 里写死颜色。
三者共用一份 `CONTROL` 常量 —— 改边框 / 底色 / 焦点 / 禁用只改一处。

```tsx
import { Input, Select, Textarea } from './kit.tsx';

<Input type="text" value={title} onChange={...} />
<Select value={unit} onChange={...}>
  <option value="day">每天</option>
  <option value="week">每周</option>
</Select>
<Textarea rows={5} value={note} onChange={...} />
```

`Select` 也支持 `options` 属性（优先于子元素）：

```tsx
<Select
  value={unit}
  options={[{ value: 'day', label: '每天' }, { value: 'week', label: '每周' }]}
  onChange={...}
/>
```

**`dense` 属性**给行内控件用：宽度跟着内容走、高度对齐 `Btn` 的 `sm` 档（30px）。
默认是整行字段（`.field` 里那种，宽度撑满）。AI 面板那几行「标签 + 下拉」用整行
会把一行撑破，用 `dense` 才排得下。不叫 `size` —— 那是 `<select>` 的原生属性
（可见行数），遮掉会出岔子。

### Field

字段外壳：`label` + 控件 + 提示 / 错误。只统一**结构**，校验逻辑留在调用方。

```tsx
import { Field, Input } from './kit.tsx';

<Field label="项目名称" htmlFor="pj-name" hint="随便起，之后能改" error={err}>
  <Input id="pj-name" value={name} onChange={...} />
</Field>
```

- 控件的 `id` 和 `htmlFor` 要指向同一个值（组件不替你做这件事）
- 有 `error` 时顶掉 `hint`，两者不同时出现
- `error` 带 `role="alert"`，读屏会念，不用调用方再补 `aria-describedby`

### IconBtn

图标按钮。必须有 `label` 属性（可访问名字）。

```tsx
import { IconBtn } from './kit.tsx';

<IconBtn label="关闭" onClick={onClose}><X size={16} /></IconBtn>
```

### Sheet / useConfirm / toast

底部浮层 / 确认框 / 全局提示。

```tsx
import { Sheet, useConfirm, toast } from './kit.tsx';

// Sheet
<Sheet open={open} onClose={onClose} title="标题" footer={...}>
  内容
</Sheet>

// useConfirm
const confirm = useConfirm();
const ok = await confirm({ title: '删除？', body: '删了找不回来', danger: true });
if (ok) { ... }

// toast
toast('已保存');
toast('已删除', { label: '撤销', run: () => restore() });
```

### useOutsideClose

`ui/hooks.ts` 的 `useOutsideClose(ref, open, close, trigger?)` 管浮层「点外面收起」。
第四个参数 `trigger` 是**开合那个按钮**的 ref —— 没有它就会跟开关自己打架：
`mousedown` 先关，紧接着 `click` 又把状态翻回来，表现是「点搜索键关不掉搜索框」。
判据是「这一下是不是落在开关上」，不是「浮层开没开」。

```tsx
const btn = useRef<HTMLButtonElement>(null);
<IconBtn ref={btn} onClick={() => setOpen(!open)}>...</IconBtn>
<Pop open={open} triggerRef={btn} />
```

## 设计令牌

组件样式全部引用 `legacy.css` 的设计令牌，不在 `.tsx` 里写死颜色：

- `--primary` / `--on-primary` —— 主色 / 主色上的文字
- `--text` / `--text-2` / `--text-3` —— 文字三档
- `--panel` / `--panel-2` / `--panel-3` —— 面板三档
- `--input` / `--border` / `--border-w` —— 描边三档
- `--r-md` / `--r-lg` / `--r-pill` —— 圆角
- `--danger` / `--danger-soft` —— 危险色 / 危险色软底

**规则：**
1. `.tsx` 里引用变量一律不给兜底值（有兜底值时不报错、不白屏，只是两套主题下全在用写死的浅色）
2. `--border`（装饰线）与 `--input`（交互控件描边）按「用户能不能操作它」分档
3. 风格轴两半：线粗细走 `--border-w`，圆角走 `--r-xs/sm/md/lg/xl/pill`

## 测试

两条扫描锁着设计令牌的使用：

```bash
cd app && node tests/contrast.mjs    # 对比度 + 未定义变量 + var() 兜底值 + Tailwind 圆角类
cd app && node tests/color-scan.mjs  # legacy.css 与 tailwind.css 里的写死圆角 / 边框 / 颜色
```

`contrast.mjs` 共 72 对，不达标 0 条。其中「`.tsx` 里 Tailwind 自带的圆角类」
是后加的 —— 这类写死值切到 flat / notion 时原地不动，而且不报错、不崩，
只靠肉眼在 6 色板 × 3 风格 × 2 深浅里找是找不到的。

`color-scan.mjs` 原来只扫 `legacy.css`，新表面（`tailwind.css`）没人锁 ——
已补上，同一套 BANNED 规则 + 同样的「不给 `var()` 兜底值」判据。
