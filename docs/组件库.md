# 组件库

`app/src/ui/kit.tsx` —— 全应用统一的 UI 组件库。

## 为什么需要组件库

旧版有 40+ 个按钮类和 6+ 个输入框类散落在旧版样式文件里，各自长歪了：
- 月/周视图的勾选圈是 `<span>`（Tab 进不去、没有按钮角色、读屏念不出）
- 打卡页和时间轴的勾选圈没有可访问名字
- 逾期行的标题写死成「标记完成」（已完成时也是这句，读屏听起来是反的）

收成一个组件库，这些漂移就不可能再发生。

## 组件清单

### Btn

按钮。六种固定 variant，覆盖全应用所有按钮场景：

| variant | 用途 | 样式 |
|---------|------|------|
| `primary` | 主操作（保存、确认、跳转） | 实心 `--primary` 底 |
| `normal` | 普通操作（导航、切换、取消） | 透明底 + `--input` 描边 |
| `ghost` | 极轻操作（关闭、清空） | 透明底，无描边 |
| `danger` | 危险操作（删除、退出） | 透明底 + `--danger` 描边 |
| `chip` | 标签式操作（筛选、选择）—— **未选中**那一档 | `--panel` 底 + `--input` 描边 |
| `chipOn` | 同一个胶囊的**选中**档 | `--panel` 底 + `--primary` 描边 + `--primary` 文字 |

`chip` / `chipOn` 是一对，由 `Chips` 在两档之间切。**两者边框都在**：选中只换颜色
不换几何，否则选中的那个会少一圈边框、缩 2px，点一下整排抖一下。

**选中档不填充底色。** 原先填的是实心 `--primary`，于是「色板」那一行里每个胶囊
上画的色点（它画的就是 `--primary`）整个消失在主色底上 —— 用户的原话是
「颜色圆点完全看不见」。不填充之后色点在 `--panel` 上正常显色，选中态靠主色
描边 + 主色文字，形状和 `normal` 一样（有描边、有底色面），只是换成主色。

分成两档、而不是给 `chip` 叠一层 `className`：Tailwind 里同特异度的工具类谁赢
只看生成顺序，叠 `className` 会在某个值上静默失效 —— 那正是「切风格时这个按钮
和别的不一致」那个 bug 的成因。**新增 variant 必须先在这里加。**

三种 size：

| size | 高度 | 内边距 | 字号 |
|------|------|--------|------|
| `sm` | 30px | `0 10px` | 12.5px |
| `md` | 36px | `0 14px` | 14px |
| `lg` | 44px | `0 20px` | 15px |

> 圆角、边框宽度、颜色**全部**走令牌（`--r-md` / `--border-w` / `--input`…），
> 所以三档风格切过去时所有按钮一起变。`.tsx` 里手写 `border`（Tailwind 的 1px）
> 或 `rounded-[var(--r-pill)]` 会绕开这一条 —— 切到 flat 时只有它还是 1px 细线。

```tsx
import { Btn } from './kit.tsx';

<Btn variant="primary" onClick={save}>保存</Btn>
<Btn variant="ghost" size="sm" onClick={cancel}>取消</Btn>
<Btn variant="danger" onClick={remove}><Trash2 size={14} /> 删除</Btn>
```

### Input / Textarea

输入框 / 文本域。样式全部引用 `styles/tokens.css` 的设计令牌，不在 `.tsx` 里写死颜色。

**字号统一 13px**，`Input` 的普通档和 `dense` 档都是 —— 13px 是**界面文字那一档**
（成员名、列表行、`InlineRename` 的显示态都是 13px）。输入框里的字必须和它旁边那行字
一模一样，否则点一下铅笔，同一行字会当场变大一号。`dense` 只改高度和内边距
（`h-[30px] px-2`），**不改字号**。

```tsx
import { Input, Textarea } from './kit.tsx';

<Input type="text" value={title} onChange={...} />
<Input dense value={name} onChange={...} />
<Textarea rows={5} value={note} onChange={...} />
```

> ⚠️ **给表单控件定字号的规则必须待在 `@layer base` 里。** `tokens.css` 里的语义
> 样式模块整体不进 `@layer`（第 17 条：没有层的作者样式永远赢过层内样式，这正是
> 「已定稿的表面压过工具类」要的效果）—— 但同一条规律会反咬：那里原先有一条
> **没有层**的 `input, select, textarea { font-size: 14px }`，它把这里每一个
> `text-*` 都静默吃掉了（`dense` 的 12.5px、行内改名框的 13px 全是白写的）。
>
> **而真凶是 `styles/responsive.css` 里另一条同样没有层的**
> `input, select, textarea { font-size: max(14px, 16px) }`（防 iOS 聚焦时自动放大
> 页面）—— 它把**全项目每一个输入框**都钉在 16px，连 kit 的 `<Input>` / `<Textarea>`
> 也跑不掉。同一个抽屉里因此有两种字号：`.field input` 是 13px（类选择器压得过它），
> `<Input>` 是 16px。修法是 `responsive.css` 那条删掉桌面端那一半，只留
> `@media (max-width: 820px)` 里的 16px（≤820px 下这两个组件仍是 16px，那是 iOS 的
> 规矩）。**这条必须留在没有层的作者样式里** —— 它是全项目唯一还压得住组件上
> `text-*` 的东西。详见[踩坑 45](踩坑-前端.md)。

### IconBtn / MiniIconBtn

图标按钮。两个尺寸档，都**必须有 `label`**（它就是可访问名字，同时当 `title`）。

| 组件 | 尺寸 | 用在哪 |
|------|------|--------|
| `IconBtn` | 32×32，`--r-pill` 圆钮 | 抽屉关闭、顶栏、AI 面板那排 |
| `MiniIconBtn` | 24×24，`--r-sm` 圆角 | **由 13px 文本撑高的紧凑行**：成员行、邀请行 |

`MiniIconBtn` 是必需的，不是可选的「小号 IconBtn」：32px 塞进成员行会把整行顶高
11px。24px 是 WCAG 2.5.8 的下限，**别再往小改**。`danger` 给「移出 / 撤回」这类
会改变关系的操作（hover 变 `--danger`）。

两个**色调档**，都是 prop：

| prop | 静息色 | 用在哪 |
|------|--------|--------|
| （默认） | `--text-3` | 大多数图标动作：改名、展开、移出 |
| `danger` | `--text-3`，hover 转 `--danger` + `--danger-soft` 底 | 移出 / 撤回 / 删除这类改变关系的 |
| `primary` | `--primary` | 那一组里**唯一要突出的那个**：编辑态的 ✓（旁边是灰的 ✕）、默认集的星标、发出邀请 |

> ⚠️ **色调必须走 prop，不能在外面叠 `className`。** 叠一句
> `className="text-[var(--primary)]"` 是**不生效**的：它和基类里的
> `text-[var(--text-3)]` 特异度一样，Tailwind 里同特异度只看**生成顺序**，
> 跟 `className` 写在前面还是后面无关。症状是「类名一个不少、颜色一点没变」——
> 实测确认钮拿到的是 `rgb(95,101,119)`，和旁边那个 ✕ 一模一样。
> 同一个道理就是 `Btn` 为什么要拆 `chip` / `chipOn` 两档（见踩坑 17）。
>
> 另外：`MiniIconBtn` 带 `transition`，React 又会**复用同一个 `<button>`**
> （铅笔 → ✓），所以切进编辑态**立刻读 `color` 会读到动画中途的值**（150ms）。
> 探针里要先轮询到落定再比。

> ⚠️ **尺寸必须写 `h-[24px] w-[24px]`，不能写 `h-6 w-6`。** Tailwind 的间距刻度是
> 「0.25rem × n」，而本项目 `html { font-size: 14px }`，于是 `1rem = 14px`、
> 一档 = **3.5px** —— `h-6` 是 **21px**，比下限差 3px。这个差肉眼看不出来，
> 所以它一直藏着：组件库里注释写着 24px，实测只有 21px。

```tsx
import { IconBtn, MiniIconBtn } from './kit.tsx';

<IconBtn label="关闭" onClick={onClose}><X size={16} /></IconBtn>
<MiniIconBtn danger label="移出日程集" onClick={kick}><UserMinus size={13} /></MiniIconBtn>
<MiniIconBtn primary label="确认" onClick={commit}><Check size={14} /></MiniIconBtn>
```

### Dropdown

下拉选择器 —— 一个按钮，点开是**自己的菜单**（不是浏览器默认菜单，也不是 Sheet）。用于「选项不多但要省横向空间」的场合：成员权限、AI 授权项那几行。

**零原生 `<select>`** 是全局约定：原生 select 在 PWA 里样式不可控、和设计系统不一致，移动端体验也差。要一直看得见选项用 Chips，选项动态或很多用 SheetPicker。

> **选项多到二三十个、但仍旧是「一排里挑一个」的场合，也是 `Dropdown`** ——
> 菜单自带 `max-h-64 overflow-y-auto`，25 个整点在 DOM 里一个不少，滚动不影响
> 按键和读屏。设置页那两个时间窗（0:00 … 24:00）就是这么用的。
>
> **别看到「时间」就去搬 `ClockBody` 那只转盘**：时间窗的值域是 **0–24 的整点**，
> 而 `ui.dayFrom` / `ui.dayTo` 在领域里就是**小时数**（`windowOf()` 做
> `Math.round(dayFrom) * 60`）。转盘给的是 `HH:MM`，而且**画不出 24:00**
> —— 它最上面那个是 0 点。换转盘就得连领域和 `domain.test.ts` 里那几条
> `{dayFrom: 7, dayTo: 23} → {from: 420, to: 1380}` 一起改，
> 还会把「结束 = 24:00（一直到今天结束）」这个值弄丢。

```tsx
import { Dropdown } from './kit.tsx';

<Dropdown<Role>
  value={m.role}
  options={ROLES.map((r) => ({ value: r, label: ROLE_LABEL[r] }))}
  onPick={(r) => void setRole(r)}
  label={`「${m.name}」的权限`}
  size="sm"
/>
```

| 属性 | 说明 |
|---|---|
| `value` | 当前值，`null` 显示 `placeholder` |
| `options` | `{ value, label, disabled? }[]` |
| `onPick` | 选中回调 |
| `label` / `labelledBy` | 可访问名字。**`label` 必填**，没有可见标签时它就是名字 |
| `size` | 复用 `Btn` 的 `sm` / `md` / `lg` |
| `renderValue` / `renderOption` | 在按钮与选项里插色点、图标 |
| `className` / `menuClassName` | 接同一套令牌下的尺寸与强调色 |

**`renderValue` 拿到的可能是 `undefined`** —— 当前值不在 `options` 里的时候。
日程集成员那个角色下拉就是这样：`owner` 不在 `ASSIGNABLE_ROLES` 里（它不是能分
下去的权限），但触发按钮上仍然要写着「创建者」。不给 `renderValue` 的话，它会在
选项里找不到当前值、回退成 `placeholder`「选择…」，于是创建者那一格显示成
「选择…」。**传了 `renderValue` 就以它为准**，不再回退。

键盘：`↑` `↓` 移动、`Enter` 选中、`Esc` 关闭，`aria-haspopup="listbox"` + `aria-expanded`。

**面板宽度是 `w-max min-w-full`，选项文字加 `whitespace-nowrap`。** 面板是绝对定位的，
宽度走 shrink-to-fit —— 触发按钮窄的时候（成员行那个角色选择器只有 78px），
只写 `min-w-full` 面板会被压到触发按钮那么窄，于是「可编辑」竖着断成两行
（实测 option 高 53px = 两行）。现在面板按内容撑开（90px），选项一行 33.5px。

### Chips

胶囊选择器 —— 一排二选一。**不是 `<select>`**：原生 select 在 PWA 里样式不可控、和项目设计系统不一致，且移动端体验差。小选项集（≤ 7 个固定选项）一律用这个。

**每个胶囊就是一个 `Btn`**（`chip` / `chipOn` 两档），不是另画一套。这一点是硬的：
这里原先自己写了一遍 `rounded-[var(--r-pill)] border …`，和 `Btn` 差在三处 ——
圆角走 `--r-pill` 而按钮走 `--r-md`、边框写死 Tailwind 的 `border`（1px）而按钮走
`--border-w`、未选中用装饰线 `--border` 而按钮用 ≥3:1 的 `--input`。症状就是
「切到 flat 时别的按钮线变 2px、这几个还是 1px」。**组件库里没有第二套画法。**

```tsx
import { Chips } from './kit.tsx';

<Chips<Role>
  value={role}
  options={['owner', 'editor', 'viewer']}
  onPick={(r) => setRole(r)}
  labelOf={(r) => ROLE_LABEL[r]}
  label="权限"
/>
```

> 一组控件用 `label`（会渲染成 `role="group"`）；只有一个输入框时才用
> `<label htmlFor>`。别拿 `<label>` 去套一组按钮 —— 读屏会念成一个不存在的表单控件。

### SheetPicker

动态 / 大选项集的选择器：一个按钮，点开是 Sheet 浮层。用于选项数量不固定（如项目列表）或选项较多的场合。小选项集用 Chips 更直接。

```tsx
import { SheetPicker } from './kit.tsx';

<SheetPicker<string>
  value={calId}
  options={cals.map((c) => ({ value: c.id, label: c.name }))}
  onPick={(id) => setCalId(id)}
  label="选择日程集"
/>
```

### InlineRename

行内改名。**项目里所有改名都走它**，形状固定一套：

```
平时    [ 显示内容 ][ 铅笔 ][ extraAction ]    ← 第二格可选
编辑中  [ 输入框   ][ √ ][ ✕ ]
```

**切换编辑态时左边那段内容一像素都不动**，这是它存在的全部理由。靠两条硬约束：

1. **动作槽固定宽度** `w-[52px]`（= 24 + 4 + 24，正好两格），右对齐，**两态都是两个
   按钮** —— 平时「铅笔 + `extraAction`」，编辑中「√ + ✕」。数目一样，槽宽就不变，
   左边可用宽度也不变，会截断的文字不会重新折行。只给铅笔、不给 `extraAction` 时
   **也照样占满 52px**：槽的右边缘是一切对齐的基准，不能随内容伸缩。
2. **行高交给外层**：组件自己不定高，调用方给一个固定高度的容器（日程集 header
   是 `h-[40px]`，输入框 `h-[28px]`、按钮 24px）。两态落在同一个高度上，下面的
   东西才不会被顶一下。

`display` 由调用方给，是个 `ReactNode` 而不是一段文字 —— 显示态常常是「一段文字 +
星标 + 徽标」，**里面还有按钮**。组件不去猜它长什么样，只负责把那几格摆稳。

**编辑态整个 `display` 和整个动作槽都被换掉**，所以：

- 想「编辑时隐藏」的东西，**塞进 `display` 或 `extraAction` 里就行**，它会自己消失，
  外面不用再判一次 `editing`。日程集 header 的星标（「设为默认」）就在 `display` 里
  紧跟着名字 —— 不会出现「名字已经是输入框了，星标还杵在旁边」这种两处状态对不上的错位。
- 反过来的约束：**`display` 里可以有按钮，但别把 `display` 整个包进 `<button>`** ——
  按钮套按钮是非法 HTML，`<input>` 也进不了 `<button>`。需要「点整行展开」时，那个
  开关必须放在 `InlineRename` **外面**（日程集 header 现在把它单独放在最右的
  「箭头区」，由它独家持有 `aria-expanded`）。

编辑态里是**真 `<input>`**，不是 `<span contenteditable>`：后者没有输入法、没有
撤销栈、没有平台的读屏支持。`Enter` 提交、`Esc` 取消。输入框字号 = 显示态字号
（都是 13px），点铅笔那一行字不会跳一下。

两个动作槽按钮的色调是**分开**的：`√` 走 `MiniIconBtn primary`（编辑态里它是唯一的
「落定」动作，两个灰按钮并排看不出哪个是哪个），`✕` 是默认的灰。**别改成叠
`className`** —— 那样两个都会是灰的，理由见上面 `IconBtn / MiniIconBtn` 那条。

```tsx
import { InlineRename } from './kit.tsx';

<InlineRename
  value={cal.name}
  label="日程集名字"
  disabled={!manage || busy}
  onSave={saveName}
  /* 只在平时出现：编辑态被 √ / ✕ 顶掉 */
  extraAction={manage ? <MiniIconBtn danger label="删除日程集" onClick={remove}><Trash2 size={13} /></MiniIconBtn> : null}
  display={<span>{cal.name}<MiniIconBtn label="设为默认日程集"><Star size={13} /></MiniIconBtn></span>}
/>
```

> 探针抓手走 `inputProps` / `confirmProps` 透传（`data-cal-name` / `data-cal-save`）。
> `browser-smoke.mjs` 里有一条断言**量编辑态前后标题行的高和下面那块的位置**，
> 差超过 0.6px 就算坏 —— 这个约定光靠注释守不住（[踩坑 44](踩坑-前端.md)）。

### Card / Field / Row

布局原语 —— 「一张卡 = 一个主题，卡内一组小节，小节标题在上、内容在下」的排法。
设置页四个 tab 和成员区都走这一套。

| 组件 | 是什么 |
|------|--------|
| `Card` | 一张卡。`icon` + `title`，`children` 一律是 `Field`，`hint` 是卡底那行小字，`extra` 是标题右边那一小块（全局的入口，比如「邀请收件箱」） |
| `Field` | 一个小节。`label` 在上、`children` 在下；`htmlFor` 传了才渲染成真 `<label>`，不传就是 `<div>` |
| `Row` | 一行控件：flex 换行 + 统一间距 |

**为什么放在组件库而不是设置页里**：这套排法 `Settings.tsx` 和 `Members.tsx`
都要用（成员 / 邀请两块在两个地方渲染），而 `Members.tsx` 原先把 `Field` 的标题
样式 `mb-1.5 flex items-center gap-1.5 text-[12px] text-[var(--text-2)]`
**逐字抄了两遍**。抄出来的第二套一定会漂。

`Field` 的 `htmlFor` 是分水岭：小节标题大多是**一组控件的名字**（色板 / 风格 /
深浅），那种该是 `div` —— 用 `label` 去套一组按钮，读屏会念成一个不存在的表单
控件。真的是单个输入框时（日程集名字）才传 `htmlFor`。

```tsx
import { Card, Field, Row } from './kit.tsx';

<Card icon={<Layers size={14} />} title="日程集管理">
  <Field label="名字" htmlFor={fid + '-name'}>
    <Row>
      <Input id={fid + '-name'} value={name} className="h-[30px] min-w-0 flex-1" />
      <Btn variant="chip" size="sm" onClick={save}>保存</Btn>
    </Row>
  </Field>
</Card>
```

### Sheet / useConfirm / toast

底部浮层 / 确认框 / 全局提示。

```tsx
import { Sheet, useConfirm, toast } from './kit.tsx';

// Sheet
<Sheet open={open} onClose={onClose} title="标题" footer={...}>
  内容
</Sheet>

// useConfirm
const confirm = useConfirm();
const ok = await confirm({ title: '删除？', body: '删了找不回来', danger: true });
if (ok) { ... }

// toast
toast('已保存');
toast('已删除', { label: '撤销', run: () => restore() });
```

## 设计令牌

组件样式全部引用 `styles/tokens.css` 的设计令牌，不在 `.tsx` 里写死颜色：

- `--primary` / `--on-primary` —— 主色 / 主色上的文字
- `--text` / `--text-2` / `--text-3` —— 文字三档
- `--panel` / `--panel-2` / `--panel-3` —— 面板三档
- `--input` / `--border` / `--border-w` —— 描边三档
- `--r-md` / `--r-lg` / `--r-pill` —— 圆角
- `--danger` / `--danger-soft` —— 危险色 / 危险色软底

**规则：**
1. `.tsx` 里引用变量一律不给兜底值（有兜底值时不报错、不白屏，只是两套主题下全在用写死的浅色）
2. `--border`（装饰线）与 `--input`（交互控件描边）按「用户能不能操作它」分档
3. 风格轴两半：线粗细走 `--border-w`，圆角走 `--r-xs/sm/md/lg/xl/pill`

## 领域常量

`domain/types.ts` 里的角色常量，给 UI 渲染下拉选项和提示用：

- `Role` —— `'owner' | 'editor' | 'viewer'`
- `ROLE_LABEL` —— 角色中文名（创建者 / 可编辑 / 只读）
- `ROLES` —— 全部角色，给「读现有角色」的场合用
- `ASSIGNABLE_ROLES` —— **能授出去的**角色，只有 `editor` / `viewer`。
  界面上凡是「给某人挑权限」的选择器都用这个，**不要用 `ROLES`**：
  `owner` 不是一种可以分下去的权限，而是一个集必须存在的那个主人
  （不变量 2）。列出来就等于在问「把谁升成第二个主人」，那是个没有答案的问题。
- `ROLE_HINT` —— 角色一句话解释，选权限时直接写清楚会怎样

这些常量原先在 `Calendars.tsx` 和 `Settings.tsx` 里各定义一遍，现在收拢到
`domain/types.ts`，和 `ROLE_LABEL` 放一起。
