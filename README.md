# 日程清单

个人用的任务与打卡网页。记「要做什么、哪天做、做多久」，日 · 周 · 月三视图。

**网址：https://home.xiaokubao.space/schedule/**

**数据存在服务器上**（SQLite 库），登录后多设备自动同步。浏览器里也留一份：
**断网时整个页面照样打得开、照样能改，联网后自动补交**。

**部署与运维 → [DEPLOY.md](DEPLOY.md)**
**给 AI 编码助手 → [AGENTS.md](AGENTS.md)**

## 这是什么

```text
任务    标题、日期、时间、时长、重复规则、备注
打卡    每天要做的习惯（学英语、训练小狗……），记连续天数
```

**待办箱**（没定日期的）· **今天** · **逾期** · **日程**（日/周/月）· **项目**（泳道看板）·
**打卡** · **已完成** · **垃圾箱**，外加 **AI** 与 **设置**。

侧栏的顺序存在 `ui.navOrder` / `ui.navBottom` 里（垃圾箱可以归到底部），刷新不会丢。
**改顺序的入口在「设置 → 功能区」** —— 底栏挑哪几项（最多 4 项 + 「更多」）、
侧栏怎么排、藏起哪几项，都在那儿。

### AI 助手

「AI」页：用大白话问排期，它**自己查**你的日程集再回答，不是靠你复述。

```text
这周还剩什么没做？          下周哪天适合出去玩？        最近有什么落下的吗
```

它也能**改数据** —— 建任务、改期、标完成、删除 —— 但**不会直接改**：先把改动列成卡片，
你点「确认」才真的落库。没点确认之前一个字都不会写进去。

模型在 AI 页右上角 ⚙ 里配：**Base URL / 模型名 / API key**（任意 OpenAI 兼容端点，
本机的也行）。**key 存在服务器上**，不回传给浏览器。

## 怎么用

1. 打开网址 → **注册一个账户**（用户名 + 密码）。
   **注册开放，也没有管理员** —— 所有人平等，家里人各注册各的。
2. 想一起用 → 侧栏「日程集」里点 ⚙ 打开管理浮层，填对方的用户名发邀请，
   **对方接受之后**才生效。见下面「共享是怎么运作的」。
3. 底部或侧栏「＋新建任务」，或者用顶部的快速输入框。
4. **快速输入框不猜日期**：打字只给标题，日期 / 时间是**选**出来的
   （默认跟着当前页面走，面板里可以直接改）。**别指望它认「明天下午3点」** ——
   猜错比不猜更糟（[踩坑 25](docs/踩坑-环境.md)）。

5. **日程页**拖动任务方块改时间：**拖中间移动位置，上下沿都能拉伸**
   （上沿改开始时间、下沿改时长，15 分钟一档）。
6. 手机上**能拖着排序**：**长按任务 0.3 秒**提起来（卡片浮起一层分身）再拖到目标位置松手。
   **原地松手什么都不会发生** —— 改时间 / 时长 / 改期 / 删除都在点开它后的抽屉里。
7. 顶栏 `‹ ›` 前后挪日期，**找日期**可以直接挑日子（快捷键 `D`）。
8. 顶栏「今天」按钮：在今天/本周/本月时是安静的灰字，离开后才变成高亮的「回到今天」。
9. **项目页**是泳道看板：泳道 = 项目，列 = 待办 / 进行中 / 已完成，头上写「多久没动 +
   下一步是什么」。

### 快捷键

| 键 | 作用 |
|---|---|
| `N` | 聚焦快速输入框 |
| `T` | 回到今天 |
| `D` | 打开找日期面板（跳转到日程页） |
| `1` `2` `3` | 日 / 周 / 月视图 |
| `←` `→` | 前一天 / 后一天 |
| `Esc` | 逐层关闭浮层（更多 → 搜索 → 找日期 → 抽屉） |
| `Ctrl + Enter` | 快速输入后打开详细设置 |

## 共享是怎么运作的

共享的**单位是日程集，不是一条任务**。你可以有多个日程集，每个集里的人各不同。

- 侧栏「日程集」那一段切换当前在哪个集
- 顶上那几项是**跨集汇总**的：**今天 · 逾期 · 待办箱**（你在哪个集里出的活都算你的）
- **日程 · 打卡 · 已完成**是**按集**的，只显示顶栏勾选的那几个集

| 权限 | 能干什么 |
|---|---|
| **创建者** | 改内容，也能改名、加人、删日程集 |
| **可编辑** | 增删改任务和打卡，管不了成员 |
| **只读** | 只能看 |

发邀请是**两段式**：你填对方用户名发出去 → **对方在自己界面里点接受**才真正加入。
不是直接把人加进来 —— 用户名打错一个字符就是把日程交给了陌生人，而发出去的那一方
看不到任何异常。

> 两条底线由服务器保证：**每个人始终至少属于一个日程集**（退出 / 被踢 / 集被删之后
> 自动补一个「我的日程」），**每个集始终至少有一个创建者**（最后一个人不能降级、
> 不能退出）。

## 数据在哪（重要）

**数据在服务器上**：`/home/xiaokubao/.local/schedule/data/schedule.db`（SQLite）。
登录同一个账户，手机和电脑看到的是同一份数据，改了自动同步。

浏览器 localStorage 里**也留一份**（key `schedule-app-v4`），作用是：

- 断网 / 服务器没起来时照样能看能改，改动排队等联网后推上去
- 换设备要看到数据 → **登录**，不是拷 localStorage

> 旧版（纯本地那一代）的数据会在第一次登录时从 `schedule-app-v1` 导入，**那个旧 key
> 不会被删** —— 万一退回旧版本，数据还在。新版不生成演示数据。

**换设备 / 换浏览器**：注册或登录同一个账户即可，不需要导出导入。

**备份**：**设置页 →「数据」卡**里的「导出备份 / 导入备份」，导出一份 JSON。
导入是**合并**，不是覆盖 —— 同 id 的按逐字段 LWW 定胜负，现有数据不会被清空。

同一个账户在多台设备上同时改同一个任务时，**按字段**决定留谁的：A 改标题、B 改日期，
两个改动都保得住；改的是同一个字段才分先后，后改的赢。

## 本地开发

```bash
node server/server.js          # 后端 127.0.0.1:25692，数据落 server/data/
cd app && npm run dev          # Vite :5199，/api 自动代理到本机后端
cd app && npm run build && npm run preview   # 预览构建产物，同样 :5199
```

> `dev` / `preview` 都跑在 5199，**别同时开**。改完前端要重新构建才看得到变化。

端到端：

## 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 改了代码但页面没变 | 前端要 `./deploy/publish-web.sh`（光 `npm run build` 不够）；再强刷 |
| 页面还是旧版界面 | 旧版注册过 Service Worker。新版第一次打开会自动注销它并刷新一次；没生效就 DevTools → Application → Service Workers 里 Unregister |
| 登录不上 / 接口全 404 | 后端没起：`systemctl --user status schedule-backend` |
| 手机上装成 App 后白屏 | 网址要带结尾斜杠：`/schedule/`，不是 `/schedule` |
| 改了任务另一台设备没变 | 断网时会排队，联网后自动推。看顶栏右侧：转圈=正在同步，☁︎划掉=离线 |
| 断网打开是白屏 / 一句「先联网打开一次」 | 这台设备**从没联网打开过**，还没有缓存副本。找个有网的地方打开一次 |
| 首次打开有一堆别人的任务 | 那不是新版（新版不生成演示数据）—— 大概是 SW 发了一份旧版页面，强刷 |

## 技术栈

```text
前端    React 18 + TypeScript + Vite 6 + Tailwind 4
        图标 lucide-react（零 emoji）；弹层自绘（零原生 confirm / alert）
后端    Node 22 —— node:http + node:sqlite，**外加 AI 那一组依赖**
存储    服务端 SQLite（权威）+ 浏览器 localStorage（离线副本）
离线    手写 Service Worker 缓存外壳 + 发件箱排队，可装到桌面
同步    服务端权威 + 客户端 outbox + 逐字段 LWW + 游标增量拉取
AI      接 pi 的 agent 框架（@earendil-works/pi-agent-core / pi-ai），
        模型是任意 OpenAI 兼容端点；AI 读走快照、写走同步，改动要用户点确认
部署    nginx 伺服 ~/.local/schedule/web，/schedule/api/ 反代到 127.0.0.1:25692
```

**为什么不引数据库 / ORM / 同步框架**：数据量是「一个人一辈子的待办」，SQLite 单文件
足够；同步用「逐字段 LWW + 幂等 op」就够，不需要 CRDT。

**AI 那一组是「零依赖」唯一的有范围让步**：为了接 pi 的 agent 框架（tools / 流式 /
工具循环都是它管的）而不是自己手搓一遍。依赖锁精确版本、只在一个文件里调用，
**加别的仍然要先问**。没装也能起服务、也能用剩下所有功能，只是 AI 页报「依赖没装好」。

**为什么保留 `legacy/`**：旧版是能用的，新版出问题时可以整体退回去
（回滚办法见 [DEPLOY.md](DEPLOY.md)）。旧数据 key 也一直没删。
