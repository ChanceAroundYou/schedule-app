# 日程清单

个人用的任务与打卡网页。记「要做什么、哪天做、做多久」，日 · 周 · 月三视图。

**网址：https://home.xiaokubao.space/schedule/**

**数据存在服务器上**（这台机器自己的 SQLite 库），登录后多设备自动同步。
浏览器里也留一份：**断网时整个页面照样打得开、照样能改，联网后自动补交**。

**部署与运维 → [DEPLOY.md](DEPLOY.md)**
**给 AI 编码助手 → [CLAUDE.md](CLAUDE.md)**

## 这是什么

一个纯任务管理的应用：

```text
任务    标题、日期、时间、时长、重复规则、备注
打卡    每天要做的习惯（学英语、训练小狗……），记连续天数
```

七个入口：**待办箱**（没定日期的）· **今天** · **逾期** · **日程**（日/周/月）·
**打卡** · **已完成** · **垃圾箱**，外加一个 **AI**（见下）。

侧栏这 8 项的顺序存在 `ui.navOrder` / `ui.navBottom` 里（垃圾箱可以归到底部），
刷新不会丢。**改顺序的入口在「设置 → 功能区」** —— 底栏挑哪几项、侧栏怎么排，
都在那儿。2026-10-06 重写时这个入口一度掉了（`navOrder` 变成死数据），
后来在设置页补回。

### AI 助手

多一个「AI」页：用大白话问排期，它**自己查**你的日程集再回答，不是靠你复述。

```text
这周还剩什么没做？          下周哪天适合出去玩？        最近有什么落下的吗
```

它也能**改数据** —— 建任务、改期、标完成、删除 —— 但**不会直接改**：
它先把改动列成卡片，你点「确认」才真的落库。没点确认之前一个字都不会写进去。

模型在哪配：AI 页右上角 ⚙ ，填 **Base URL / 模型名 / API key**（任意 OpenAI
兼容端点，本机的也行）。**key 存在服务器上**，不回传给浏览器。

## 怎么用

1. 打开网址 → **注册一个账户**（用户名 + 密码，用户名随便起）。
   **注册是开放的，也没有管理员** —— 所有人平等，家里人各注册各的。
2. 想一起用 → 在侧栏「日程集」里点 ⚙ 打开管理浮层，填对方的用户名发邀请，
   **对方接受之后**才会生效。之后你们看到的是同一个日程集，任务和打卡都能一起改。
   见下面「共享是怎么运作的」。
3. 底部或侧栏「＋新建任务」，或者用顶部的快速输入框
4. **快速输入框支持直接写中文**，回车就存：

   ```text
   明天下午3点 交周报 2小时 每周一
   ```

   会被拆成：日期=明天 · 时间=15:00 · 时长=2小时 · 重复=每周一 · 标题=交周报，
   存进去之前下面会先显示拆解结果，不对可以直接改。

   能认的说法（不只这些）：

   | 类别 | 例子 |
   |---|---|
   | 日期 | 今天 / 明天 / 后天 / 大后天 · 下周三 / 本周五 · 3天后 · 10月15日 · 下个月15号 · 2026-10-15 · 1015 |
   | 时间 | 下午3点 · 早上8点半 · 晚上9点 · 14:30 · 3点一刻 · 3pm |
   | 时长 | 2小时 · 1个半小时 · 45分钟 · 半小时 |
   | 重复 | 每天 · 每周 · 每周一 · 工作日 · 每月 · 每月15号 · 每年 |

5. **日程页**拖动任务方块改时间：**拖中间移动位置，上下沿都能拉伸**
   （上沿改开始时间、下沿改时长，15 分钟一档）
6. 手机上也**能拖着排序**：**长按任务 0.5 秒**把它提起来（会浮起一层阴影），
   然后拖到想放的位置松手。提起之后**原地松手**就是操作层，可以改时间 /
   改时长 / 改期 / 上移下移 / 删除 —— 想调菜单，长按完别动就行
7. 顶栏 `‹ ›` 前后挪日期，**找日期**可以直接挑日子（快捷键 `D`）
8. 顶栏「今天」按钮：在今天/本周/本月时是安静的灰字，离开后才变成高亮的「回到今天」

## 共享是怎么运作的

共享的**单位是日程集，不是一条任务**。你可以有多个日程集，每个集里的人各不同。

- 侧栏「日程集」那一段切换当前在哪个集
- 顶上那几项是**跨集汇总**的：**今天 · 逾期 · 待办箱**
  （你在哪个集里出的活都算你的）
- **日程 · 打卡 · 已完成**是**按集**的，只显示当前选中的那个集

三档权限：

| 权限 | 能干什么 |
|---|---|
| **创建者** | 改内容，也能改名、加人、删日程集 |
| **可编辑** | 增删改任务和打卡，管不了成员 |
| **只读** | 只能看 |

发邀请的流程是**两段式**：你填对方用户名发出去 → **对方在自己的界面里点接受**，
这时才真正加入。不是直接把人加进来 —— 用户名打错一个字符就是把日程交给了陌生人，
而发出去的那一方看不到任何异常。

> 有两条底线由服务器保证：**每个人始终至少属于一个日程集**
> （退出 / 被踢 / 集被删之后自动补一个「我的日程」），
> **每个集始终至少有一个创建者**（最后一个人不能降级、不能退出）。

## 数据在哪（重要）

**数据在服务器上**：`/home/xiaokubao/.local/share/schedule/schedule.db`（SQLite）。
登录同一个账户，手机和电脑看到的是同一份数据，改了自动同步。

浏览器 localStorage 里**也留一份**（key `schedule-app-v4`），作用是：

- 断网 / 服务器没起来时照样能看能改，改动排队等联网后推上去
- 换设备要看到数据 → **登录**，不是拷 localStorage

> **旧版（纯本地那一代）的数据会上来。** 第一次登录时，应用会读一下
> 本机 localStorage 里的 `schedule-app-v1`，把里面的任务和打卡导入到你的账户，
> 之后就不再看了。**那个旧 key 不会被删** —— 万一想退回旧版本，数据还在。
> 新版不再生成演示数据（团队早会那几条是旧版才有的）。

**换设备 / 换浏览器**：注册或登录同一个账户即可，不需要导出导入。

**备份**：**设置页 →「数据」卡**里的「导出备份 / 导入备份」，导出一份 JSON。
服务器上的库自己也会留底，但导出一份存网盘更放心
（导入是**合并**，不是覆盖 —— 备份里的任务与打卡并进当前账户，同 id 的按逐字段
LWW 定胜负，现有数据不会被清空；导入前会先问一次）。

同一个账户在多台设备上同时改同一个任务时，**按字段**决定留谁的：
A 改标题、B 改日期，两个改动都保得住；改的是同一个字段才分先后，后改的赢。

## 本地开发

前端有构建步骤了（Vite）。**改完要重新构建，dist/ 才是线上伺服的东西。**

```bash
cd app
npm run dev          # Vite 开发服务器 :5199，/api 自动代理到本机后端
```

另开一个终端起后端：

```bash
# 工程根目录
node server/server.js          # 127.0.0.1:25692，数据默认落在 server/data/
```

想预览构建产物（更接近线上）：

```bash
cd app && npm run build && npm run preview   # :5199，同样代理 /api
```

> **`npm run dev` / `preview` 都跑在 5199 端口**，两者别同时开。

### 测试

```bash
cd app && npm test                        # 前端单元测试：node --test
cd app && npm run typecheck
cd app && node tests/contrast.mjs         # 配色 / 描边对比度 + 令牌名 / 兜底值（72 对）
cd app && node tests/color-scan.mjs       # 写死色值 / 圆角 / 原生 select
node server/tests/api.test.js             # 后端接口测试
node server/tests/migration.test.js       # schema 迁移：8 条
node --test server/tests/ai.test.js       # AI 层：18 条（假模型，不联网）
```

> **完整清单、每个探针节在验什么、哪条约定锁在哪一节 → [docs/测试.md](docs/测试.md)。**

端到端（真实网络 / 真实 Chrome，零 npm 依赖）：

```bash
# 两个人共享一个日程集的完整流程：起临时后端，全是真请求
node server/tests/smoke-share.mjs

# 真实 Chrome 量卡片几何（.task-el 那一族被五种界面共用，最容易互相踩）
cd app && npm run build && node tests/browser-cards.mjs
```

> `browser-cards.mjs` **要求 dist 是同源构建**（`npm run build`，别带
> `VITE_API_BASE`）—— 它直接伺服 `dist/`，带线上基址的构建会去连真服务器。
> 它只量布局，不写库。

> 2026-10-15 删掉了 `browser-smoke.mjs` / `browser-dayview.mjs` / `smoke.mjs`：
> 前两个卡在等 Service Worker 上（跑不完），第三个打的是**已部署的那份**
> 而且会在那个服务器上注册新账户。**端到端交互现在没有自动化覆盖** ——
> 发布前在真机 / 浏览器上手工走一遍。

## 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 改了代码但页面没变 | `dist/` 是构建产物，要先 `cd app && npm run build`。再强刷（Ctrl+Shift+R） |
| 页面还是旧版界面 | 旧版注册过 Service Worker。新版第一次打开会自动注销它并刷新一次；没生效就 DevTools → Application → Service Workers 里 Unregister |
| 登录不上 / 接口全 404 | 后端没起。`systemctl --user status schedule-backend` |
| 手机上装成 App 后白屏 | 网址要带结尾斜杠：`/schedule/`，不是 `/schedule` |
| 改了任务另一台设备没变 | 网络断时会排队，联网后自动推。看顶栏右侧图标：转圈=正在同步，☁︎划掉=离线 |
| 断网后打开是白屏 / 一句「先联网打开一次」 | 这台设备**从没联网打开过**，还没有可用的缓存副本。找个有网的地方打开一次即可 |
| 首次打开有一堆别人的任务 | 那不是新版。新版不生成演示数据 —— 大概是 Service Worker 发了一份旧版页面，强刷 |
| 数据在哪、怎么备份 | 见上面「数据在哪」。服务器库 + 设置页的「导出备份」 |
| 删除按钮点了没反应 | 已修：新版全部换成应用内确认弹层，不再用会被 PWA 吞掉的原生 `confirm()` |

## 技术栈

```text
前端    React 18 + TypeScript 5.7 + Vite 6 + Tailwind 4
        图标 lucide-react（不用 emoji）；弹层用 Radix headless
后端    Node 22 —— node:http + node:sqlite，**外加 AI 那一组依赖**（见下）
存储    服务端 SQLite（权威）+ 浏览器 localStorage（离线副本）
离线    手写 Service Worker（app/public/sw.js）缓存外壳 + 发件箱排队，可装到桌面
同步    服务端权威 + 客户端 outbox + 逐字段 LWW + 游标增量拉取
AI      接 pi 的 agent 框架（@earendil-works/pi-agent-core / pi-ai），
        模型是任意 OpenAI 兼容端点；AI 读走快照、写走同步，改动要用户点确认
部署    nginx 伺服 dist/，/schedule/api/ 反代到 127.0.0.1:25692
```

**为什么不引数据库 / ORM / 同步框架**：这个应用的数据量是「一个人一辈子的
待办」，SQLite 单文件足够；同步用「逐字段 LWW + 幂等 op」就够，不需要 CRDT。

**关于「零依赖」**（2026-10-06 变了）：后端原本一个 npm 包都不引，换来的是
「十年后 `node server.js` 还能跑、部署就是拷文件」。这一条被**有意推翻**了 ——
为了接 `pi` 这个 agent 框架（tools / 流式 / 工具循环都是它管的），
而不是自己手搓一遍。**这是一次有范围的让步**：只许引 AI 这一组，加别的仍然
要先问；而且依赖锁精确版本、只在一个文件里调用。

> 代价说清楚：`node server/server.js` 从此不再自包含，部署多一步装依赖
> （装法见 [DEPLOY.md](DEPLOY.md) 1.3）。没装也能起服务、也能用剩下所有功能，
> 只是 AI 页会报「依赖没装好」。

**为什么保留 `legacy/`**：旧版是能用的，新版出问题时可以整体退回去
（见 [DEPLOY-运维.md](DEPLOY-运维.md)「回滚」）。旧数据 key 也一直没删。
